> 동일한 pretrained TSFM과 LoRA를 사용하는 조건에서,
> 실제 계층(parent/child) 과거 정보를 작은 residual PEFT가 이용하면

# 7. Hierarchy context를 만드는 위치와 수식

각 rolling origin에서 모든 hierarchy node의
48-month context를 동시에 준비한다.

Chronos-Bolt의 instance normalization / patch embedding 경로를 그대로 사용해
각 node의 pre-attention patch embedding을 얻는다.

shape 개념:
`H[node, patch, 512]`

future target은 context 계산에 절대 사용하지 않는다.

## 7.1 hierarchy graph

문자열 이름을 억지로 parse해서 parent를 만들지 않는다.

공식 summing matrix `S_df`의 support 관계로 graph를 생성한다.

node i support:
`{bottom column b | S[i,b] != 0}`

direct parent p:
- support(i) is strict subset of support(p)
- 그 사이에 intermediate support가 없는 minimal strict superset

direct child는 converse.

grouped hierarchy에서 multiple parents를 허용한다.

검사:
- root
- leaf
- isolated node 0
- duplicate support ambiguity
- edge count
- every nonroot has >=1 parent
- every nonleaf has >=1 child

ambiguous duplicate supports가 있으면 보고하고
unique_id metadata로 원인을 확인한 뒤 임의로 삭제하지 않는다.

## 7.2 공통 adapter

SELF / POOL / HIER가 capacity 때문에 달라지지 않게
**모두 정확히 동일한 ResidualAdapter**를 사용.

```
512 -> 8 -> 512
```

params:
8,712

up weight/bias:
zero initialization

따라서 optimizer step0에서:
- LORA_SELF == LORA
- LORA_POOL == LORA
- LORA_HIER == LORA
예측이 exact 또는 documented floating tolerance 안에서 동일해야 한다.

## 7.3 context 정의

SELF:
`c = 0`

POOL:
동일 origin, 동일 patch에서
자기 node를 제외한 모든 다른 node embedding의 평균.

HIER:
동일 origin, 동일 patch에서
direct parent embeddings와 direct child embeddings를 사용.

구체적:
- parent mean을 계산
- child mean을 계산
- 둘 다 있으면 두 group mean의 평균
- 하나만 있으면 존재하는 group mean
- root/leaf도 위 규칙으로 동작

미래 정보 없음.

## 7.4 adapter input

context 정보의 scale 차이가 adapter 효과로 둔갑하지 않게
stateless normalization을 공통 적용한다.

예:
- SELF: `u = layer_norm(h_self)`
- POOL/HIER:
  `u = layer_norm(h_self + scale_context(c, h_self))`

`scale_context`는 학습 파라미터 없는 RMS matching:
`c * stopgrad(rms(h_self)/(rms(c)+eps))`

그 뒤 동일 adapter:
`delta = cap(h_self) * tanh(up(gelu(down(u))))`
`h_prime = h_self + delta`

cap 정의와 eps는 모든 arms 동일.

중요:
- context formula를 result 보고 변경 금지
- learned gate 추가 금지
- attention graph layer 추가 금지
- HIER만 extra params 추가 금지

adapter 출력 이후 동일 Chronos encoder/decoder/head와 LoRA 경로를 사용한다.

# 9. loss와 metric

계열 규모와 hierarchy node 수가 큰 level을 지배하지 않게 한다.

TRAIN에서 series i의 seasonal squared scale:
`d_i = mean((y_t - y_{t-12})^2)` over legal TRAIN times

floor:
training data 기준 작은 positive eps를 명시.

training loss:
- horizon squared error / d_i
- 먼저 각 series 평균
- 각 hierarchy level 평균
- level들을 동일 가중 평균

모든 neural arms 동일 loss.

## primary metric

hierarchy-level-balanced RMSSE.

각 level별 RMSSE를 먼저 계산하고
level들을 equal weight로 평균.

반드시 별도 보고:
- each level RMSSE
- bottom-level RMSSE
- raw MAE
- unreconciled
- reconciled
- coherence violation


# 10. reconciliation

예측 정확도와 coherence를 구분한다.

반드시 포함:
- BottomUp
- MinTrace(method="mint_shrink")
- 가능하면 MinTrace(method="ols") as cheap diagnostic

공식:
`hierarchicalforecast`

MinT-shrink는 CALIBRATION residual에서만 추정.

패키지 API에 rolling-origin residual 형식이 바로 맞지 않으면:
1. package source를 읽는다.
2. exact shrinkage/MinTrace 계산을 local helper로 구현한다.
3. 작은 synthetic hierarchy에서 official package 결과와 parity test를 만든다.
4. parity 없이는 custom implementation을 `MinT-shrink`라고 부르지 않는다.

TEST y로 covariance/reconciler fit 금지.

주 비교:
각 neural method의 **MinT-shrink reconciled** forecast.

같이 보고:
- unreconciled
- BottomUp
- OLS diagnostic

"coherence violation = 0"은 성능 win이 아니다.

# 12. training protocol

optimizer:
AdamW

weight decay:
0

grad clip:
1.0

scheduler:
none for screen

precision:
우선 FP32.
VRAM 때문에 변경해야 하면 BF16을 모든 neural arms 동일하게 적용하고
parity/overflow audit 기록.
TF32 여부 기록.

LR:
Stage A `[1e-4, 3e-4]`

updates:
max 512

checkpoints:
0,128,256,512

selection criterion:
VALIDATION에서 MinT-shrink reconciled primary metric.
CALIBRATION residual은 checkpoint별 해당 model prediction으로 추정.

tie:
1. lower validation primary
2. lower LR
3. earlier checkpoint

repeat seed에서는 chosen LR을 고정하지만
checkpoint는 자기 VALIDATION으로 선택한다.

## batch / memory

한 origin의 hierarchy 전체가 context 정보 계산에 필요.

메모리가 부족하면:
- all-node patch embeddings/context summary는 계산
- encoder/decoder forward는 node chunks로 수행
- loss gradient accumulation으로 hierarchy 전체 loss를 정확히 재현

node subset을 랜덤 샘플링해서 HIER context 자체를 바꾸지 않는다.

permutation check:
node order를 바꿔도 unique_id 기준으로 원래 순서 복원 시 prediction이 같아야 한다.
