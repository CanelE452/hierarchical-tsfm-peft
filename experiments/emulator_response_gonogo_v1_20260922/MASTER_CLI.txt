4. 대리모델은 실제 factorized 계산으로 구현
======================================================================
임의 layer 삭제/새 distillation backbone은 이번에 사용하지 않는다.
원래12block, hidden dimension, attention mask, positional/group structure를 그대로 유지한다.
encoder blocks 내부의 실제 nn.Linear만 activation-aware SVD로 factorize.
입력 patch embedding, 출력 head, embedding/LayerNorm/relative-bias, tied/shared tensors는 유지.
특수 구조 때문에 직접 .weight를 사용하는 층은 누락하지 말고 preflight에서 확인한다.

각 eligible W[out,in]의 저장 entry 목표:
  r = floor(0.5 * out * in / (out + in)), 최소1
  저장 = left[out,r] + right[r,in].
  실제 비용이 dense보다 작지 않은 층은 대상 제외하고 기록.
0.5는 layer별 factor parameter 보존비이지 모델 전체가 정확히 절반이라는 뜻이 아니다.
전체 params/bytes/실제 step time은 별도로 계산한다.
forward 안에서 left@right dense 행렬을 만들어 사용하면 이 비교로 인정하지 않는다.

TRAIN-only calibration origin16개:
TRAIN legal origin index 전체에서 linspace로 고른16개(중복불가).
각 origin의 모든21개 계열을 같은 group으로 처리한다.
activation은 미래 target 없이 F0 원래 forward에서 수집.
각 compression module에 대한 uncentered X^T X / n 사용.
원래 입력·출력의 bias는 그대로 보존.

EMLoC 공식 부품과 동일한 목표:
  min ||(W - Wu Wv) C^(1/2)||_F
  고유값 상대 floor1e-7, truncated SVD.
reference_core.activation_factors는 해당 weighted SVD 부품이다.
실모델 forward에서 original 가중치를 factor 계산과 함께 GPU에 보관하지 않는다.
압축 산출물을 저장하고 unused 원래 사본·activation 행렬을 해제한 뒤 main 학습.

원래 projection의 in/out가 보존돼야 LoRA A/B가 원래 모델에 그대로 들어간다.
adapter를 Wu/Wv의 새 latent 차원에 붙이지 않는다.
원래 in->out 옆의 additive s*B*A branch로 붙여 main adapter dimension을 보존한다.

[한계] 같은 layer 수와 attention 계산은 유지하므로 activation 메모리/step time이
저장량과 같이 줄어든다는 보장은 없다. 특히 작은 TSFM에서 두 작은 GEMM이
하나의 큰 GEMM보다 느릴 수 있다. 이것은 실패하면 그대로 보고할 실험 결과다.

======================================================================
5. 출발 예측 보존 수식: raw 공간과 native 공간을 혼동하지 않음
======================================================================
F0_raw(x): 원래 pretrained 모델의 raw quantile forecast.
E0_raw(x): 해당 arm의 calibration이 끝난 후, LoRA0인 emulator의 raw forecast.
Etheta_raw(x): main LoRA가 적용된 같은 emulator의 raw forecast.

DELTA/VALUE_DELTA/RESPONSE_DELTA의 supervised 학습 예측:
  train_raw = stopgrad(F0_raw) + Etheta_raw - stopgrad(E0_raw).

처음에는 Etheta=E0이므로 train_raw=F0_raw.
그러나 이것만으로 main LoRA 학습 뒤 실제 Ftheta가 train_raw와 같다는 보장은 없음.
그 차이를 response calibration과 실제 transfer 평가로 검토한다.

공통 native loss를 쓰려면:
  train_raw를 원래 모델과 같은 context loc/scale로 normalize하고 asinh 변환 후
  기존 mean-horizon / sum-quantile / mean-series native pinball을 계산한다.
'raw 변화분 더하기'를 임의로 'asinh 공간에서 더하기'로 바꾸지 않는다.
원래 F/E의 input normalization loc/scale이 같아야 한다. 다르면 BLOCKED_MAPPING.
훈련 중 quantile sorting하지 않는다. 평가 sorting과 crossing보고는 기존 metric과 동일.

F0_raw/E0_raw TRAIN/VAL cache의 비용을 각 독립 적용 비용에 모두 청구한다.
물리적으로 공유되는 파일이어도 새로운 사용자에게 공짜 준비비라고 하지 않는다.
캐시는 exact original source/model/input/group/normalization fingerprint에 묶는다.
캐시에는 future y가 입력된 예측을 넣지 않는다.
E0 cache는 calibration 후 생성하며 이후 emulator gamma/factors는 main fit 동안 동결.
E0를 매 step 갱신해서 변화분을 지워버리지 않는다.

최종 배포는 반드시 원래 F0 + 학습한 LoRA이다.
F0/E0를 매번 함께 호출해서 train_raw를 배포한 뒤 '원래 모델로 이전'이라고 하지 않는다.

======================================================================
6. 작은 예측 반응 calibration (새 기법 가설, 미검증)
======================================================================
기존 factor Wu/Wv를 새로 모두 학습하지 않는다.
각 retained SVD component에만 multiplier exp(gamma)를 두고 gamma0=0.
W_em(gamma)=Wu diag(exp(gamma)) Wv.
따라서 prep trainable은 각 층의 압축 rank 수만큼. 총수를 실제 기록.
main LoRA 학습 전에는 모두 동결. 최종 원래 모델에는 gamma/factors를 옮기지 않는다.

같은 starting E_svd에서 두 calibration을 각각16updates:
  VALUE: F0의 원래 출력만 matching.
  RESPONSE: F0의 원래 출력 + small-LoRA finite response matching.
둘 다 AdamW lr1e-2, weight_decay0, clip1, scheduler없음.
각 step 뒤 gamma를[-log2,log2] 범위로 투영한다. epsilon1e-8.
같은 calibration예제 순서. 파라미터/예제수는 같되 forward 수 차이는 비용에 공개.

고정 probe:
- probe seed92703. 실제 main LoRA와 같은 canonical module/rank8/alpha16.
- 두 개의 독립 Gaussian A/B direction을 생성.
- 각 module의 effective s*B*A Frobenius norm을 원래 W norm의
  1e-4 또는1e-3로 정규화. 총4개의 probe directions/scales.
- plus/minus는 B 부호만 반전; A도 같이 반전하면 같은 곱이 되므로 금지.
- gamma 학습 시 probe A/B는 frozen. main fit은 probe checkpoint에서 출발하지 않는다.
- calibration origin j에는 probe j mod4를 적용한다. 성능을 보고 probe를 고르지 않음.
- F0/F_plus/F_minus는 미래 y 없이 계산·저장. 전체 dense model의 SGD teacher를 따로 학습하지 않는다.

delta_F=(F_plus_raw-F_minus_raw)/2
 delta_E=(E_plus_raw-E_minus_raw)/2
TRAIN sigma로 scale-normalized MSE를 계산한다.

L_value = MSE_sigma(E_gamma,0 - F0) /
          (MSE_sigma(E_svd,0 - F0) +1e-8)
L_response = MSE_sigma(delta_E-delta_F) /
             (MSE_sigma(delta_F)+1e-8)

VALUE: L_value
RESPONSE: L_value + L_response. lambda=1고정.
반응 target이0에 가까우면 그 비율과 raw numerator를 기록하고 probe 크기를 키우지 않는다.
L_response 감소만으로 GO하지 않는다. 최종 main-trained Ftheta의 실제 정답 오차가 핵심.

response 계산에서는 E_plus/E_minus의 gamma gradient를 끊지 않는다.
F teacher는 no_grad/cached. E0 baseline cache는 여기서 쓰지 말고 calibration의 current E_gamma,0를 계산.
완료 후 VALUE/RESPONSE emulator fingerprint를 각각 봉인하고 main학습 동안 변경금지.

검사용 TRAIN origin8개를 calibration16개와 겹치지 않게 선고정하고,
그들에 대해 별도의 probe seed92704로 반응 오차를 평가한다.
이 검사에는 future y를 사용하지 않고, 검사 결과로 gamma/LR/압축비를 다시 선택하지 않는다.

이것은 full Jacobian을 정확히 일치시키는 방법이 아니다.
고정된 작은 finite perturbation에서의 반응 보존 가설이다.
큰 main update나 unseen domain에서도 일치한다고 전제하지 않는다.

공통 SVD모델/두 calibration emulator는 main두seed에 공유한다.
따라서 두seed는 main optimizer 변동 반복이며 calibration모집단 반복은 아님을 명시.

======================================================================
7. EMLoC correction 포팅 범위와 필수 산술검사
======================================================================
공식 getCorrectedLoRA/clamp를 참조한다. 단순히 압축모델에서 학습하고 복사만 한
방법을 EMLoC라고 부르지 않는다.

PyTorch convention:
  W(out,in), A(r,in), B(out,r), effective LoRA=s*B*A.
A.T의 SVD로 orthonormal input basis U를 구해 동일 update로 재표현.
원래 W와 emulator W_em의 차이를 그 basis에서 계산하고 B쪽을 보정한다.
공식 clamp는 basis별 mean-absolute-norm을 사용하며 L=3.
본 비교에서 alpha/r=2이므로 correction 전후 effective scaling을 반드시 포함.
공식 코드가 암묵적으로 처리하는 scaling을 빼먹으면 다른 알고리즘이 된다.

reference_core.emloc_correct:
- algebraic scope를 검사하는 우리 포팅 함수.
- float64 unit test에서 unclamped active-subspace identity 검증.
- 제한0이면 update 보존, zero B이면 finite한0보정, 동일base이면 update불변.
- CUDA/BF16 공식 함수와의 parity는 CLI 실모델/작은행렬 검사로 추가해야 한다.

보정은 checkpoint별 복사본에 수행한다. main 학습 중 A/B를 수정하지 않는다.
ELMoC와 후보의 checkpoint selection은 둘 다 실제 full-model transferred VAL에서 수행한다.
EMLOC_PORT의 실제 구현 차이가 해결되지 않으면 전체 파이프라인을 재현한 것처럼 보고하지 말고
BLOCKED_BASELINE 또는 LIMITED_BASELINE으로 표시한다. 강한 대조가 빠진 상태에서 METHOD_GO 금지.

======================================================================
8. 본학습: 동일 기회, 128updates에서 종료
======================================================================
6arms x2seeds =12 main fits.
fit당128 optimizer updates. checkpoint=0,16,32,64,128.
한 update의 effective batch는 같은 origin의21계열 x4 origins 누적.
모든 main arm에서 원래 source와 동일한 native loss/원점schedule 사용.
각 seed의 LoRA A/B 초기 tensors를 canonical original module path에 저장해 재사용.
원래/축소모델의 표현 차원은 같으므로 theta 정의도 동일해야 함.
F_TOP3는 공통맵의 일부만 사용하고 나머지LoRA는0고정.

모든 main trainable LoRA에 같은 LoRA+:
  lr_A=1e-5, lr_B=1.6e-4, betas(.9,.999), eps1e-8, weight_decay0.
  clipping1, dropout0, scheduler없음.
alpha/r와 optimizer그룹을 실제 PEFT reference와 확인.
수렴최적학습률이라는 주장은 안 함. 이번128회는 짧은적응 setting이다.

seed92711과92712에서 방법 실행 순서를 반대로 하여 시간순 편향을 완화한다.
한꺼번에 여러GPU작업을 띄우지 않는다. 다른 사용자의 process 종료금지.
main최대128에서 끝. 좋은점수를 위해256/512추가금지.
계속개선중이면 LIMITED_BUDGET을 표시하지만 자동으로fitterror/분야실패라고 하지 않음.

선택과 평가:
- 모든 checkpoint의 LoRA를 새 full model에 이식한 뒤 VAL 실제정답으로 평가.
- EMLoC에는 보정 포함, delta계열은 LoRA만 직접이식.
- emulator만의 VAL을 selection primary로 쓰지 않는다.
- 최소 VAL; tie는 더이른step.
- 모든 방법/seed의 선택을 봉인한 뒤 모든 TEST예측을 저장하고 채점한다.
- TEST에서 candidate가 좋아지는 checkpoint를 다시고르지 않는다.
- 후보의 train_raw/emulator_only와 actual_Ftheta 점수 차이는 진단으로만 별도 보고.

9. 총 비용: 이번에는 retrospective checkpoint비용을 주표로 쓰지 않음
======================================================================
주 시간 비용은 '128회까지의 고정 선택절차를 실제 완료한 전체 비용'.
  T_total = 사용자별 자료준비/모델로드
          + activation수집/SVD
          + probe교사호출/calibration
          + F0/E0 cache 생성
          + 128 main updates 전부
          + 모든계획된 VAL/체크포인트/LoRA이식/보정
          + 최종 선택·저장 비용.
사용하지 않은 대조를 만들고실험하는 연구코딩비는 deployment적응비가 아님.
TEST의 마지막채점/논문그림 생성은 적응비가 아니라 평가비로 분리.

공유 SVD/F0cache를 한 번 만들어도, 독립 cold-start 적용비에는 각방법에 전체해당준비비를 청구.
실험 전체실비에는 물리적으로 한 번 수행한 비용만 더한다. 두 가지 장부를 분리.
사전학습비를 추정한 N회로 임의 분할해서 '현재 빠르다'고 하지 않는다.
다른기계의 과거 LoRA시간을 분모로 사용하지 않는다.

선택된64회까지의 prefix비용은 보조표에 표시할 수 있지만
그것을 '64회가최선인지 선택까지 끝난 비용'으로 표현하지 않는다.

보조 시간-품질곡선:
공통 target = 1.005 * (현재 F_FULL의 best VAL checkpoint score의 두seed 평균).
절대 deteriorated last-step VAL로 목표를 정하지 않는다.
F0가 target을 이미 만족하면 NO_ADAPTATION_NEEDED_AT_THIS_TARGET.
첫도달은 recorded checkpoint의상한이며, 사후목표에대한보조분석이라고 명시.
그 목표를 TRAIN종료규칙으로 소급 적용하지 않는다.

메모리:
- main-only peak allocated/reserved
- SVD/probe/calibration 포함 cold-pipeline peak
- CPU RAM/disk캐시/배포adapter bytes
모두 별도 측정. 원래모델과emulator를 동시에올려놓은숨은GPU복사본 금지.
준비단계가 더 큰메모리를 요구하면 그사실까지공개한다.
최종추론은 모두fullF+LoRA이므로 새로운추론가속을주장하지않는다.

시간 신뢰도:
CUDA synchronize,동일warmup,precision/batch/checkpointing일치.
각 stage elapsed,active-step분포와GPU상태(가능한범위)를로그.
관측공유GPU잡음이CV0.2초과하거나 seed별 step throughput이20%넘게다르면
정확도수치는보고하되 speed GO는TIMING_HOLD. noisyrun을조용히재실행하지않음.
F_TOP3/HEAD/원래모델의 no_grad·cache 가능한기능을 일부러비활성화하지않는다.

GO_METHOD_SCREEN (사전제안값; 학술표준아님):
1) 후보 full-model 평균 TEST오차가 F_FULL대비0.5%이내 손해이며 두seed각각도0.5%이내.

   방법이있으면 후보GO아님. 전체 Pareto표를보여준다.
5) 실모델수치/transfer/데이터무결성에 unresolved 문제가없고 timing검증통과.

이것은 '속도+메모리+정확도 향상 모두'를요구하는것이아니다.
품질보존하의시간절약과제안부분의필요성만묻는다. 메모리는보조.
0.5/20/0.3은결과전고정한연구자원투자기준이지통계적동등성/논문PASS기준이아님.

GO_STANDARD_ONLY:
  고정압축/EMLoC/부분층LoRA/출발예측보존만으로같은목표가해결됨.
  효율화는가능해도새반응보정의필요성미확보.

NO_GO_CURRENT_IMPLEMENTATION:
  품질보존또는총시간절감이명확히안되거나,강한단순대조가지배.
  '모든 emulator방법불가능'이라고쓰지않음.

HOLD_NO_AUTO_RESCUE:
  경계효과,seed반대,준비비/타이밍불확실성,예산내학습의제한으로판정불분명.
  어떤값이확인됐고어떤값때문인지따로적는다. HOLD도자동추가학습없음.

BLOCKED_DATA / BLOCKED_IMPLEMENTATION / BLOCKED_RESOURCE / BLOCKED_BASELINE:
  실제실험이성립하지않은상태. 결과가안좋다는뜻으로쓰지않음.

reference_core.outcome은산술적분류부품이다.
최종판정전위무결성·타이밍·baseline한계를반영해야하며PASS를자동미화하지않는다.
