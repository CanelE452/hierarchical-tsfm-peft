# 고정 과거 창의 재구성 학습 재평가

[확인] 저장된 REC/PRED codec 40개를 추가 학습 없이 CPU에서 실행했다. REC의 초기0→최종600 비교에서 고정 FIT의 정규화 재구성 MSE는 4/4 조건에서 소폭 개선했으나, 고정 TUNE의 정규화 재구성 MSE는 4/4 조건에서 악화했다. 따라서 현재 결과를 **“재구성은 잘 일반화됐는데 예측만 실패했다”**라고 해석할 수 없다. 재구성 학습의 일반화 문제도 남는다.

이 문서는 최초 자동 생성 보고서의 조건부 해석이 FIT 재구성과 TUNE 예측의 구분을 흐릴 수 있어 명확히 한 해석 개정본이다. 기존 보고서·결과·검증 영수증을 보존했으며, 추가 실행이나 모델 선택은 하지 않았다.

## REC 초기값과 최종600: 같은 입력에서의 비교

```text
자료    seed    FIT 정규화 재구성 MSE   TUNE 정규화 재구성 MSE   미래 TUNE 물리 예측 MSE
Jena    92601  0.147215 → 0.145960     0.400644 → 0.460918      20896.801 → 21207.776
Jena    92602  0.147215 → 0.146069     0.400644 → 0.495028      20896.801 → 21223.095
Robin   92601  0.116615 → 0.110079     0.038509 → 0.047335         81.964 →    87.416
Robin   92602  0.116615 → 0.110178     0.038509 → 0.049814         81.964 →    90.045
```

최종600만의 현상도 아니다. REC의 모든 저장된 후속 step100/200/400/600에서 고정 FIT 정규화 재구성 MSE는 초기보다 낮고, 고정 TUNE 정규화 재구성 MSE는 초기보다 높았다. 원래 REC의 미래 TUNE 예측 MSE에 따른 선택은 네 조건 모두 초기0이다. 이번 검사는 checkpoint를 다시 선택하지 않는다.

지표에 따라 방향이 다르다. Jena의 TUNE **물리** 재구성 MSE는 4554.253→4426.273/4469.852로 소폭 개선했다. 같은 조건의 **정규화** 재구성 MSE는 악화했다. Robin의 TUNE 물리 재구성 MSE는 38.435→46.741/48.480으로 악화했다. REC의 실제 학습 목적은 정규화 channel-macro MSE이며, 서로 단위가 다른 채널의 물리 오차와 같은 순위를 보장하지 않는다.

## 어떤 원인이 남는가

[판단] 고정 FIT 재구성 MSE가 줄었다는 사실은 최소한 학습이 전혀 진행되지 않았다는 설명을 약화한다. 그러나 감소 폭이 작고 고정 TUNE 정규화 재구성이 악화했으므로, 재구성의 일반화 문제와 목적 간 불일치를 분리해 확정할 수는 없다. 모델 용량, 초기 PCA의 강한 기준, 최적화, 제한된 FIT 창과 시간 분포 변화 중 무엇이 원인인지도 이번 검사로 특정하지 못한다.

Jena PRED에서는 과거 재구성이 나빠지는 동시에 미래 TUNE 물리 예측 MSE가 20896.801→16981.042/15838.537로 개선했다. 이는 이 구성에서 좋은 과거 재구성이 좋은 미래 예측과 같은 평가 기준이 아니라는 관측이다. PRED는 동결 Bolt를 거쳐 **E와 D를 함께** 미래 예측 목적으로 학습했으므로, 개선을 encoder 단독의 정보 보존이나 잠재 미래의 예측 가능성에 귀속하지 않는다. Robin PRED는 TUNE에서 선택된 step200과 최종600이 다르며, 최종600의 결과를 선택 모델의 결과로 바꾸어 말하지 않는다.

잠재 표현은 80개 split별 평가에서 모두 유한했다. 전체 최소 채널 std는 0.269672, 최대 절대값은 71.155464였고 std<1e-6인 채널은 없었다. 이는 전체 상수 출력 붕괴가 관측되지 않았다는 제한적인 검사다. 중복된 채널, 유용한 정보의 손실, 동결 Bolt와의 불일치 등 다른 문제를 배제하지 않는다.

## 비교 조건과 검산

- Jena/Robin, seed92601/92602, REC/PRED, step0/100/200/400/600의 총40개 저장 checkpoint를 평가했다. 같은 FIT256/TUNE64의 과거512 입력과 observed mask를 사용했다.
- TUNE 과거 창은 FIT 구간과 일부 겹치고, 겹치는 창의 위치는 중복 가중된다. 따라서 이 재구성 평가는 독립 TUNE 시점만의 일반화 검증이 아니다. 여기서 TUNE 악화는 동일한 고정 TUNE 창 집합에서의 초기 대비 악화라는 뜻이다.
- FIT-only mean/std 및 기존 window 안의 missing fill을 유지했다. 원자료는 기존 단일 bounded TRAIN/VAL 파일이지만, VAL 창·target·새 점수는 만들지 않았다. TEST guard를 등록했다. 추가 학습, Bolt 인스턴스와 실행, GPU 사용은 모두0이다.
- source/data/checkpoint SHA, 원래 Stage B의 FIT/TUNE origins와 정규화 통계 일치를 확인했다. 저장 배열을 재독해 별도 NumPy 채널 루프로 80개 재구성 점수를 검산했다. 40개 snapshot의 미래 suffix 변형과 최근 관측 양성대조도 통과했다.
- 미래 TUNE 예측 점수는 기존 Stage B checkpoint metadata를 SHA로 연결해 **재사용**했다. 이번 CPU 재구성 실행에서 새로 산출한 미래 예측 점수가 아니다.

실제 본체와 보고서·최종 배열 SHA 검사 CPU는 22.578125초, wall은 약14.408초, PyTorch threads2였다. Python import/프로세스 시작은 제외한다. 새 cache는 647,220,036 bytes다. 기존 결과 수정과 commit/push는 없다.
