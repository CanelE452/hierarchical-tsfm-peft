# 0. 목적과 범위

최상위 목적: 기존 LEVEL의 학습된 예측을 보존한 상태에서 P 보정만 추가하면, v8 공동 재학습 P/Q보다 LEVEL의 장점을 덜 훼손하면서 추가 정확도를 얻는지 확인한다. 최종 판단은 ‘이 단계적 적응이 LEVEL의 후속 대체 후보인가’다. 양성 결과를 강제하거나 모든 자료·지표에서의 승리를 완료 조건으로 만들지 않는다.

주력 질문은 방법 중심이다. Robin/Jena는 상반된 기존 결과를 가진 두 개발 자료이며, 시작부터 동일 비교를 둘 다 고정한다. 한 자료의 새 TEST 결과를 보고 다음 자료·방법을 고르지 않는다. 이번은 한정된 방법 개발이지 최종 다중데이터 확증·새 site 탐색·논문 최초성 확정이 아니다.

새 모듈의 크기·비선형성·K를 늘리지 않고, ‘LEVEL 먼저 학습 → 고정 → P만 추가 적응’이라는 학습 절차를 먼저 비교한다. 입력별 gate, 채널별/기간별 alpha, 새 loss, 별도 normalization, 새 LR sweep, Q 재학습, K 변경, NLinear_P+Q로의 주제 전환, 새 데이터, compile/양자화/새 서버는 이번 기본 범위 밖이다. Hog/Bull/Electricity 확장은 이번에 자동 추가하지 않는다.

가설 H1: 학습된 LEVEL을 보존하면 Q 재학습·공동 checkpoint 선택에 따른 변화 없이 P 추가 가치만 더 직접적으로 판단할 수 있다.
가설 H2: P 보정이 과하면 단일 전역 강도의 제한된 VAL 선택이 도움이 될 수 있다. alpha=0 복귀 자체는 새 예측 능력의 증거가 아니다.
경쟁 설명: P 입력의 정보 부족, 선형 head의 한계, 제한된 학습/선택, 추가 단계·연산, 단순 원입력 보정으로도 충분함.

완전관측·동일가중 제곱오차·고정 직교 P/Q에서는 손실이 공간별로 분리된다. 따라서 ‘P/Q gradient가 필연적으로 충돌했다’고 단정하지 않는다. 실제 shared clipping·scheduler·checkpoint와 마스크가 연결을 만들 수 있다는 가설만 남긴다. 완전한 원인 분리를 첫 학습의 조건으로 삼지 않는다. 기존 원리나 alpha fallback을 새 발명으로 포장하지 않는다.

# 3. 재사용할 부모 LEVEL과 자료 계약

P=UU^T, Q=I-P, U는 각 자료의 고정 TRAIN PCA다. X는 이미 정해진 TRAIN 표준화 좌표의 [B,512,C], deltaX=X-last(X)이다.

각 dataset·seed의 부모 f*는 ‘그 자료 TRAIN으로 학습하고 기존 VAL 정책으로 선택된 LEVEL_RES’다.
- Robin: v6의 선택 LEVEL, C17/K5, 시간 간격1시간, H48=48시간.
- Jena: v7의 선택 LEVEL, C21/K6, 시간 간격10분, H48=8시간.
- seed는92601/92602. 가장 잘 나온 seed를 하나 고르거나 서로 다른 seed를 평균한 ensemble을 부모로 쓰지 않는다.
- v8 P/Q의 Q head나 학습 전 LEVEL_ONLY를 부모 LEVEL이라고 바꾸지 않는다.

로컬 byte 경로는 위 selected/data/reuse manifest를 실제로 열어 확인해 계획에 적는다. 존재하지 않는 cache나 내부 키를 만들지 않는다. 부모 checkpoint·PCA·백본 revision·정밀도·전처리·TRAIN/VAL/TEST 원점·mask·기존 예측 해시를 묶어야 한다. 원격의 작은 결과 파일만으로 checkpoint가 로컬에 있다고 주장하지 않는다.

부모의 학습된 F0/E/D/G 및 통계는 이번 단계에서 모두 고정한다. 새로운 TRAIN-only normalization/PCA를 다시 맞추거나 다른 자료의 학습 G를 이식하지 않는다. 부모도 TRAIN에 적합하고 VAL로 선택됐다는 이력을 보존한다. 부모 선택→head checkpoint→alpha 선택에서 VAL을 반복 사용하므로, 그 VAL 개선을 독립 일반화 근거로 쓰지 않는다.

기본은 부모 재학습0. 파일이 없으면 승인 전에 알리고, 정확한 과거 레시피로 복구할 수 있을 때만 예비 최대4attempt에서 부모 재적합을 계획한다. 새로 복구한 부모의 정확한 예측을 대응 기준으로 삼고, 역사적 점수를 함수가 같은 것처럼 그대로 사용하지 않는다. 필요한 복구와 직접 대조가 상한에 함께 들어가지 않으면 범위 변경안을 계획 승인 전에 제시한다.

Robin/Jena의 TRAIN·VAL·TEST 및 모든 preprocessing/metric 계약은 v7/v8 그대로 사용한다. 둘 다 이미 노출된 개발 자료다. v9의 새 학습·선택은 TRAIN/VAL에만 의존하고, 두 자료의 선택을 모두 끝낸 뒤 이번 TEST 비교를 한 번에 수행한다. 과거 봉인을 ‘새 미사용 확증’으로 갱신하지 않는다.

# 4. 비교 방법과 정확한 수식

아래 이름은 v9에서 새로 제안한 이름이며 기존 코드 키라고 가정하지 않는다.

BASE_LEVEL: f*(X), 부모 그대로. 새 fit0.
JOINT_PQ_V8: 기존 v8 두 head 공동 재학습 결과. 새 fit0, 참고 비교.
STAGED_P: f*(X) + H_P(deltaX P).
STAGED_RAW: f*(X) + H_RAW(deltaX).

H_P와 H_RAW는 각각 공유·무편향·무활성화 Linear(512,32)→Linear(32,48), 새 학습 파라미터17,920개. base LEVEL은 학습 이력이 있는 G17,920개를 갖지만 현재는 고정한다. 누적 적합된 어댑터 변수는35,840개이며, 이번 단계에서 optimizer가 갱신하는 것은17,920개다. 전체 기반 모델 크기는 그대로 필요하다.

두 head의 초기 down weight는 같은 dataset·seed에서 정확히 맞추고 up은 모두0으로 한다. 가능하면 v8의 해당 seed P-head 초기 텐서를 복원해 동일한 시작값을 재사용하고, 그 출처를 검증한다. 없으면 v8의 확인된 독립 RNG 규칙으로 결정적으로 생성하고 일치 범위를 보고한다. 학습된 v8 H를 가져오지 않는다.

초기 STAGED_P와 STAGED_RAW의 함수는 둘 다 학습된 BASE_LEVEL과 같다. 두 모델은 동일 부모·새 head 수·초기 head 값·TRAIN 표본 순서·학습 및 선택 기회를 받는다.

STAGED_RAW는 과거 LEVEL_RAW나 RAW64와 다르다. 이미 학습된 LEVEL 위에 원입력 변화 보정 head를 하나 더 얹는 ‘같은 출발점의 대조’다. 기존 RAW64 점수만으로 이 대조를 대신하지 않는다. RAW는 최종 Q도 바꿀 수 있으나, STAGED_P는 이론상 Q 출력을 유지한다.

H_P는 원채널의 PCA 재구성 deltaXP를 입력으로 받는다. v8과 같은 원채널 표현을 유지해 학습 절차를 비교한다. 같은 시간 선형 연산을 전 채널에 공유하므로 출력도 P에 남는 조건을 검사한다. 편향·비선형·새 채널 mixing·별도 P의 last-value 복원은 추가하지 않는다. P의 수준은 이미 부모 main forecast에 있어 중복 가산하면 안 된다.

# 5. 첫 직접 학습: 두 자료를 함께 고정

1차: STAGED_P × Robin/Jena × 두 seed =4 신규 fit.
대응 비교: STAGED_RAW × Robin/Jena × 두 seed =4 신규 fit.
총기본8fit. 대응 RAW까지 처음부터 계획에 포함하여, TEST 결과를 본 뒤 새로운 대조를 즉흥적으로 만들지 않는다. 두 자료의 같은 방법 비교가 모두 완료되기 전에 유리한 자료 하나의 결과로 결론내리지 않는다.

학습 목적은 기존 observed-target channel-macro MSE(f*(X)+H(input),Y). H에는 과거 입력만 제공한다. 별도 미래 P 정답을 추론 입력에 넣거나 이미 노출된 TEST 오류에 맞춰 학습 정답를 만들지 않는다. 새로운 projected-loss로 바꾸지 말고 v8과 같은 전체 관측 MSE를 사용한다.

[제안·미검증] 새 head 학습은 기존 레시피를 출발점으로 고정한다: AdamW LR1e-3/weight_decay0, 새 학습 변수만 clip1, batch4, epoch당512 TRAIN origins, max120epoch, strict VAL nonimprovement6, 기존 plateau scheduler. Robin24/Jena144 phase sampler와 seed/epoch 순서를 실제 코드에서 검증해 동일하게 적용한다. 새로운 LR/K/rank 탐색은 하지 않는다.

기본 checkpoint는 alpha=1 상태에서 step0을 포함한 전체 VAL MSE 최소, 정확 동률은 먼저 나온 상태다. 선택이 step0이면 ‘학습된 P가 필요 없었다’고 보고한다. 모든 보정기가 초기 상태로 선택돼도 그 자체를 학습 실패 버그로 가정하지 않는다. 실제 TRAIN probe·최소 두 step의 head gradient·갱신·VAL 곡선으로 구현 오류와 유효한 음성을 구분한다.

보조 강도 비교를 위해 각 run은 epoch>=1 중 alpha=1 전체 VAL MSE가 최소인 단 하나의 best-trained checkpoint도 저장한다. 이 후보의 선정 규칙은 TEST 전부터 고정하며, alpha별로 모든 epoch를 다시 탐색하지 않는다. 일반 best와 best-trained를 혼동하지 않는다.

명백한 기술 오류의 복구는 예비에서 수행한다. 학습상한에서 아직 strict 개선이 계속되는 경우의 단 한 차례240epoch 연장을 넣으려면 계획에서 동일 자격 규칙·예비 소모를 먼저 확정한다. 정상 조기 종료를 LR/seed 무한 탐색으로 바꾸지 않는다. 무효 parent 복구·head 재시도·연장을 합쳐 예비4를 넘기지 않는다.

# 6. 보조 분기: 단일 보정 강도, 학습과 분리

[제안·미검증] 기본 무조절 비교를 대체하지 않는 제한된 후처리 비교를 계획에 포함한다.
S_alpha(X)=f*(X)+alpha H(input), alpha∈{0,0.25,0.5,0.75,1}.

각 run의 사전에 정한 best-trained H 하나에 대해 전체 기존 VAL MSE로 alpha 하나를 선택한다. 정확 동률은 작은 alpha, alpha0은 부모 복귀다. dataset·seed마다 동일한 규칙을 적용하고 STAGED_P와 STAGED_RAW 모두 같은 기회를 준다. 전역 상수 하나이며 channel/horizon/window마다 다르게 고르거나 TEST 값으로 routing하지 않는다.

H 학습 중 alpha는1로 고정한다. alpha0과 up0을 함께 학습시키는 구조로 gradient를 막지 않는다. alpha를 새 trainable gate로 만들지 않는다. 이5개 후보의 VAL 계산은 새 신경망fit0이지만 시간과 선택 횟수를 계상한다.

기본 모델(alpha1에서 step0 포함 checkpoint 선택)과 보조 모델(best-trained 하나+VAL alpha 선택)의 결과를 따로 표기한다. alpha1이 선택되면 강도 수정이 불필요한 것이고, alpha0이면 기존 LEVEL로 복귀한 것이다. 여러 checkpoint×여러 alpha의 대규모 탐색이나 TEST 뒤 alpha grid 변경은 금지한다.

VAL에 alpha0이 포함돼 있다는 것은 해당 선택 VAL에서 baseline보다 나쁜 후보를 강제로 고르지 않는다는 뜻이지 미래 TEST 비열화 보장이 아니다. 두 자료의 alpha를 TEST 결과로 사후 지정하지 않는다. 대부분 alpha0인 결과를 P 보정의 범용 성공으로 세지 않는다. 동일 VAL의 재사용에 따른 선택 편향과 추가 기회를 보고한다.

# 7. 무결성 점검: 보호할 함수와 학습할 함수

- 부모의 train/eval/dropout 상태·parameter·buffer·normalization·PCA까지 고정하고 optimizer에서 제외한다. 새 wrapper.train()이 부모를 train mode로 바꾸지 않도록 한다.
- 부모 출력과 P 입력의 고정 계산은 no_grad로 처리할 수 있지만 새 H forward는 autograd 밖으로 빼지 않는다. inference_mode tensor를 잘못 재사용해 head weight backward가 실패하거나 끊기지 않는지 확인한다.
- 초기 full output=부모 output, 저장/재시작 후 full output 정합성을 실제 과제 형상으로 확인한다.
- P head 학습 전후 부모 해시가 같고, 새 head는 실제로 갱신되는지 검사한다. 첫 step down gradient0은 zero-up 초기화에서 정상일 수 있으며 그다음 갱신을 확인한다.
- STAGED_P의 correction Q≈0, 최종 prediction Q≈parent prediction Q를 고정된 수치 허용오차로 검사한다. alpha를 쓰더라도 같은 범위를 확인한다. 이 구조 성질과 전체 TEST MSE 비열화는 다른 주장이다.
- 결측 target을0으로 채워 P/Q 투영하지 않는다. P/Q 오류는 같은 완전관측 target subset에서만 계산하고 coverage를 보고하며 원래 masked macro MSE와 구분한다.
- 부동소수점 오차는 실제 max difference·위반 원소수로 보고하고 통과할 때까지 허용오차를 늘리지 않는다. 기본은 기존 v8/v7 parity 계약을 실제 확인해 사용하고 필요한 변경은 영향과 이유를 남긴다.
- checkpoint에는 새 head·spec·alpha와 부모 checkpoint/초기파일/코드/PCA 출처를 복원 가능하게 연결한다. 미학습 부모를 다시 만드는 restore는 금지한다. 외부 부모 파일 의존이 있으면 manifest에 명시한다.
- 초기/선택/재시작 검사는 필요한 합성 세션에 묶고, 테스트 PASS를 과학적 효능 증거로 세지 않는다.

# 8. 평가와 비교 해석

두 자료의 모든 필수 fit·checkpoint·보조 alpha를 TRAIN/VAL로 확정한 뒤 새로운 결과를 평가한다. 둘 다 노출 개발자료이며, 새 봉인은 회차의 선택 경계 기록일 뿐 새 독립 확인을 만들지 않는다. TEST 이후 추가적합·alpha 재선택·시간/채널 제외·새 seed를 수행하지 않는다.

필수 비교:
1) STAGED_P vs 동일 parent BASE_LEVEL: P의 추가 가치.
2) STAGED_P vs JOINT_PQ_V8: 이미 학습된 LEVEL을 보존하는 단계적 절차의 실용 효과. 초기화·학습 단계·총비용이 달라 pure causal isolation이 아님.
3) STAGED_P vs STAGED_RAW: 같은 부모와 추가 head에서 P 제한의 가치.
4) 보조 alpha 정책 vs 기본 무조절 및 BASE_LEVEL: 선택/축소가 어떤 이득·복귀를 만드는가.
5) F0/LoRA/DIRECT_NLINEAR 및 기존 RAW64: 남은 실용 격차, 모두 기존 유효 예측을 같은 계약으로 재사용.

주 MSE, 보조 MAE, 두 seed·각 기간·전체·채널 오차 및 signed bias를 남긴다. 전체는 채널별 기간 SSE/count를 합친 뒤 채널 평균, seed별 손실 평균이지 prediction ensemble이 아니다. 서로 다른 자료 MSE의 단순 평균이나 임의 종합점수는 만들지 않는다. 주 비교를 가장 유리한 분모로 바꾸지 않는다.

기존 같은 조건의 block bootstrap(Robin7/Jena42 origins,2000 resamples)을 재사용할 수 있다. 두 seed를 고정한 조건부 구간이고 alpha/parent/방법 선택 전체의 불확실성을 나타내지 않는다는 제한을 쓴다. 새 p-value 기준·비열등성 합격선·개선율 목표를 만들지 않는다. 0 포함은 동등성도 실패 증명도 아니다.

별도 표에 parent epoch/seed, head best epoch, alpha, 실제 head-only step/time, parent 학습 이력, P/Q 변화와 남은 LoRA/NLinear 차이를 연결한다. 함수 보존만 확인하고 정확도 개선 완료라고 선언하지 않는다.

# 9. 비용: 유지 가능성이 있는 결과에 한정해 같은 자료에서

이번 실제 사용 예산은 재사용 parent를 다시 학습한 것처럼 세지 않는다. 그러나 새로운 target에서 이 방법을 쓰는 총 적응 비용은 ‘부모 LEVEL 적합+P head 적합(+VAL 선택)’이다. head 단계만 보고 총 학습이 v8보다 저렴하다고 하지 않는다. 과거 parent와 새 head 시간이 다른 세션이면 합산은 역사적 추정으로 표시하며 엄밀한 same-session training-speedup은 주장하지 않는다.

단계2 trainable17,920 / 누적 적합 어댑터35,840 / 전체 배포모델 / 추가 alpha1개를 구분한다. alpha0이면 head를 배포에서 제거할 수 있으나 그것은 새 P 보정의 효능이 아니라 부모 복귀다.

신규 적합은 끝났는데 과제상 의미 있는 후보가 남지 않으면 비용 benchmark를 더 채우지 않고 이유를 기록한다. 유지할 후보가 남는 자료는 Robin이든 Jena든 그 자료에서 비용을 측정할 수 있도록 이번 계획에 사전 승인한다. 결과를 보고 Robin timing을 Jena에 이식하지 않는다.

측정 대상은 해당 자료의 BASE_LEVEL, 기본/선택 STAGED_P, STAGED_RAW, 기존 JOINT_PQ_V8, F0·병합LoRA 및 유효 DIRECT_NLINEAR 중 결정에 필요한 최소 집합을 계획에서 확정한다. 과거v7 full/chunk 결과와 비율을 직접 만들지 않는다. 압축의 독점 메모리 우위를 다시 주장하지 않으며, 그 주장을 할 때는 기존의 출력동등 미압축 소배치 참조도 같은 세션에 포함한다.

같은 장치·FP32·TF32off·CPUthreads4·전체 원채널 출력, B1 지연/B4 처리량·peak allocated/reserved·배포bytes를 구분한다. 기존 계약의VAL24, warm10,20 passes,3 orderblocks와 sentinel 변동을 보존한다. 모델load/원장/채점은 밖, full online parent+head forward와 전송은 안이다. TRAIN-only 캐시로 부모 예측을 가속해 학습했더라도 배포 timing에서 부모 forward를 생략하지 않는다. 별도 compile/양자화/시스템 튜닝은 금지한다. 비용 원인 미확정은 정확도 비교 완료를 막지 않는다.

# 10. 계획 합의용 예산과 분기

[제안·미검증] 신규 기본8fit=STAGED_P4+STAGED_RAW4, 예비4fit, 전체 최대12attempt. 예비는 parent 복구·기술 재시도·계획에 정한 상한 연장에만 사용한다. 새 후보·데이터 확대용이 아니다. parent가 모두 존재하면 새 parent fit0이다.
GPU1장/동시학습1개, GPU 전체 job 점유7200초(2시간), 합성 optimizer 검사최대6세션·세션전체10update 이하, CPU 검사누적900초, 신규저장5GiB, 다운로드0. 기존 v8의8fit/GPU약9분은 참고 규모이지 완료시간 예측이 아니다. v9은 부모 재생·head 평가·조건부 비용도 포함하므로 계획에서 여유를 배분하고 승인 후 자동 증액하지 않는다.

모든 fit/실패/재개/합성optimizer/GPUjob을 공통 원장에 실행 전에 예약한다. CPU 구문·문서 검사는 예약된 검사 세션으로 묶는다. 부모GPUjob과 내부fit 시간은 이중 계상하지 않는다. 문헌/파일 읽기를 fit으로 세지 않는다. 다른 프로젝트 프로세스 종료·전역환경/전력/driver 변경·유료서비스·새 서버·보안권한 우회는 금지한다.

사전에 정할 결과별 의사결정:
- 같은 규칙의 STAGED_P가 Robin의 손해를 줄이고 Jena 이득도 유지: 대체 후보로 조건부 유지, 실제 비용·단순 대안과 남은 차이를 보고.
- P는 불리하고 alpha0 복귀가 대부분: 기존 LEVEL 보존은 됐지만 추가 적응의 가치 미확보.
- STAGED_RAW도 같거나 더 유리: P 제한의 고유 추가 가치 축소, 단순 side correction으로 설명.
- Q를 보존했는데 P 때문에 악화: Q 재학습만이 원인은 아니라는 결론, 무단 새 보정기를 추가하지 않음.
- 두 자료 중 한쪽만 양성: 조건부 효과와 반례를 같이 보고; TEST 기반 자료별 선택정책을 만들지 않음.
- 기술무효/상한/필수자료 미확보: 과학적 음성과 구분하고 유효 비교/미완료 범위를 보고.

이득이 있으면 그 범위의 발전을 인정하고 무조건 ‘주제 미확보’로 되돌리지 않는다. 반대로 alpha0 복귀·VAL-only 개선·불확실한 작은 차이를 범용 대체 성공이라고 부르지 않는다. 남은 예산을 채우기 위한 추가 실험은 하지 않는다.

# 11. 산출물과 자율 실행

승인 후 실제 계획 본문과 승인문을 원문 그대로 PLAN.md/APPROVAL.txt에 남긴다. 요약이 필요하면 별도 문서로 만들고 원문처럼 표시하지 않는다. 이 설계 요청문과 실제 승인 계획도 구분한다.

새 연구 폴더의 STATUS, 부모/자료/초기값 reuse manifest, 실행별result/curve/checkpoint receipt, 선택·alpha기록, 전체 비교JSON/CSV, Q보존과P오차진단, 조건부 비용, TOPIC_DECISION, 검산·게시기록을 연결한다. 기존 원고를 덮어쓰지 않고 방법 중심의 짧은 결과 업데이트/부록 초안만 만든다. 긴 전체 원고 재작성과 제출은 이번 필수가 아니다.

TOPIC_DECISION은 ‘무엇을 보존했는가 → 무엇을 새로 학습했는가 → 기존 LEVEL/v8/대응RAW보다 무엇이 달라졌는가 → 언제 alpha가 켜졌는가 → 추가 비용 → 대체 후보 판정’ 순서로 작성한다. dataset 이름별 개발 일지만 나열하지 않는다.

수리 가능한 같은 범위의 경로·직렬화·autograd·집계 오류는 실패 원본·영향·diff를 보존하고 재승인 없이 수리해 계속한다. 목표·데이터·총예산·새구조의 실질적 변경만 다시 보고한다. 첫 실행 상태부터 실제 폴더·완료산출물·PID/예산을 기록하고 파일만 읽고 종료하지 않는다.

관련 신규 파일과 색인만 개별 검증·일반 commit·origin/main push 후 실제 원격 SHA를 확인한다. 기존 v1~v8와 무관파일 보존, force push/이력삭제/hook우회 금지. 세션 재개 시 PLAN/STATUS/원장/실제 프로세스부터 읽고 중복 실행하지 않는다. 코드PASS·실험개선·논문기여·제출준비를 구분한다.

이번 /plan 응답 마지막에는 ①실제 부모LEVEL과재사용범위 ②두새수식과동결/학습변수 ③두자료기본8fit ④기본checkpoint/alpha보조선택규칙 ⑤예비4와총예산 ⑥완료·중단·결과별결정 을 한 표로 정리하고 전체 실행계획의 승인만 한 번 요청해라.
