2. 목적에 필요한 최소 진단

질문은 “왜 못했는지 완벽히 증명하라”가 아니라 “첫 수정에서 어느 부분을 바꿀지 결정하라”다. 계획 단계에서는 존재하는 기록을 읽고, 승인 후 다음 진단을 수행한다.

A. 오차 위치와 형태
- 동일 원점·채널·horizon·mask에서 RES 대 LoRA/F0 및 대응 RAW/LINEAR의 손실 차이를 본다.
- 채널별·시간별 MSE/MAE와 부호 있는 평균오차를 구분한다. RES 자체의 손실 기여와 비교군 대비 초과손실 기여를 분리한다.
- Hog TEST-A/B를 모두 유지한다. 손해가 큰 몇 채널을 먼저 시각화할 수 있지만 전체 지표에서 제거하지 않는다.
- 필요한 경우 예측 편향·큰 오차·최근 입력 수준/변동·입력 결측 여부를 연결한다. 시점이 다르다는 것만으로 계절 변화나 분포 이동을 원인이라고 단정하지 않는다.

B. 주경로 공간 안/밖
- 같은 기준 RES decoder의 채널 공간으로 모든 비교군의 오차를 분해한다.
- FIXED PCA에서는 Q=VV^T가 가능하지만 학습된 CURRENT에서는 DE를 직교투영으로 취급하지 않는다. decoder 열공간의 수치적 직교기저를 사용하고 rank 처리 조건을 기록한다.
- 미래의 원채널 값이 모두 관측된 벡터에서만 완전관측 공간 분해를 직접 계산하고, 해당 원점/시점의 커버리지를 보고한다. 결측 목표를 0으로 채운 뒤 투영하여 참오차라고 부르지 않는다.
- 이 부분집합의 분해 합과 원래 전체 masked macro MSE를 혼합하지 않는다. 원래 주 평가는 계속 전체의 관측 mask를 사용한다.
- Bull의 과거 공간 밖 손해 비율을 Hog에 그대로 적용하지 않는다. 공간 분해만으로 정보의 예측 가능성이나 성공 원인이 증명됐다고 하지 않는다.

C. 입력 잔차와 학습 상태
- 과거 잔차의 최근 수준·변동 폭과 실패 패턴, 고정 TRAIN probe/VAL의 초기·선택 점수, 실제 선택 epoch를 확인한다.
- 평균/scale은 실제 추론 시점의 과거 입력에서만 계산하는 조건을 지킨다.
- 모든 epoch의 checkpoint나 중간값이 저장됐다고 가정하지 않는다. 기존 최적 모델을 복원한 최소 추가 추론은 허용한다. 기존 cache를 못 읽는 항목은 제한을 보고하고 직접 비교 가능한 분기로 진행한다.

진단이 덜 완벽하다는 이유로 학습을 무기한 미루지 마라. 승인 후 최초 진단의 운영 한도는 GPU 작업20분/CPU분석30분을 출발안으로 제안한다. 이는 원인 판정 합격선이 아니라 분석 과잉을 막는 시간 배분이다. 한도 안에 확보한 근거로 첫 후보를 선택하거나 사전 승인한 단순 기본 후보를 시험한다. 수치는 승인 전에 실제 환경에 맞게 조정할 수 있다.

A. LEVEL — G의 수준 제거·복원(신규 제안 레이블)
- 지속적인 수준 차이가 관찰되면, 과거 잔차 r의 마지막 값 또는 문맥 평균을 제거하고 복원하는 단순 변형 하나를 고른다. 사용할 통계는 PLAN에서 고정한다. 출발 기본안은 NLinear의 마지막 값 방식이다.
- 예: G_level(r)=repeat_H(r_last)+G_theta(r-repeat_L(r_last)). 공식 원형과 달리 rank32/bias없는 G를 유지한다면 그 차이를 명시한다. 이를 NLinear 전체 재현이나 새 정규화 발명이라고 부르지 않는다.
- 마지막 값의 detach 여부, 결측 입력의 기존 대체 처리, 채널별 통계 축을 명시한다. 미래 정답이나 미래 관측 mask로 통계를 만들지 않는다.
- RAW 보정기에 무조건 원입력의 마지막 값을 더하면, 주경로가 이미 예측한 공통 수준까지 다시 더할 수 있다. 이처럼 RAW에 불리한 초기 함수를 만든 뒤 잔차 정보의 우위라고 하지 마라.
- 이에 대한 기본 대응 설계[추정·미검증]: b(X)=D(F0(E(X))), r=X-D(E(X)), p(u)=각 채널의 마지막 값, P_L/P_H=그 값을 과거/미래 길이로 반복한 배열로 정의한다. LEVEL_RES=b(X)+P_H(r)+G_theta(r-P_L(r)), LEVEL_MATCHED_RAW=b(X)+P_H(r)+G_theta(X-P_L(X))를 비교한다. 두 팔이 같은 잔차 수준복원항 P_H(r)를 받고, 학습 분기의 중심화된 입력만 다르다. 이 RAW는 v4 RAW와 구분한 신규 대응 대조 이름이다. 원래 RAW 점수도 별도 참조로 남긴다.
- G_theta 출력층0이면 두 새 팔은 모두 b(X)+P_H(r)로 시작하며 COMPRESS가 아니다. 바로 이 같은 함수의 무학습 LEVEL_ONLY 참조를 계산해, 기본 수준 복원만의 이득과 추가로 학습한 시간 예측의 이득을 구분한다. 더 나은 대응 설계가 있으면 승인 전 수식·초기함수·정보/gradient 차이를 설명한다.
- 원형처럼 p를 detach할지 여부를 두 팔에 일관되게 적용하고 기록한다. 앞의 공통항은 정답에서 만든 보정이 아니라 과거 X/E/D에서 계산한 값이어야 한다. 같은 수준복원항을 쓰더라도 E/D 공동학습에서는 이후 내부값이 달라질 수 있으므로 순수 인과분리라고 주장하지 않는다.
- 초기 출력 보존을 위해 새 gate까지 의무적으로 붙이지 않는다. 필요한 경우 별도 설계·대응 대조로 승인 계획에 명시한다.
- 중요: 별도 affine/bias/비선형이 없는 선형 G에서 채널별 같은 scale로 나누고 다시 곱하면 순전파에서 scale이 상쇄될 수 있다. s*A((r-m)/s)+m=A(r-m)+m이다. 실제 수식을 먼저 단순화하여 동일 함수인 ‘평균만/평균+scale’을 별개의 방법 후보처럼 반복 학습하지 마라. RevIN의 원래 학습형 affine까지 있는 경우와 이 특수 경우를 구분한다.

B. FULL_LINEAR — 시간 rank 제약 완화(신규 제안 레이블)
- 공간 밖의 시간 예측 손해가 크고 수준 복원만으로 설명하기 어렵다면, G를 공유 Linear(512,48,bias=False) 하나로 바꾼 단순 대조를 우선 검토한다.
- 파라미터는17,920에서24,576으로 증가한다. 추가6,656개와 실제 비용을 보고한다. 바로 큰 MLP/attention부터 도입하지 않는다.
- 초기 함수는 기존 G의 두 행렬 곱으로 맞출 수 있다. 그러나 동일 초기 함수라도 파라미터화와 최적화가 바뀌므로 순수한 rank 효과만 증명했다고 부르지 않는다.
- 기존 G의 함수군을 포함하는 대조이지 새로운 시간 모델 발명은 아니다. 작은 비선형 대조가 정말 더 적합하면 선행·크기·같은 용량 선형 대조·초기화까지 승인 PLAN에서 정하고, 별도 후보 무한 추가로 확장하지 않는다.

C. K-ALLOCATION — 압축 주경로의 차원 배분(조건부 예비 방향)
- 손해가 decoder 공간 안에 크면 G 확대부터 고집하지 않는다. K를 사전 정한 한 값으로 늘리는 단순 비교 등을 검토한다. 기본 대안은 min(2K,C)이며, 같은 질문의 기존 실행이 있으면 먼저 재사용한다.
- 추가 TSFM 처리 계열 수와 비용이 늘므로 같은 비용의 개선이라고 주장하지 않는다. 원래 전체 F0를 뒤에 또 실행해 더하는 식으로 절감을 숨기지 않는다.
- K 변경으로 난수 소비가 달라져 G 초기값까지 바뀌지 않도록 G tensor를 명시적으로 공유한다.

계획은 A/B/C 중 무엇을 먼저 고를지, 그 선택을 뒤집을 관찰, 최대 두 번째 수정의 정확한 범위를 적어야 한다. 원인이 미확정이면 ‘수준 보정 또는 full linear로 먼저 직접 확인’이 가능하다. 작은 정상 대조를 시작하기 전에 완벽한 원인 증명이나 새로운 난이도 지표를 요구하지 마라.

4. 학습·비교 공정성과 유지할 계약

자료는 기존 Hog·Bull·Electricity의 이미 확보된 TRAIN/VAL/개발 구간만 쓴다. 새 site/새 데이터 수집·다운로드·새 TEST 개봉은 이번 범위에서 제외한다.
- Hog TEST-A/B, Bull E1/E2, Electricity DEV는 v5에서는 모두 노출된 개발 평가다.
- 가중치 적합·PCA·전처리 적합은 TRAIN, 체크포인트와 유한한 설정 선택은 VAL만 사용한다.
- 이미 노출된 개발 결과에서 수정 아이디어를 얻는 것은 개발로 기록할 수 있다. 그러나 그 아이디어를 고른 구간의 점수를 독립 확증으로 부르지 않는다. 원점별 미래 정답을 모델 입력/게이트/라우팅에 넣지 않는다.
- 원래 채널·정답 mask·표준화·L512/H48·주 macro MSE를 유지하고 MAE, 기간별/seed별·채널별 손익과 비용을 함께 본다. 사후 채널 삭제·클리핑·분할 교체·불리한 seed 생략으로 개선을 만들지 않는다.
- E/D 모드는 우선 Hog FIXED K8, Bull FIXED K4, Electricity CURRENT K8를 유지한다. 모드 탐색 자체를 다시 전부 돌리지 않는다.
- 각 비교는 같은 자료의 학습 전 PCA/가능한 G 초기값·seed92601/92602·TRAIN 표본 순서·optimizer·학습량 정책을 맞춘다. v4의 RAW step0 결과는 정당한 참조다. 새 RAW가 나쁘다고 임의로 제외하지 않는다.
- 초기함수가 달라지는 수정은 그 차이를 기록하고 무학습 수준복원 등 필요한 단순 참조를 둔다. 첫 비교는 원칙적으로 같은 학습 전 상태에서 독립 적합한다. 기존 최적 RES만 warm-start하면 RAW·계속학습 기준에도 같은 기회를 주는 별도 계획이 필요하다.
- 기존과 자료·모델·선택 계약이 같은 baseline의 checkpoint/예측은 재사용한다. 새 설정에 맞지 않거나 파일이 없는 baseline만 재실행하고 예산에 포함한다. Electricity v1 초기값의 완전 동등성이 확인 안 된다는 기존 한계를 보존한다.
- 출력층0의 첫 step에서 G 앞층 gradient가0인 것과 영구 단절을 구분한다. CURRENT에서 E로의 gradient를 끊지 말고, FIXED의 새로운 학습 모듈을 no_grad에 넣지 마라. 실제 갱신·frozen불변·저장/재시작 복원을 확인한다.
- FIXED E/D·F0 출력은 TRAIN/VAL 학습 가속용으로 cache할 수 있지만 동일 예측 정합성을 확인한다. CURRENT E/D의 달라지는 출력을 고정 cache로 대신하지 않는다. 배포 비용은 cache 없이 전체 forward로 잰다.

기본 학습 레시피는 실제 기존 최종 실행에서 가져온다. LR1e-3, AdamW/weight decay0/clip1, epoch당위상균형512원점·batch4, 최대120epoch·patience6·plateau scheduler가 출발안이다. 변경에 따라 한 개의 대응 LR 보완이나 수렴 보완이 필요하면 trigger·대상·예산을 PLAN에 적는다. ‘모든 step0은 버그’ 또는 ‘patience 종료면 최적 수렴 증명’으로 취급하지 않는다.

5. 실제 개발 루프와 순서

권장 경로(계획에서 실행 가능한 분기표로 구체화):

1) 기존 Hog 오차/가능한 공간·수준 진단 → 첫 수정 선택.
2) Hog에서 수정 RES와 동일 수정 RAW를 각 두 seed로 실행: 신규4fit.
3) 판단에 도움이 되는 수정을 Bull·Electricity의 동일 수정 RES/RAW 각 두 seed로 확인: 신규8fit. 다른 자료는 사후 골라 버리지 않는다.
4) 첫 수정이 무차이·악화하거나 다른 자료에서 큰 역효과가 드러나고, 근거 있는 예비 수정이 승인돼 있으면 최대 두 번째 수정으로 이동한다. 그때도 필요한 대응 RAW·두 seed·기존 자료 손익을 유지한다.
5) 개발에서 선택한 최종 구성과 가까운 대조의 비용·저장 증거를 확인하고 유지/수정/보류를 판정한다.

첫 수정이 충분하면 두 번째를 억지로 실행하지 않는다. 첫 음성에서 유효한 승인 분기를 남기고 종료하지도 않는다. RES만 먼저 몰아서 개발한 뒤 RAW 비교 예산이 없어지는 계획을 만들지 마라.

수정은 처음부터 LEVEL+FULL_LINEAR+K변경을 한꺼번에 합치지 않는다. 하나의 변경을 먼저 판별한 뒤 다음 행동의 근거를 적는다. 구성 결합이 필요한 경우 순차 변경과 각각의 대조가 가능한 범위를 승인받아야 한다.

Hog만 좋아지면 ‘Hog 개발 개선’, 다른 자료에도 남으면 그 범위를 추가로 인정한다. 작은 또는 엇갈린 이득에 근거 없는 합격선을 붙이지 않는다. 표준 처리나 단순 참조만으로 충분하면 더 복잡한 후보를 채택하지 않는다.

6. 측정과 판단

정확도는 기존 RES·동일 수정 RAW·해당 자료 F0/LoRA·필요한 기존 LINEAR/SHARED 점수와 비교한다. 이번 목적은 F0/LoRA와의 손해를 얼마나 줄였는지도 보는 것이므로 RAW만 이긴 것으로 완료를 선언하지 않는다.

기존 RES 대비 절대/상대 MSE·MAE, LoRA 대비 남은 차이, 각 기간·seed·채널을 남긴다. 서로 다른 자료의 정규화 MSE를 합쳐 단일 평균 우승자를 만들지 않는다. 겹친 목표·채널을 독립 반복으로 세지 않는다. 원수치와 단위·분모를 명시하고, 불확실성은 개발에 조건부임을 표시한다.

최종 비용은 우선 Hog의 최종 수정 RES/RAW, 기존 RES, F0·병합 LoRA의 필요한 선택 모델만 같은 세션에서 재측정한다. 다른 자료에서 비용 주장을 할 경우 그 자료에서도 같은 조건으로 짝지어 측정한다. 모든 중간 후보/모드를 다시 benchmark하지 않는다.

기본 조건은 현재 장치·FP32·같은 thread·입력/전체 출력·batch1/4, 예열10회·동일 VAL24원점20회·순서3블록이다. 설치 환경에 맞춰 사전 고정한다. 로드·채점·원장 쓰기는 시간 밖, CPU→GPU→원채널 전체 CPU출력 범위와 peak allocated/reserved·학습 파라미터·배포 크기는 구분한다. LoRA는 병합 반환 모델과 출력 정합성을 확인한다.

v4의 불안정한 속도 중앙값을 새 실행과 직접 나눠 개선율을 만들지 않는다. 블록별 변동을 남기고 안정적 우위를 못 확인하면 제한을 쓴다. 비용의 근본 원인 규명을 정확도 개발의 필수 진입 조건으로 삼지 않는다. 이번은 새로운 compile/quantization/전력설정 최적화 프로젝트가 아니다.

7. 승인할 자율 범위·예산 제안

[추정·미검증] 새 회차 제안 상한:
- 실제 데이터 적합 최대24attempt. 두 수정×세 자료×RES/RAW×두 seed까지의 최대규모이며, 재시도·CPU 적합·필수 baseline 재현도 이24회 안이다. 전부 실행해야 하는 목표 횟수가 아니다.
- 첫 Hog 비교4회, 한 수정의 세 자료 대응까지12회가 기본 진행 단위다. 남은 예산에서 두 번째 수정·대조·복구 중 다음 판단을 바꿀 것만 실행한다. 새 분기는 필요한 짝비교를 닫을 수 있는 잔여 예산을 먼저 확인한다.
- 로컬 GPU 한 장, 동시 학습1개, GPU 작업 점유 누적4시간. 학습·실패·복원·진단·추론·비용을 포함하고 상위 GPU job/하위 fit를 중복 가산하지 않는다.
- 합성 optimizer 검사 최대6세션, 세션 전체 업데이트 합계10step 이하, CPU 검사 누적15분. GPU를 사용하면 GPU시간에도 포함한다.
- 신규 저장5GiB. 새 raw·백본 다운로드 기본0. 필요한 논문/공식 문서 읽기는 모델 다운로드와 구분한다.

근거: v4는19fit와 비용·검산을 GPU약21.53분에 마쳤지만, v5는 세 자료/수정/추론을 포함하므로 완료시간을 그대로 예측할 수 없다. 4시간은 개발 여유를 둔 운영 상한이지 성공 예상시간이 아니다. 실제 로컬 자원·캐시·필수 대조가 다르면 승인 전에 더 적절한 상한을 제안하라.

기존 원장 코드를 필요한 최소 범위에서 재사용한다. 모든 실자료 fit(데이터에 맞춘 ridge/상수/게이트 포함), 재시도·새 resume는 시작 전에 예약하고 이름 변경으로 계상을 피하지 않는다. TRAIN 통계/PCA 재계산·무학습 진단은 적합 횟수와 구분하되 시간은 남긴다. 실패 후 소진 기록을 지우지 않는다. worker는 실제 GPU/optimizer 작업을 임의로 중복 시작하지 않는다.

승인 후에는 같은 질문·자료·수정 후보·예산 안의 구현 오류를 원본과 diff를 남겨 고치고 계속할 권한을 준다. 과거 실험의 단발/무수정 규칙을 v5에 자동 적용하여 매번 멈추지 않는다. 그러나 예산 증액·새 서버·유료 서비스·다른 작업 종료·시스템 전역 변경·권한 우회·새 자료 사용은 승인 밖이다.

충돌 시 실제 PID/활동을 확인하고 다른 작업을 종료하지 않는다. 진행 없는 자신의 작업은 상태를 기록하고 승인된 복구 규칙 안에서 처리한다. 중단/재개 시 PLAN·STATUS·원장·프로세스·완료 결과를 읽어 중복 적합하지 않는다.

최소 산출물:

- 조건부 개선: MSE/MAE 또는 자료별 손익이 갈린다. 무엇을 얻고 잃는지와 선택할 조건을 남긴다. 결과를 보고 새로운 허용 오차선을 만들어 PASS로 바꾸지 않는다.
- 개선 미확보: 허용한 비교를 제대로 수행했지만 유지할 변경이 없다. v4의 잔차 경로 양성 근거까지 폐기하지 말고 이번 수정 후보를 보류한다.
- 실행 차단/비교 불충분: 없는 파일·권한·예산 때문에 무엇을 못 했는지 명시한다. 미실행을 방법 음성 결과로 바꾸지 않는다.

추가 가치가 남으면 더 검사를 만들어 끝없이 보류하지 마라. 반대로 진단만 완료했다고 정확도 개선 목표가 달성됐다고 하지 마라. 필요한 비교가 끝났거나 근거 있는 허용 다음 행동이 없으면 예산을 채우려고 반복하지 않는다.

관련 파일만 일반 commit·origin/main push하고 원격 반영을 확인한다. 기존 v1~v4·무관 dirty/미추적 파일을 보존하며 raw/cache/가중치/예측 배열·비밀정보를 게시하지 않는다. force push·hook 우회·이력 재작성은 하지 않는다.

9. 지금 제출할 계획의 형식

다음 의사결정이 읽히는 한 계획을 제출하고 사용자 전체 승인을 기다려라.
1) 목표와 현재 근거/미확정 원인.
2) 실제 재사용할 데이터·모델·가중치·예측의 확인 범위.

4) 실제 첫4fit와 다른 두 자료까지 연결되는 대응 RAW 포함 실행·분기·예산표.
5) 학습/평가·수리·자율권·종료·게시 계약.

추가 확인 질문은 읽기로 해결되지 않고 다음 행동을 바꾸는 것만 최대2개 하라. 다시 처음부터 주제를 찾거나 Time-PEFT의 문제정의를 맞추는 탐색으로 돌아가지 마라. 이번에는 기존 후보의 정확도 손해를 줄이는 작은 개발을 실제로 마무리할 수 있는 계획이 필요하다.
