## A. 네 역할과 의사결정 목표

너는 이 저장소의 연구용 CLI 에이전트다. 정해진 실험 세트를 기계적으로 수행하는 실행기가 아니라 **실패 가설을 분해하고, 결과를 본 뒤 가장 정보가 큰 다음 실험을 선택하는 연구자**로 행동한다. 다만 사용자 승인 계획, 평가 데이터 사용 경계, 자원 예산, 연구 목표를 자의적으로 바꿀 권한은 없다.

**최상위 목표:** 교수에게 보고할 근거를 확보한다. **다변량 입력 X의 채널 수 C를 K≪C로 줄여 고정 Chronos-Bolt를 이용할 때, (a) 미래 예측에 유용한 공통 패턴이 실제로 살아 있는가, (b) 그 패턴이 단순 잠재 예측기가 아니라 특히 Bolt를 거칠 가치를 만드는가, (c) 원채널 현재값/저비용 잔차와 결합해 Raw Bolt 및 단순/표준 대안 대비 정확도-전체 추론비용 측면에서 유리한 조건이 존재하는가**를 판단한다.

결과는 성공/부분/실패/불충분을 모두 허용한다. 목적을 '새롭고 복잡한 모델을 하나 반드시 성공시키기'로 바꾸지 않는다. **모델 구조보다 문제의식과 판별력을 우선한다.**

2. 기존 연구에서 얻은 것과 미검증을 증거표로 정리한다. 반드시 다음 범위를 포함하되 없는 것은 보고한다:
   - `research/professor_compressor_direct_20261011/` (원형 TS2Vec/GTConvAE·Decoder A/B; GTConvAE는 채널이 아닌 주로 시간 압축),
   - `research/forecast_component_study_20261013/` (예측 목적 E/D·학습 시작점 변화·학습 일반화),

   - `research/tsfm_peft_internal_vs_subspace_v11_20260930/` (학습형 U, 보정/LoRA/원자료 NLinear 대조 — 새 실험인 양 중복하지 말 것),
   - `research/smallk_failure_followup_20261014/` v1/v2/v3 (E/F/D 분리, 직접 readout, MAIN 유지 잔차 보정),
   - 해당 과거 LEVEL PCA+잔차 구현.
3. 선행연구 원문 또는 공식 설명을 확인한다. 기본 후보: *Forecastable Component Analysis*(ICML 2013), *Temporal Regularized Matrix Factorization for High-dimensional Time Series Prediction*(NeurIPS 2016), *Think Globally, Act Locally*(NeurIPS 2019), *TS2Vec*(AAAI 2022), *AdaPTS*(ICML 2025). 각 후보에 **기존 연구와 실질적 차이, 동일 전제, 실패 위험**을 적는다. 논문을 읽지 않았으면 '미열람' 표시. 기존 어댑터·미래예측 손실·학습형 투영을 신규로 주장하지 않는다.
4. 사용 가능한 **실제 데이터, C, 길이, 관측 마스크, FIT/TUNE/DEV/TEST 분할, 예측 시작점, H, 표준화·지표·평가 노출 이력**을 실제 코드/manifest로 확인한다. 숨겨진 경로를 가정하지 않는다. 이전에 본 Robin/Jena/Beijing의 VAL/EVAL은 독립 확증으로 취급하지 않는다. 보호 TEST는 열지 않는다.
5. 독립적인 '미래 관련 정보'라는 주장이 성립하는지 확인한다: C 간 유용한 공통 신호가 존재하는가? 자기 채널만 쓰는 강한 기준선보다 원채널 다변량 기준선이 실제로 나은가? 이게 성립하지 않으면 공통 패턴 추출에 관한 가설을 과하게 확장하지 않는다.

**승인 게이트:** 위 감사가 끝나면 목표-가설-간단한 대안-선택할 첫 실험-데이터/평가 계약-예산-예상 결과별 후속 분기를 1~2쪽의 Phase 1 계획으로 제시하고 **사용자의 긍정 승인**을 받은 후에만 구현/실제 학습을 시작한다. *기존 대화의 다른 실험 승인으로 새 캠페인이 자동 승인되는 것은 아니다.* 승인 뒤에는 아래 예산·범위 안에서 하위 실험마다 재승인을 요구하지 않고 스스로 적응한다.

## B. Phase 1 승인 후 탐색하는 연구 질문 (고정 실험 목록 아님)

### RQ1. 장기 관측과 패턴 범위가 문제인가?

- 기존 L128 vs L512 비교는 재사용한다. 같은 **미래 예측 시작점과 정답**으로 Raw Bolt의 L512/1024/2048 및 압축 경로의 지원 가능한 범위를 비교한다. 원본 데이터가 2048 길이를 충분히 제공하는지 먼저 확인; 부족하면 무리하지 않고 `INFEASIBLE` 보고.
- 공식 `amazon/chronos-bolt-small` config `context_length=2048`이지만 **실제 고정한 revision/래퍼가 같다고 가정하지 않는다**. 사용 가능한 context를 확인하고, 지원하지 않는 L은 실행하지 않는다.
- 긴 과거를 본 인코더의 **실제 수용영역(receptive field)**이 늘지 않으면 '정보 범위 확대'로 주장하지 않는다. Bolt가 512를 보고 인코더만 2048을 보는 경우도 입력 범위가 서로 다르다는 사실을 분리한다.
- 긴 L 때문에 사용 가능한 origins가 줄었다면 **모든 L에 공통인 origin**으로 짝지은 비교를 만들고, 원래 L512 전체-origin 수치와 별도로 표시한다. 결측 채움이 절단 전 데이터에 의존하지 않는지 검사.
- Raw Bolt도 긴 L에서 비슷하게 좋아지면 '압축의 고유 효과'로 부르지 않는다.

### RQ2. K 표현은 '예측하기 쉬운가'뿐 아니라 원래 미래에 필요한 정보를 보존하는가?

- F가 예측하기 쉬운 정적/상수 표현을 만들어도 전체 원채널 예측에 쓸모가 없을 수 있다. **잠재 분산·유효 차원·채널/시간 변화·해당 표현에서 복원한 원미래 정확도**를 함께 검사한다. 잠재 MSE 단독 최적화 금지.
- 간단한 비교를 먼저: 기존 PCA→Bolt→D 및 v11 learned-U 재사용, 원채널 현재값 보존, 과거/미래 잠재값을 직접 예측하는 저비용 모델(동일 학습 origins), 엄격한 K-only 경로와 current-C 우회 경로 구분. 필요하면 ForeCA/TRMF류의 원리 하나를 선택하되 기존 방식보다 **무슨 전제를 추가로 해결하는지** 명시한다.
- 진짜 미래 잠재값을 쓰는 oracle는 **진단 전용**이며 배포 가능한 예측/최적화 결과로 순위에 넣지 않는다. E 고정·D 고정·예측기만 교체한 근접 대조를 우선해 E/F/D 문제를 구분한다.
- 'TSFM 친화적'의 검증은 (a) 동일 E/D/데이터에서 고정 Bolt가 단순 잠재 예측기보다 실제 미래 원채널 Y를 더 잘 예측하는가, (b) 그 효과가 Raw+동일 보정/단순 다변량 예측과 비교해 남는가로 판단한다. 잠재 autocorrelation이나 주파수 엔트로피만으로 확정하지 않는다.

### RQ3. 예측 가능한 공통 표현과 개별 채널 정보는 결합해야 하는가?

- 고정 K 공통 경로의 예측 결과를 보존한 상태에서 **기존 LEVEL 스킵/잔차**를 우선 재사용한다. 새 보정기의 개선을 부르기 전에 MEAN, ZERO, 원채널과 K의 대조가 있는지 확인.
- MAIN 보정이 Robin에서 ZERO 선택·Beijing에서 작은 MSE 개선과 MAE 악화였다는 기존 결과를 '미해결'로 보존한다. 해당 구조를 이름만 바꿔 재실행하지 않는다.
- 모든 개선을 Raw와만 비교하지 말고 **Raw Bolt+동일 수준 보정**, PCA+동일 보정, 간단한 NLinear/Ridge, 가능하면 AdaPTS 계열의 의미 있게 맞춘 어댑터 대안과 비교한다. 표준 어댑터의 원본 백본이 다르면 '직접 재현'으로 부르지 않는다.
- 원채널 과거의 추가 사용은 '엄격한 K-only 압축'이 아니다. 전체 연산·전송·메모리/시간을 포함해 결합의 순이득을 평가한다.

## C. 자율 실험 선택 규칙 — **매 반복마다 적용**

반복마다 `DECISION_LEDGER`에 다음 6항목을 기록한다.

1. **이번에 알고자 하는 단 한 가지 질문**: 무엇을 구분해야 최상위 판단이 달라지는가?
2. **현 증거 [확인]/[추정]/[추정·미검증]**: 이전 결과를 먼저 재사용한다. 기존 숫자와 새 숫자의 분할/척도 차이를 병기한다.
3. **서로 다른 경쟁 설명 2개 이상**: 예) E의 예측 정보 부족 vs F의 부적합 vs D의 수용영역/일반화 vs 감독 origin 노출/정규화. 근거 약하면 실험 설계를 단순화한다.
4. **가장 저렴하고 반증 가능한 다음 실험 1개**를 선택한다. 그 실험이 긍정·무차이·악화일 때 각각 다음 선택/중단이 어떻게 달라지는지 미리 쓴다.
5. **실행 후 결과**: FIT/TUNE, 2 seed 가능 시 개별값, 주지표 및 MAE, Raw 대비 차이, trainable 계수/입력 정보, 비용, 검산/누출, 가능하면 같은-origin 쌍 차이. 중첩 창을 독립 표본으로 세지 않는다.
6. **다음 결정**: 유지/다른 설명 점검/방법 교체/보류/중단. 새 모듈을 만들 이유가 없으면 단순 대안으로 종료한다.

분기 예시(고정 체크리스트가 아님):
- 긴 입력에 신호가 없으면 입력 확장 중단. Raw에만 이득이면 '압축기 문제'가 아니라 정보 사용 계약 문제를 검토.
- 원채널 미래에 유용한 공통 정보가 적으면 글로벌 표현 기여 가설을 약화/기각하고 잔차만으로 점수를 끌어올리는 방향을 중단.
- 동일 표현에서 Bolt가 간단 잠재 예측기보다 낫지 않으면 더 복잡한 E를 만들기 전에 **Bolt 사용 이유**를 검토.
- 잠재 미래를 잘 예측하지만 원채널 복원이 나쁘면 D와 보존해야 할 정보/현재값 경로를 우선 검사.
- FIT만 개선, TUNE 악화이면 loss 추가보다 데이터/최적화/학습 노출/과적합의 단순 설명을 먼저 점검.
- 개발 TUNE에서 충분한 근거가 생기면 **추가 알고리즘 탐색을 멈추고** 새로운 독립 평가 설계를 제안. 새 보호 TEST는 사용자 승인 전까지 읽지 않는다.
- 어떤 실험에서도 기존 강한 기준선 대비 추가 기여가 없으면 실패 경계/조건을 명확히 보고하고 종료한다. 성공하도록 무한 탐색 금지.

방법 후보를 처음부터 15개씩 학습하지 않는다. 서로 원리가 다른 3개 계열(시간적 예측 가능성 기반 선형 성분, 표준 예측 목적 어댑터, 전역/개별 결합)을 **읽고 비교한 뒤**, 가장 큰 의사결정 공백을 메울 1~2개만 첫 라운드에서 고른다. 필요한 경우만 후속 후보를 추가한다. 표준 해법이 충분하면 신규법 연구는 중단한다.

## D. 고정해야 할 과학적 계약 / 위험

- Primary: 기존 후속 계약의 **FIT 통계 기반 정규화 관측 채널별 macro MSE**. Secondary: 정규화 MAE, 원단위 MSE/MAE, 채널별 지표, 시간 블록, 전체 추론시간·VRAM·학습 시간. 모든 지표는 보고하되 결과 확인 후 주지표 변경 금지.
- Horizon 기본 H=48, frozen Chronos-Bolt-small, 동일 0.5 quantile 사용 여부는 **실행 전 소스에서 확인**. 데이터 계약/모델 revision을 맞출 수 없는 숫자는 직접 랭킹 불가.
- 학습·선택·개발 분석·최종 평가는 분리. FIT 통계만 적용, TUNE로 학습 방법 선택, 반복 DEV/VAL은 확인/진단, 이미 열람한 EVAL은 독립 확증 아님. 새 TEST/보호 TEST 열람 금지.
- 미래 실제값이 인코더/추론 특징/동적 graph/보정 입력으로 들어가지 않게 기계적 교란 테스트 수행. 학습 정답으로 사용하는 것은 별개의 적법한 감독 학습.
- K와 L 비교는 가능한 동일 target origins로 공정 비교. 특히 K=C는 압축이 아님. K가 바뀌면 용량·학습표본·계산비용도 바뀌는 점 기록.
- 우회경로가 같은 C 정보를 사용하는지, 근거 없이 '채널간 의존성 복구', '새로운 그래프'로 명명하지 않는다.
- 캐시·checkpoint는 실행별 불변 artifact. 오류 수정은 실패 원본 보존 + 새 시도. 실행 전 합의한 기여 가설과 지표를 결과에 맞춰 재정의하지 않는다.
- 그림: ① Raw 대비 paired MSE/MAE ② K·history와 비용–정확도 곡선 ③ E/F/D 또는 스킵 분해 결과 ④ 실패·일반화·데이터 지원 경계. 유효 데이터가 없는 패널은 만들지 않는다.

## E. 자원·권한·중단 (합의용 임시 상한)

현재 단계에서 **아래 수치는 [추정·합의용]**이다. 기존 G 캠페인에서 실제 GPU process 약34분/최대45분 규모의 실행을 했으므로, 그보다 넓은 적응형 탐색에 대한 **별도 신규 예산안**으로 제시한다:

- 새 캠페인 GPU process-wall 누적 최대 **90분**, 전체 wall 최대 **4시간**, 신규 저장 최대 **6 GiB**. GPU VRAM은 사전 검사에서 안전한 최대치 이내로 제한. **사용자가 승인하기 전 실제 실행 0회.** 이 상한을 넘기려면 중간 결과와 추가 필요성을 먼저 사용자에게 보고한다.
- 1차는 existing artifact 재사용 + 작은 진단 + 2개 이질적 대안 정도로 제한. 필요하면 중간에 더 적은 실험으로 종료. 강한 증거가 있을 때만 추가 seed/자료로 확대.
- PyTorch/Chronos/데이터 로더/외부 라이브러리 변경이 필요하면 baseline parity부터 다시 검사. 설치/다운로드가 안전하지 않으면 중단/보고.
- **절대 금지**: 사용자 승인 없는 TEST 개봉, 광범위 새 자료 사용 계약 변경, 원본 수정·삭제, 기존 병렬 job 중지, 다른 프로젝트 실행, push/commit, 대형 백본 파인튜닝, 무제한 하이퍼파라미터 검색, 숨겨진 환경변수/자격증명 출력.
- 새 결과는 식별 가능한 새 연구 폴더에 기록하되 **실제 폴더명과 파일명은 리포지터리 관례를 확인한 뒤 새로 지정**한다. 본 문서의 예시 이름은 실제 기존 경로가 아니다. gitignore 보호 자산을 푸시하지 않는다.

## F. CLI 보고 형식

### 실행 전 승인 요청(한 번만)

- Phase 0 목적 트리: 연구 질문 / 예상 결과별 결정 / 기존과 겹치는 작업 제거.
- Phase 1 실행 계획: 첫 분기에서 가장 정보가 많은 최소 비교, 두 번째 분기 결정 규칙, 데이터·분할·C/K/L/H·자원·중단·검산/출처. 수치화 불가 조건은 [추정] 명시.
- '이 계획 승인 후에는 위 범위 안에서 중간 실험별 승인 없이 자동 진행하고, 중단/범위 변경 시 다시 묻겠습니다'라고 적고 사용자 답변을 기다린다.

### 승인 뒤 자율 실행

- `RUN_STATUS.md`: 실제 수행/성공/실패/중단, 종료 시각, HEAD, 코드/설정/가중치/자산 manifest.
- `DECISION_LEDGER.md`: 가설→증거→다음 선택을 매 단계 누적.
- `COMPARISON.csv`: **동일 계약의** Raw / Raw+보정 / PCA / 기존 수준 학습형 E/D / 채택한 새 후보 / 단순 direct predictor, MSE·MAE·추론 비용·trainable 계수·seed. 조건 다른 과거 논문/실험 수치를 이 CSV에 억지로 합치지 않는다.
- `REPORT_KO.md`: ① 무엇을 확인하려 했나 ② 왜 이 실험으로 구분되는가 ③ 결과 ④ 반례/무차이 ⑤ 신규성 반론 ⑥ 최상위 목표 유지 여부 ⑦ 다음 최소 확인.
- `PRESENTATION_BRIEF_KO.md`: 교수님용 5~7장 발표 스토리(문제→방법 차이→Raw 비교→병목→향후 의사결정), 주장 옆 사실·추정 분리.

**완료란 좋은 점수가 나왔다는 뜻이 아니라, 사용자가 최상위 연구 방향을 유지/조건부 유지/보류/기각 중 하나로 판단할 수 있도록 충분하고 공정한 근거가 확보되거나 주어진 자원 내에서 불가능함을 명확히 보인 상태다.**
