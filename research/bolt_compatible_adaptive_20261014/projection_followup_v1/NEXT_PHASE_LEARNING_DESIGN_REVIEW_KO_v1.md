# 다음 학습 단계의 설계 검토 — 조건부 제안이며 이번에는 미실행

작성일: 2026-10-15. **상태: 방법론 검토만 작성 / 새 데이터·NPZ·모델 접근, fit, F, GPU, 비용 실행 0.** 최신 사용자의 현재 작업 마무리·게시 지시에 따라 학습과 기간 확장을 시작하지 않는다. 이 문서는 향후 판단 자료이며 실행 계획의 승인·완료 기록이 아니다. 기존 파일은 수정하지 않았다.

**핵심 판단:** 향후 실제 학습을 다시 한다면 먼저 현재 고정 full-FIT upstream을 A-only로 다시 적합하는 비교를 분리해야 한다. 다만 그것만으로 학습 자료 부족을 시험한 것은 아니다. 별도 기간 확장은 안전한 관측값·시간 경계가 실제로 확인될 때만 정의할 수 있으며, Beijing은 이미 넓은 FIT 시간대를 사용하므로 두 dataset을 모두 “짧고 중복된 FIT 때문에 실패했다”로 설명할 수 없다. 추가 데이터, 더 긴 최적화, 표현의 변경을 한 번에 섞으면 어떤 설명도 분리되지 않는다.

`[확인]` 최신 purged readout은 추가 STATIC slope만 A에서 적합했고 scaler/E/old D와 F cache는 full-FIT에서 고정했다. A117/B53/C64의 두 선형 선정 해를 독립 재풀이한 결과도, 비선형 E/F/D 학습의 전역 최적성이나 전체 upstream의 시간 이전을 검증한 결과는 아니다. 반대로 Oct11에는 fold별 fit-only normalizer·graph·표현학습 이력이 있으므로 역사 전체에 A-only upstream 검증이 전혀 없었다고 말할 수도 없다. 당시 목적·K·분할과 최신 actual-F gradient 학습이 달랐다는 사실을 구분해야 한다.

`[판단]` 남은 실질적인 질문은 **이미 시험한 학습 구조를 정확한 시간 경계와 유효 관측 범위 아래 다시 학습하면 결과가 달라지는가**다. “예측 목적을 이제 처음 넣자” 또는 “optimizer를 더 돌리면 해결된다”는 명분으로 같은 비교를 재명명하면 안 된다.

## 2. 실제 자료량에서 dataset마다 다른 점

다음은 [cross-moment 결과 메타데이터](runs/predictive_cross_moment_v1/RESULT.json)의 값이다. timestamp는 정수 위치이며 독립 표본 수가 아니다.

FIT history 범위         528–2072              0–20989

`[확인]` Robin의 기존 safe TRAIN 경계는 `[528,2520)`, 실제 FIT는 `[528,2121)`다. 기존 256창의 과거·미래가 짧은 시간대에 많이 겹친다. 창 수나 update를 늘려도 같은 시간대의 반복일 수 있다. FIT512가 독립적인 관측 기간을 두 배 늘렸다는 설명은 성립하지 않는다.

`[확인]` Beijing FIT 경계는 `[0,21038)`이고 현재 256개 창의 미래 slot은 12,288개 모두 서로 다른 시점이다. Robin과 같은 심한 미래 중복이 없다. 다만 **시간 범위가 넓다는 사실과 모든 가능한 supervision을 썼다는 사실도 다르다.** 현재 미래 고유 시점 12,288개가 `[512,21038)` 전체를 채우는 것은 아니므로, 같은 기간의 더 촘촘한 창은 아직 안 쓴 target timestamp를 추가할 수 있다. 이것은 기존 시간대의 supervision 밀도를 늘리는 것이며 새로운 장기간·새 regime을 추가하는 실험과는 다르다.

따라서 이후에는 window 수 외에 적어도 다음을 구분해야 한다.

- 입력 과거의 고유 timestamp 범위·개수·반복도.
- 실제 관측된 target timestamp의 고유 개수·범위·채널별 관측수.
- 시간대 자체의 폭과 그 안에서 supervision을 추출한 밀도.
- optimizer update 수·실제로 뽑은 window 수·동일 window의 재사용량.

`[판단]` Beijing은 “실패는 모두 좁은 시계열 구간의 중복 때문”이라는 설명에 대한 중요한 반례 자료다. 유지해야 하며 Robin 결과가 좋아지는 조건만 골라 다음 결론을 만들면 안 된다.

## 3. 비교 (a): A-only 전체 upstream 재적합이 답하는 질문

### 필요한 개입

각 dataset에서 기존에 허용된 origin을 시간순으로 정하고 A/B/C 역할과 response purge를 실행 전에 고정한다. 현재 실험의 Robin 117/53/64를 Beijing에도 그대로 복사하지 않는다. 시간 간격과 관측 mask가 다르기 때문이다. C를 보고 경계나 K를 바꾸지 않는다.

origin o는 첫 미래 시점이다. L512/H48에서 한 origin의 history는 `[o−512,o)`, target은 `[o,o+48)`다. A의 모든 학습 응답 마지막 시점이 첫 B origin보다 앞서고, B 선정 응답 마지막 시점이 첫 C origin보다 앞서도록 purge해야 한다.

```text
A 학습: max_A(origin+47) < first_B_origin
B 선정: max_B(origin+47) < first_C_origin
```

이 조건은 response가 다음 예측 origin에서 이미 관측 가능하도록 만드는 경계다. B/C의 과거창이 앞 A/B 기간을 포함하는 것은 배포에서 허용되는 known past이며, 이를 금지하는 L+H 완전 분리와 혼동하지 않는다.

**전체 upstream의 A-only를 주장하려면 다음을 모두 새 상태로 만들어야 한다.**

1. A의 허용 관측값만으로 scaler 평균·표준편차와 결측 처리의 초기값을 정한다. origin마다 초기화하는 causal forward fill 계약을 그대로 유지한다. B/C 과거를 실제 예측 입력으로 읽는 것과 그 값으로 통계를 다시 적합하는 것은 다르다.
2. E의 PCA/whitening·center, D의 초기 reconstruction/forecast 적합, 학습 특징 RMS와 supervised E/D 갱신까지 모두 A에서만 계산한다. D의 과거 reconstruction label은 true-observed A 과거, 예측 목적의 label은 true-observed A 미래다. 결측을 채운 값은 label로 세지 않는다.
3. 기존 full-FIT E/D·scaler·teacher·F cache를 이름만 같다는 이유로 재사용하지 않는다. 새 전처리·E로 만들어진 입력은 기존 latent 입력과 다르므로 frozen F를 실제 다시 실행해야 한다. 가중치 동결은 새 입력에 대한 F 실행을 생략한다는 뜻이 아니다.
4. Raw C도 같은 새 전처리와 관측 cohort에서 실제 실행한다. 작은 K에만 A-only 통계를 적용하고 Raw는 예전 full-FIT cache로 두면 전처리 효과와 압축 효과가 섞인다.
5. B는 사전에 정한 checkpoint·규제 메뉴의 선택만, C는 모든 선택 잠금 뒤 진단만 담당한다. `E(Y)`나 C 최저 후보를 선택에 사용하지 않는다.

PCA+RECON의 결정적 적합만 다시 한다면 **A-only 통계로 만든 단순 구조의 성능**을 시험한 것이다. actual-Y 학습 표현의 가능성을 다시 시험하려는 목적이라면 이미 존재하는 E/D actual-F-gradient 학습 class를 A-only 초기값·A label로 적합하는 경로와 그 동일 초기값의 고정 E/D 대조를 함께 정의해야 한다. 새로운 decoder 함수나 ridge 메뉴 확장을 붙일 필요는 없다.

### 무엇을 말할 수 있는가

- fixed full-FIT upstream의 조건부 진단과 달리, 새 pipeline에서 학습·선정·평가의 시간 의존성을 명시할 수 있다.
- 같은 A/B/C에서 A-only 고정 표현과 학습 표현을 비교하면, 이 유한한 학습 절차가 같은 초기 표현보다 개선되는지 답할 수 있다.
- 같은 새 상태의 Raw와 비교하면 해당 pipeline의 압축 정확도 손실을 계산할 수 있다.

### 무엇을 말할 수 없는가

full-FIT 고정 결과와 A-only 결과의 차이를 곧바로 “누수가 원인이었다” 또는 “자료 부족이 원인이었다”로 부를 수 없다. 학습에 쓰는 값·표본량·시간 분포·scaler·E/D 초기값이 함께 달라진다. 이 비교는 시간 경계의 정합성을 회복한 새 pipeline 비교이며 한 원인의 순수 개입은 아니다.

A-only에서 더 나빠져도 표현 class가 불가능하다는 증거가 아니다. 앞 구간의 표본량 감소와 시간 차이가 남는다. 더 좋아져도 연구자가 이미 본 FIT를 새로 분할한 것이므로 독립 holdout으로 바뀌지 않는다. Robin safe archive의 FP32 복원 계보까지 고려하면 무손실 원시 관측에서 완전히 새로 시작한 검증이라고 부를 수도 없다.

## 4. 비교 (b): DISTINCT TRAIN 확대는 무엇이 실제로 추가되는지부터 정의해야 한다

**조건:** 안전한 기존 파일 안에 추가 관측값이 있고, 그 값이 고정 B/C보다 앞에 있으며, 기존 TEST·평가 정답·선정 역할을 침범하지 않을 때만 정의 가능하다. 현재 문서에서는 그런 새 실험을 시작하거나 실행 가능 범위가 모두 확정됐다고 선언하지 않는다.

자료량 효과를 보려면 작은 학습 집합 S와 큰 학습 집합 L을 `S ⊂ L`로 만들고 **같은 B/C origin·관측 mask**에서 비교해야 한다. 새로 추가하는 부분 `L\S`의 모든 origin history/target이 허용 TRAIN 경계 안에 있어야 하며, supervised target은 첫 B origin 이전에 끝나야 한다. 같은 K·모델 class·초기화 규칙·손실·선정 메뉴를 유지한다. 확대 arm에서 K·정규화 강도·최적화 recipe까지 더 유리하게 바꾸면 자료량 효과를 분리하지 못한다.

확대는 세 경우로 나눠 기록해야 한다.

```text
같은 고유 관측을 반복          재사용량/최적화량 변경
같은 시간 범위의 새 target     supervision 밀도 변경
범위 밖의 추가 과거 관측       학습 시간대 폭/분포 변경
```

첫째를 둘째·셋째로 세지 않는다. 셋째도 자료 수와 시간 분포·recency가 함께 바뀌므로 “독립 표본 수만 늘린 인과 효과”라고 부르지 않는다. 필요하면 같은 폭의 고정 subsample과 전체 pool을 비교해 밀도 효과를 따로 읽되, 이것은 별도 사전 정의가 필요한 비교다.

`[확인]` Robin의 safe TRAIN 자체는 1,992시간이고 기존 FIT 1,593시간 뒤의 나머지는 이미 TUNE 역할이다. TUNE를 TRAIN에 합친 뒤 같은 TUNE로 고르거나, 미래 TUNE를 학습하고 그보다 앞의 C를 평가하면 안 된다. 새 역할 분할 없이 “더 긴 TRAIN이 있으므로 확대 가능”이라고 결론 내릴 수 없다. 원본 CSV의 존재도 별도 안전 추출 계약 없이 기존 허용 관측의 확보를 뜻하지 않는다.

`[확인]` Beijing은 원 FIT만 21,038시간으로 이미 넓다. 기존 FIT+TUNE payload가 28,051행이라고 해서 뒤 7,013행을 학습에 자동 포함할 수 없다. 그 부분은 기존 TUNE이며 역할·시간 경계를 유지해야 한다. 반면 FIT 내부에서 아직 쓰지 않은 target을 추가하는 밀도 비교는 새로운 장기간 확장과 구별되는 조건부 후보가 될 수 있다.

`[판단]` (b)의 이득이 나면 해당 학습 pool·동일 평가 cohort에서 자료 범위/밀도를 바꾼 recipe가 도움이 됐다고 말할 수 있다. 실패하면 등록된 확대 방식으로는 개선을 얻지 못한 것이다. 어느 쪽도 정보의 존재·부재, 비선형 최적화의 충분성, 모든 압축의 한계를 단독으로 증명하지 않는다.

## 5. 자료 부족·optimizer·표현 한계의 분리 기준

**학습 자료의 유효 범위:** (b)의 S/L을 고정 평가 cohort에서 비교해야 한다. window 수뿐 아니라 새 고유 입력/target 시점이 무엇인지 기록한다. 특히 Robin과 Beijing의 결과 방향을 따로 제시한다. Robin만 개선됐다고 두 자료에 같은 병목을 부여하지 않는다.

**optimizer의 문제:** 같은 자료·초기값·model class·목적에서 optimizer schedule만 바꿔야 한다. 자료를 늘리고 update도 동시에 늘리면 어느 쪽의 이득인지 모른다. 고정 update는 일정 계산량에서의 성능을, 고정 표본 재사용량은 다른 계산량에서의 성능을 묻는다. 둘을 같은 “공정 학습”이라고 부를 수 없다. 향후 한 학습 길이 대조를 한다면 checkpoint/선정 규칙과 초기화·minibatch seed의 역할을 미리 정하고 FIT 손실·gradient·clipping 이력도 함께 봐야 한다. 유한 길이의 두 학습이 나빴다는 사실로 전역 최적성은 증명되지 않는다.

선형 ridge의 독립 재풀이가 확인하는 것은 고정 design·등록된 규제 아래의 수치 해다. 비선형 E/F 입력 학습의 초기화와 비볼록성을 해결한 증거로 옮기지 않는다. 반대로 실제 gradient가 흐르고 유한 학습을 수행한 사실도 지워서는 안 된다.

**표현/복원 공간의 한계:** 같은 K에서 고정/학습 E와 지정 D의 공간·예측 오차를 구분해야 한다. retained output-space minimum이 조건부로 Raw보다 높다면 그 등록된 공간의 반대 근거가 되지만, 새로 적합한 E/D에 예전 minimum을 대입할 수 없다. E(Y)는 미래를 아는 진단이며 과거로부터 예측 가능성의 보장이 아니다. 학습이 실패하고 oracle 여지가 남아 있다는 조합도 optimizer 부족과 representation/F 비호환 중 하나를 고유하게 고르지 못한다.

`[판단]` (a)와 (b)는 각각 시간 경계와 학습 pool을 바꾸는 실질적인 비교이지만, **두 결과만으로 이 세 설명을 완전히 식별한다는 주장은 불가능하다.** 이것이 단순 D 확장보다 나은 이유는 새로운 함수를 추가하기 전에 현재 학습 절차의 자료·시간 조건을 명확하게 만들기 때문이다. 성공 가능성이 보장돼서가 아니다.

## 6. 평가를 공정하게 유지할 최소 조건

1. **두 dataset과 K를 유지한다.** Robin/Beijing의 등록된 K를 arm 사이에서 고정한다. 기존 K4/K8·K2/K4 중 일부만 택하더라도 이전 결과를 본 적응적 선택 이력을 밝힌다. 결과를 본 뒤 유리한 dataset·K·horizon만 최종 성공으로 고르지 않는다.
2. **모델 입력 정규화와 보고 지표를 분리한다.** S/L에서 각각 scaler를 refit하면 own-train-std로 계산한 MSE는 채널 가중치 자체가 달라진다. raw 물리 오차를 공통 보고 scale `s_ref,c`로 나눈 `mean_c mean_observed((ŷ−Y)²/s_ref,c²)`를 주지표로 고정하고 B 선정에도 같은 지표를 쓴다. `s_ref`는 두 arm이 공통으로 허용하는 앞 학습 구간에서만 정하고 B/C로 적합하지 않는다. 각 arm의 입력 scaler는 별도로 기록한다. 자료량 효과만을 묻는 supervised 학습도 공통 채널 가중치를 유지해야 한다. own-normalized 오차를 쓴다면 `train_std,c²/s_ref,c²`를 곱해 같은 물리 오차 목적에 맞추거나, 그렇지 않을 때는 자료와 학습 가중치를 함께 바꾼 recipe 비교라고 명시한다. 예전 지표와 새 공통 지표의 값을 설명 없이 직접 우열 비교하지 않는다.
3. **Raw도 동일 조건에서 다시 계산한다.** 새 scaler·창 처리로 입력이 달라지면 actual Raw F도 새로 실행한다. 같은 origin/mask에서 작은 K의 자기 baseline 대비 이득과 Raw 대비 gap을 모두 제시한다. F 내부 정규화 때문에 입력 변경이 무해하리라고 가정하지 않는다.
4. **선정과 성공을 구분한다.** ZERO가 포함된 메뉴의 B 비악화는 메뉴 구성의 성질일 수 있다. 주평가는 잠금 뒤 같은 C의 Raw 대비 signed MSE 차이와 자기 고정 표현 대비 차이다. 모든 arm·실패·음성 결과를 보존한다. 둘 중 하나만 좋아진 결과를 정확도·비용 동시 성공으로 바꾸지 않는다.
5. **비용은 새 상태에 결속한다.** 실제 전처리→E→actual F→D→물리 CPU 반환 전체 경로를 해당 새 상태로 측정하기 전에는 비용 미측정이다. 이전 계수·다른 cohort의 B8 시간이나 K/C 비를 새 모델의 시간으로 대입하지 않는다. 새 학습 비용과 배포 latency도 구분한다.

강한 일반화 주장에는 별도의 적절한 평가 근거가 여전히 필요하다. 이미 노출된 FIT/TUNE/DEV를 재배치하거나 두 seed·다수 horizon을 늘려 독립 dataset/holdout 수로 세지 않는다. 이 문서는 새 TEST 사용을 제안하지 않는다.

## 7. 자산·권한 경계의 현재 판단

`[확인]` 현재 [addendum](EXECUTION_SCOPE_ADDENDUM_KO_v2.md)은 자료·K·L/H·split을 유지한다고 적는다. 이후 사용자의 같은 목적 지속 지시가 있었지만, 최신 직접 지시는 현재 작업을 마무리하고 게시하는 것이다. **이 문서를 쓰면서 새로운 데이터 범위나 학습 실행을 시작할 근거로 삼지 않는다.** 향후 계약의 변경이 필요하다면 현재 split 불변 기록과 구분한 명시적 새 범위 기록이 있어야 한다. 과거 기록을 고쳐 확대가 원래 조건이었던 것처럼 만들면 안 된다.

[TRAIN 자산 조사](TRAIN_ASSET_REVIEW_KO_v1.md)가 확인한 중요한 제약은 다음과 같다.

- Robin safe trainval에는 전체 TRAIN 통계로 표준화된 FP32 x와 mask/statistics가 있다. 원 physical은 별도 보관되지 않아 역변환 시 FP32 rounding 계보가 남는다. A에서 다시 scaling해도 무손실 원시 A 값만 쓴 완전한 전처리 독립성이라고 주장하지 않는다.
- Beijing에는 physical/mask가 있으나 FIT+TUNE 결합 archive다. 필요한 키·시간 경계만 사용해야 하며 full-FIT의 x/filled/mean/std를 새 A-only 통계로 착각하지 않는다.
- 기존 TEST 파일명 가드는 Beijing EVAL target이나 전체 CSV/ZIP까지 자동 차단하지 않는다. TRAIN-only loader의 경로 allowlist·부작용·자동 복구/재파싱·다운로드 가능성을 SOURCE에서 먼저 고정해야 한다.
- 결합 NPZ를 읽어 즉시 행을 자르는 것과, 나중 기간의 값이 물리적으로 전혀 역직렬화되지 않는 것은 다르다. C label 비사용·선정 전 C 점수 0·C data 접근 0은 서로 다른 계약이다. 사실에 맞는 수준만 기록한다.

원시값의 완전한 A-only lineage가 확보되지 않으면 안전한 artifact를 조건으로 한 재적합이라고 범위를 낮춰 말할 수는 있다. 그 제한을 숨긴 채 더 강한 검증으로 부르면 안 된다. 이번에는 어느 경로도 실행하지 않았다.

## 8. 향후 판단 순서와 이번 종료 상태

미래에 같은 목적의 학습 비교를 다시 진행한다는 조건 아래, 우선순위는 **안전 자산·통계 lineage와 시간 경계 확정 → (a) 전체 upstream의 A-only 재적합 및 같은 Raw 대조 → 실제 가능한 (b)의 supervision 밀도/시간대 확장 분리**다. 전체를 하나의 “데이터 늘린 새 방법”으로 합치지 않는다. 이미 시험한 actual-F-gradient 학습을 사용한다면 고정 E/D 초기 대조와 학습 budget의 의미를 함께 명시한다.

(a)가 실패하면 시간순으로 더 정합적인 새 recipe에서 이득이 없다는 결과다. (b)가 실패하면 등록한 pool 변경이 해결하지 못했다는 결과다. 둘 중 하나가 좋아져도 이미 본 평가 자료의 적응적 결과라는 한계와 Raw 대비 정확도·새 상태 비용을 따로 확인해야 한다. 성공을 보장하지 않으며 현재 음성 결론을 없애기 위해 설계를 바꾸지 않는다.

**이번 산출물은 이 미실행 검토 문서뿐이다.** 추가 loader·scaler·E/D·학습·실제 F·예측·비용 결과를 만들지 않았다. 현재 실제 압축 정확도 목표는 미해결이며, 과거 첨부 비판과 최신 실행 결과·미래 조건부 제안을 서로 다른 근거 수준으로 유지한다.
