# main 게시 후 검토할 때 사용할 체크리스트

이 문서는 새 결과를 검토하는 사람/LLM용이다. 실행 계획 전체를 다시 읽기 전에 **공개 증거와 실제 비교 계약**을 확인한다.

## 1. 먼저 원격을 확인한다

현재 `main`의 SHA를 읽고, 새 캠페인 README와 `EXPERIMENT_REGISTRY.csv`, `RUN_INDEX.csv`, `SCORES.csv`, `AUDIT_REPORT.json`을 그 SHA로 고정해서 읽는다. 파일 이름만 새것이라고 새 학습으로 간주하지 않는다.

다음 항목은 각각 독립된 상태로 답한다.

| 질문 | 필요한 증거 |
|---|---|
| 실제로 실행했나? | 로그 시각, 실행 명령, checkpoint/optimizer hash, 학습곡선, 예측 파일 hash |
| 동일 조건으로 비교했나? | 자료·시점·마스크·정규화·L/H·point type·학습 정보·선택 예산 |
| 숫자는 맞나? | 공개 SSE/SAE/count의 별도 집계와 저장 예측 재채점 |
| 모델은 정상 동작하나? | checkpoint 재추론·합성 불변성·실패 주입 검사 |
| 충분히 학습했나? | epoch, 마지막 개선 여부, 조기 종료, 비교군의 같은 기회 |
| 도움이 되나? | Raw/B0/G-only/같은 정보 대조/병합 LoRA/표준 포트 비교 |
| 게시까지 됐나? | remote main의 commit ancestry와 공개 파일 hash |

## 2. 필수 커버리지 확인

- **E0:** 기존 12개 학습 미해결 ID가 전부 장부에 있고, 실제 이어 학습/자료 차단/미실행을 구분하는가?
- **E1:** Electricity 전체 채널, PeMS08 전체 센서, 등록한 M5 패널의 실제 점수가 있는가? 기존 Beijing/Jena를 반복한 것을 새 도메인 확대라고 하지 않는가? K1/4·K1/2·C와 전체 등록 grid가 구분되는가?
- **E2:** alpha0/0.5/1/학습 alpha, 조건부 H, G_past_control, G_refit, Raw-conditioned, B0-conditioned의 비교가 있는가?
- **E3:** 지연 압축을 실제 학습했고 같은 K·D의 B0/B2 및 시간 경계 대조가 있는가?
- **E4:** 하나의 checkpoint로 여러 K를 실제 실행했는가? D의 lag×K slicing과 F 실제 stream 수를 검사했는가?
- **최종:** 선택에 사용하지 않은 마지막 구간과 실제 전체 비용을 확인했는가?

누락이 있으면 `PARTIAL`이다. 방법이 무효여서 못 한 것인지, 데이터/인증/예산 때문에 못 한 것인지 구분한다.

## 3. 가장 먼저 볼 성능표

같은 자료·같은 평가 origin에서 다음 행을 나란히 읽는다.

1. Raw Bolt-small, 가능한 Raw mini/tiny, 병합 LoRA.
2. G-only, G가 추가 학습 정보를 받은 강한 비교, 과거 전용 동용량 보완.
3. 고정 PCA, B0, B2/B4, 새로운 지연 압축.
4. 단순 예측 결합, 예측값 조건부 보완.
5. 각 K 별도 모델, prefix 절단, 다중 K 공동학습.

Raw 대비 좋아졌다는 이유만으로 시간 앞단의 효과라고 하지 않는다. **B2−B0**, **조건부 H−과거 전용 H**, **압축-conditioned−Raw-conditioned**, **multiK−독립K**가 별도의 주장이다.

## 4. 특히 놓치면 안 되는 오류

- M_cal까지 학습한 부모의 in-sample 예측으로 결합기를 평가하는 문제.
- V에서 정한 K/seed라고 하면서 실제로 T 최선값을 고른 문제.
- 여러 K의 전체 F를 계산하고 작은 K의 비용이라고 표시하는 문제.
- G-only 비용 측정 프로세스에 필요 없는 Bolt를 로드한 문제.
- LoRA를 병합할 수 있는데 미병합 비용만 일반적인 비용으로 주장하는 문제.
- M5의 판매 0을 전부 결측으로 처리하거나, 제한 패널 점수를 전체 WRMSSE라고 표시하는 문제.
- UCI 원본 370고객/15분과 표준 321 hourly 자료를 같은 것으로 표시하는 문제.
- H가12/28인데 H48의 decoder/loss/분석 구간을 그대로 사용하는 문제.
- 지나치게 작은 분모·상수 채널 때문에 큰 상대 변화가 생겼는데 원수치를 숨기는 문제.
- metadata/hash 검사 PASS를 독립 재학습/충분 수렴/과학적 성공으로 부르는 문제.

## 5. 동봉한 산술 검사 도구

`audit_public_bundle.py`는 새로 제안한 공개 스키마의 `SCORES.csv`와 `PUBLIC_ERROR_STATS/*.csv(.gz)`를 별도 표준 라이브러리 코드로 집계한다. **SSE/SAE/count가 실제 예측에서 올바르게 생성됐는지까지 증명하지는 않는다.** 실제 예측 재채점과 checkpoint replay는 캠페인에서 별도로 수행해야 한다.

```text
python audit_public_bundle.py --self-test
python audit_public_bundle.py --root <공개_캠페인_폴더>
```

실제 스키마가 아직 구현되지 않은 상태에서 이 명령의 실패를 연구 방법의 실패로 해석하지 않는다. 스키마가 다르면 매핑을 명시하고 변환된 검산용 자료를 생성한다. 기존 원자료를 덮지 않는다.

검토의 최종 답은 “다시 다 하자”가 아니라 **유지할 유효 결과, 수정해야 하는 특정 비교, 아직 말할 수 없는 주장, 필요한 최소 추가 확인**으로 정리한다.
