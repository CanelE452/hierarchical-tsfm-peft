## 읽기 범위와 ROOT의 조건 구체화

소스를 먼저 확인했을 때 `_base`는 `COMPLETE_VALID` 자체 생성 receipt를 확인하고 `_bound`로 로컬 artifact의 실제 SHA를 검증한 뒤 `torch.load(..., weights_only=False, map_location="cpu")`를 호출했다. RAW mini/tiny는 기존 로컬 foundation 파일들을 SHA 해시한다. 처음에는 이 두 경로를 미실행 대상으로 분류해 ROOT에 보고했다.

ROOT가 이 검증된 현재 campaign 소유 checkpoint에 한한 기존 loader 실행과 기존 mini/tiny 로컬 byte SHA 읽기를 명시적으로 허용한 뒤, 기존 코드를 그대로 전체134에 실행했다. 초기 분류103개 checkpoint 의존·7개 foundation SHA 의존·24개 나머지는 해당 허용으로 진행했으며 실패나 방법 성능 문제를 뜻하지 않는다. 외부·출처 미상 pickle, 새 다운로드·설치, 모델 생성·forward는 허용하지 않았다. in-memory monkeypatch나 source 수정은 없다.

[확인] 실제 checkpoint load는 **103회 모두 `weights_only=False`, `map_location="cpu"`**였다. `weights_only=True` 검증이라고 표현하지 않는다. 각 call 전에 실제 `_bound`가 반환한 같은 파일의 SHA를 관찰했고, `runs/.../selected_bundle.pt` 경로·캠페인 소유·크기 제한을 다시 검사했다. 가장 큰 실제 load bundle은 4,434,618 bytes였다. 로컬 mini/tiny foundation의 파일은 해시만 읽었고 모델 객체로 만들지 않았다.

## 실제 검산과 자원

원 API의 `_bound` actual-return을 관찰한 file SHA 검증은 285회, 중복 제거 파일/SHA 조합은 233개다. 이는 원 `_bound` 호출·반환을 profile로 관찰한 수이며 SHA 함수를 대체한 결과가 아니다. checkpoint loader의 실제 인자도 profile로 관찰했고 함수 구현을 교체하지 않았다.

네 자료는 기존 `data_contract.load_task`의 합법 safe-prefix를 실제 로드했다. legacy Beijing/Jena의 필요한 압축 NPZ member는 전체 해제 후 허용 FIT prefix로 잘리므로 물리적 파일 읽기까지 행 격리되었다고 주장하지 않는다. 반환된 데이터·mask·시간·채널 SHA는 각 고정 V manifest의 data SHA와 일치했다. RAW-small route의 A-only normalization 계산은 수행했지만 history/target window 추출·새 예측·T target 평가는 없었다. raw observation이나 target 값은 공개하지 않았다.

실제 실행 시작/종료 UTC는 `2026-10-15T16:37:42.736295+00:00` / `2026-10-15T16:37:55.937872+00:00`다. 이 약13.2초는 해당 CPU 검증 process의 경과 범위이며 배포 latency 측정이나 GPU 비용 추정이 아니다. cost timing trial은 0이다.

최대 RSS 668,356,608 bytes(약637MiB), 제한2GiB, CPU thread2, `CUDA_VISIBLE_DEVICES=-1`, CUDA 초기화 전후 false였다. model construction/forward, foundation instance, GPU lease, 학습·추론, T window, 다운로드·설치·Git 호출은 0이었다. profile은 model construction/forward·CUDA 초기화·history/target 추출을 거부하도록 설정했으며 해당 시도는 없었다.

source18을 포함한 source30은 실행 전후 실제 SHA가 같았다. 고정 V 134개의 manifest SHA 및 registry 과학 identity도 같았다. 이 실제 실행 동안 main registry byte SHA 역시 같았으며, 이 worker는 registry를 수정하지 않았다. 기존 파일과 결과는 보존했다. 원 실행은 ID별 결과·최종 summary를 모두 저장했으나 최초 shell의 종료코드 필드는 별도 파일에 포획하지 못했으므로 그 값을 추정해 기록하지 않았다. 후속 독립 metadata 검산의 실제 exit0와 SHA는 `VERIFICATION.json`에 구분했다.

전체 route spec·artifact/부모 바인딩·실제 실행 log·입력 capture는 private campaign cache에 보존했다. 공개 JSON에는 상대경로와 SHA만 남겼다. 실패 route는 없지만, 이 검사를 통과했다는 이유로 비용 full protocol이나 최종 campaign을 완료로 표시하지 않는다.
