# 실제 데이터의 정보 사용 경로 개입 검사

[확인] 2026-10-15 CPU 실행에서 검사한 **A60 통계/PCA 적합, V 과거 창 추출, 선택 P/E 경로에서는 미래 의존성이 검출되지 않았다.** 이 결과를 모든 누출의 부재, 인코더의 예측 적합성, 성능 개선, 독립적인 일반화 검증으로 확대하지 않는다.

실행 결과는 [snapshot README](doc_0040.md), [입력 봉인](../../gzip_extra_aux_20261016_v1/files/item_0437.json.gz), [데이터별 집계](../../../diagnostics/information_1792059220909884100/INFORMATION_AUDIT.csv), [실행 영수증](../../gzip_extra_aux_20261016_v1/files/item_0436.json.gz)에 있다.

## 무엇을 실제로 바꾸었는가

`information_audit.py`는 새 CPU 프로세스에서 실행하며 CUDA를 숨기고 NumPy/BLAS/PyTorch thread를 2개로 제한한다. 기존 `load_task`가 반환하는 허용 prefix 네 개를 사용한다. 원본 `physical`·`observed` 배열은 읽기 전용으로 두고, 개입 때마다 이 두 배열만 복사한다. 미래 값은 기존 수치에 더하지 않고 큰 유한한 행/채널 패턴으로 **덮어쓴다**. 미래 mask는 복사본에서 반전한다. 원본 파일·배열은 수정하지 않는다.

실행 전 source, 데이터 배열, 데이터 SHA, A60 끝, 고정 V origin, 기존 encoder receipt·선택 checkpoint SHA를 `INPUT_SNAPSHOT.json`에 봉인했다. 어떤 오차나 미래 정답도 창 선택에 사용하지 않았다.

1. **A60 적합 독립성**: A60 끝 이후의 복사본 값과 mask를 전부 바꾼 뒤 실제 `fit_statistics`와 `initialize_pca`를 다시 실행했다. mean, std, 관측 개수, PCA center, basis, eigenvalue와 `E @ E.T` projector를 정확 비교했다. basis의 부호 모호성은 projector로 별도 확인하며, 동일한 결정론적 구현의 basis 자체도 exact equality를 요구했다. PCA는 전체 C에서 `ceil(C/4)`개의 축을 사용하여 전체 차원 projector의 자명한 항등 비교를 피했다.

2. **과거 창 경계**: 각 데이터 V의 stride-H origin 목록에서 첫 번째·중간·마지막을 메타데이터만으로 고정했다. 각 origin 이상을 바꾸고 실제 `history_window`를 재호출했다. `[origin-L, origin)` 창의 fill·표준화 결과와 원래 관측 mask가 정확히 같은지 확인했다. 창 안 결측은 그 창의 시작에서 A 평균으로 초기화하는 기존 규약을 그대로 사용했다.

3. **선택 P/E 경계**: 기존 [encoder 진단 입력 목록](../../gzip_extra_aux_20261016_v1/files/item_0321.json.gz)의 동일한 선택 checkpoint 24개를 CPU에 로드했다. Beijing·PeMS08 각각 B0, B2, LAG_CAUSAL, LAG_BIDIR 세 K이다. 각 checkpoint의 데이터·A60 scaler·원 training source SHA와 실제 artifact SHA를 확인하고, 저장 state를 정확히 복원했다. 동일한 세 origin에서 원본/개입 복사본의 실제 `model.front`와 `model.encode` 출력이 정확히 같았다. F를 전달하거나 호출하지 않았다. 입력 창이 동일할 때 고정 P/E도 동일하다는 경계 검사이며, 인코더의 예측 정보를 측정한 실험은 아니다.

4. **F 호출 경계 소스 검사**: [SOURCE_CALL_AUDIT.json](../../gzip_extra_aux_20261016_v1/files/item_0438.json.gz)은 `predict_model`, `ForecastAdapter.forward`, `RowForecaster.forward/_invoke`, `FrozenBolt` 내부 `predict`의 실제 AST를 확인한다. 모델에 들어가는 것은 과거 `x`, 과거 잠재열 `z`, 행으로 펼친 `rows`이며 실제 Bolt 호출은 `model(context=rows)`이다. 미래 target 인자가 없는지 확인했다. 이는 지정된 소스 경계의 검사이며 전체 프로그램의 형식 검증은 아니다. D의 `future`라는 이름은 F가 만든 예측을 뜻하므로 미래 정답 인자와 혼동하지 않는다.

## 원수치와 실행 범위

```text
데이터       허용 N    C     A60 끝   PCA K   V 과거 창
Beijing      21038    11      12622       3        3
Jena         20965    21      12579       6        3
Electricity  24240   321      14544      81        3
PeMS08       17856   170      10713      43        3
```

네 데이터 모두 통계/PCA exact 비교와 원본 배열 SHA 불변 검사를 통과했다. 실제 V 과거 창 12개, 선택 encoder checkpoint 24개, P/E 원본-개입 비교 72개를 통과했다. source SHA도 실행 중 바뀌지 않았다. CPU process 3.21875초, 측정 본체 wall 1.99324초였다. 다중 thread 때문에 CPU process 시간은 wall보다 클 수 있다. 두 시간은 데이터·checkpoint의 최초 봉인 준비와 Python 시작 시간을 포함하지 않는다.

`target_window`는 호출하면 즉시 실패하는 guard로 막았고 실제 호출은 0회였다. 실제 F 로드·추론, 학습 update, 새 T 평가, registry/SCORES 변경도 0이다. 실제 F/D의 전체 예측 재실행은 이 결과에 포함하지 않는다.

## 남는 불확실성과 다음 판단

이번 결과는 **현재 실패 원인을 미래값 입력 누출로 설명할 직접 근거를 제공하지 않는다.** 검사한 경로가 과거 입력만 사용한다는 증거를 강화한다. 반면 재구성 안정성, 잠재열의 미래 예측 가능성, F 호환성, D 복원 오차 중 무엇이 성능을 제한하는지는 별도의 단계별 오차·동일 조건 대조로 판단해야 한다.

B2와 LAG_BIDIR가 공급된 과거 창의 앞쪽 표현을 만들 때 그 창 뒤쪽의 과거를 이용하는 것은 별개의 성질이다. 이번 검사는 `origin` 이후 의존성을 검사하므로, 이 방법들이 **창 안에서도 prefix causal**하다고 주장하지 않는다.

archive를 읽는 방식과 모델에 전달하는 수치 범위는 구별해야 한다. legacy NPZ의 필요한 멤버는 전체 역직렬화한 뒤 허용 FIT로 자르므로 **물리적인 행 격리가 아니다.** 이 감사는 보호된 옛 TEST 파일을 새로 열지 않았으며 기존 허용 task prefix만 사용했다. campaign의 미래 행은 복사본 개입 대상으로 덮어쓸 뿐, 미래 정답 창으로 추출해 점수나 선택에 쓰지 않았다. Jena 등의 FP32 정규화·역변환 계보와 rounding은 남아 있다. Bolt 사전학습 데이터 중복 여부도 미확정이다. 유한 개입 검사와 지정된 소스 경계만으로 모든 입력·모든 코드 경로의 누출 부재를 보장하지 않는다.

## 재실행과 단위 테스트

API는 `run(public_root, cache_root, asset_root, encoder_snapshot=None)`이며 매번 새 `diagnostics/information_<ns>/`에만 기록한다. 기존 snapshot을 덮어쓰지 않는다. 실제 사용한 CLI 형태는 다음과 같고 경로는 환경변수로 지정할 수 있다.

```powershell
python -X utf8 information_audit.py --asset-root $env:INFORMS_ASSET_ROOT --cache-root $env:INFORMS_CACHE_ROOT --encoder-snapshot diagnostics/encoder_cpu_1792058187600403500/INPUT_SNAPSHOT.json
python -X utf8 -m unittest test_information_audit -v
```

CPU 단위 테스트 5개는 정상 경로 불변, **전체 미래로 평균을 적합하는 잘못된 callable의 실제 FAIL**, **origin 미래값을 과거 창에 더하는 잘못된 callable의 실제 FAIL**, mask와 경계 포함 여부, target 인자 식별을 확인한다. 잘못된 함수를 별도 helper가 아니라 실제 개입 검사 함수에 주입하여 오류를 검출하는지 검사했다. 첫 테스트 실행은 구현 부재로 RED였고 구현 후 다섯 개 모두 GREEN이다.
