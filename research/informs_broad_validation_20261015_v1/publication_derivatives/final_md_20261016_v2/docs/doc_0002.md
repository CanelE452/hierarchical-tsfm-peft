# 실제 예측과 영수증에 연결한 파생 시각화

[확인] `report_figures.py`는 matplotlib 스킬을 적용한 CPU 전용 시각화 도구다. 새 실험을 학습하거나 예측하지 않고, 허용된 private cache의 실제 저장 예측과 공개 영수증을 읽는다. `generate(public_root, private_root, split='V_select')`는 기존 파일을 수정하지 않는 새로운 `figures/snapshot_<UTC시각>_<ns>/`를 반환한다.

```text
python -X utf8 report_figures.py --public-root <campaign> --private-root <private-cache> --split V_select
```

기존 세 자료를 읽을 때는 자산 root 환경변수 `INFORMS_ASSET_ROOT`, 준비한 새 cache는 `INFORMS_CACHE_ROOT`로 지정한다. 원자료·체크포인트·registry·전체 SCORES·기존 그림에는 쓰지 않는다. 데이터 내려받기·패키지 설치·GPU·commit/push 기능은 없다.

## 사용 전 검산과 추적

표준 `PREDICTION_MANIFEST.json`을 실제로 검색한다. score가 없는 dense 학습 cache나 다른 split은 그림에 포함하지 않는다. 각 예측은 독립 `audit_predictions.py`로 archive SHA·5개 배열 shape/dtype/SHA·사전 reference의 target/mask/origins/channel·identity를 확인하고 FP64로 다시 점수를 계산한다. 공개 SSE/SAE/count도 재집계하고 실제 F stream ledger를 검사한다. 실패한 입력은 그림에서 제외하되 `excluded_prediction_inputs`에 파일과 이유를 남긴다. 이 검사는 **수치 bundle 검산**이며 전체 registry 감사·체크포인트 replay·학습 재현을 했다는 뜻이 아니다.

실험 이름·K·seed·fold는 registry를 사용하며, 학습 예산·선택 epoch·미수렴 상태는 실제 fit receipt에 결속한다. learning extension의 `__e1`/`__e3`도 원 ID와 다른 run으로 유지한다. `.25`, `1`, `3` 예산이나 다른 seed를 같은 K 선으로 이어 붙이지 않는다. 동일 K/예산의 중복 레시피가 있으면 점을 따로 찍고 최선만 고르지 않는다. source가 다른 실험의 조상 관계를 그림으로 지워 버리지 않는다.

`FIGURE_MANIFEST.json`에는 시각화 코드·검산/데이터/집계 의존 코드 SHA, 읽은 공개/비공개 입력의 상대 경로·SHA·크기, 파생 출력 SHA, 6개 그룹의 실제 상태, 제외 입력, trace의 제한된 private plot-data SHA를 남긴다. 갱신 중인 registry도 파싱한 정확한 바이트로 hash를 기록한다. 개인 절대 경로는 공개 manifest에 넣지 않는다.

## 여섯 그룹과 미실행 처리

1. `accuracy_by_k`: 자료·fold·동일 target/mask/origin/channel cohort별 정규화 macro MSE/MAE. K 비교가 없으면 존재하는 baseline 막대만 만들고 **K sweep pending**을 표시한다. Ridge는 A 적합, naive는 무학습, Raw F는 고정 사전학습 모델로 구분한다. 다른 자료의 점수를 평균하지 않는다.
2. `matched_controls`: B2−B0, H−동용량 과거 대조, Raw 보정−원 Raw, H−M_cal 적합 alpha. 동일 cohort·scaler·자료·seed·K 및 허용 학습 예산 조건을 확인한다. H 대조는 frozen parent 증빙도 같아야 한다. 대응 후보가 중복되거나 없으면 임의의 가장 좋은 결과를 선택하지 않는다. delta는 기술적 차이이며 유의성 검정이나 일반화 증거가 아니다.
3. `learning_diagnostics`: A50 search의 A_stop 곡선, 선택 epoch, search/refit 노출·update·clipping을 따로 표시한다. 같은 run 내부 경계만 연결한다. 실제 `.25` screen은 watermark로 보이며 마지막 checkpoint가 최선이라는 관찰을 수렴으로 바꾸어 말하지 않는다. Ridge는 optimizer 곡선을 만들지 않는다. 현 엔진의 deadline 중단 구간 clipping 누락은 원 영수증의 한계로 유지한다.
4. `cost_accuracy`: 실제 whole pipeline trial receipt가 있을 때만 점수와 연결한다. warm/timed 및 별도 stage probe, balanced/shared process와 fresh single route, dtype·배치·장치를 구분한다. data/scaler·가능한 exact artifact SHA를 대조한다. per-route artifact SHA가 없는 receipt는 연결 수준을 CSV에 명시한다. CPU RSS after close를 peak RSS라고 표시하지 않으며 GPU fresh peak reserved와 구분한다. 학습 peak나 저장 예측 읽기 시간을 배포 비용으로 쓰지 않는다. 원 costs가 없으면 PENDING이다.
5. `lag_prefix_multik`: causal/bidirectional lag, posthoc/nested prefix, ordered multi-K의 실제 점수와 F rows, 단계별 origin exposure·K ledger를 구분한다. 학습 기록만 있으면 해당 노출 그림만 생성하고 미래 예측 대조의 공백을 밝힌다. exposure를 unique/independent sample이라고 세지 않는다.
6. `representative_traces`: 모델 우선순위·channel 0·first/middle/last와 RNG seed 92601의 원점 규칙을 고정한다. V에 한해 같은 사전 지정 anchor의 사후 최선/최악 원점을 별도 **POST-HOC** 표기로 덧붙인다. 모든 사례의 관측 mask와 정답 누락을 보이고, 누락을 0 정답으로 바꾸지 않는다. 가능한 메서드가 없으면 상상한 Raw/G/LoRA 선을 만들지 않는다. 한 cohort에서 최대 6개 메서드, 최대 6개 원점, 원점당 과거 최대 48행+해당 H의 제한된 trace만 그린다.

자료가 없는 그룹은 `PENDING`이며 빈 placeholder 이미지를 만들어 완료 수에 넣지 않는다. 자료가 있는 그룹도 `AVAILABLE_PARTIAL_EVIDENCE`이고 `complete_campaign_claimed=false`다. 일부 PNG의 존재를 필수 실험 커버리지나 연구 성공으로 세지 않는다.

## 물리 단위·공개 경계·T 제한

대표 trace는 canonical A60 mean/std로 native 단위로 역변환한다. Jena/Robin은 기존 전체-TRAIN 정규화의 FP32 역변환 계보가 남으므로 `legacy FP32 inverse-normalized native units`라고 표시한다. 자료마다 시간 간격이 다르다. Jena 600초, Beijing/Electricity 3600초, PeMS08 300초이며 PeMS의 H는 12, 나머지는 48이다. 같은 512행을 같은 물리 시간이라고 비교하지 않는다.

공식 PeMS NPZ에는 진짜 달력 timestamp가 없으므로 origin index와 상대 sample step을 사용하며 합성 1970 시각을 실제 날짜로 그리지 않는다. 원본 전체 시계열과 전체 trace array CSV는 공개하지 않는다. bounded trace는 파생 PNG/SVG로만 공개하며 정확한 plot-data CSV.gz는 private cache의 해당 snapshot에 저장한다. 공개 CSV는 점수·차이·학습량·노출·비용 집계다. 공개된 연구 자료의 파생 시각화는 raw 재배포 허가를 뜻하지 않는다.

T 그림은 `SELECTION_LOCK.json`이 실제 locked이고 해당 run의 artifact 또는 portable route SHA가 허가되어 있으며, 이미 존재하는 T manifest가 검산될 때만 생성한다. T 예측이 없으면 실패하며 새 추론으로 T를 열지 않는다. **T에서는 사후 최선/최악 사례를 고르지 않는다.** 고정 first/middle/last/seeded 규칙만 사용하며 모델·K·epoch·fit·사례 선택에 T 오차를 사용하지 않는다. 합성 unittest의 T 데이터는 이 운영 제한을 검증하기 위한 toy다.

## 검증 수준과 현재 결과

[확인] 구현 전 모듈 부재의 RED를 확인했고 CPU unittest 8개가 통과했다. 실제 저장 bundle의 비어 있지 않은 PNG/SVG와 정확한 SHA 연결, private trace CSV 경계, 기존 snapshot 불변, 예산 분리, matched-parent 분리, cost trial SHA·timer scope, 잘못된 T artifact를 cache 읽기 전에 거부하는 동작, 허용된 toy T의 고정 사례 4개를 검사했다.

[확인] 최초 실제 CPU snapshot `snapshot_20261015T091654Z_1792055814416198700`은 4개 자료의 V baseline manifest 12개를 재채점했고 제외 입력이 0개였으며, 당시 완료 fit receipt 47개로 PNG/SVG 각 12개를 만들었다. 이 최초 버전은 baseline 축 라벨과 footer가 겹쳐 다음 snapshot에서 수정한다. 원 snapshot은 덮어쓰지 않는다. 최종 사용할 snapshot은 해당 `FIGURE_MANIFEST.json`과 최신 생성 로그로 확인해야 한다. 학습이 계속되는 캠페인에서는 나중에 다시 호출하여 새로운 immutable snapshot을 만든다.

[확인] 라벨 겹침과 baseline 설명을 수정한 실제 snapshot은 [snapshot_20261015T092412Z_1792056252745543800](doc_0089.md)이다. 저장 V 예측 12개·제외 0개, 당시 완료 fit receipt 49개, PNG/SVG 각 12개를 포함한다. accuracy와 PeMS trace·Beijing learning PNG를 직접 열어 렌더링을 확인했다. matched/cost 두 그룹은 실제 결과가 없어 PENDING이다. 공개 파생 파일은 manifest 포함 약 3.95MB이며 정확한 bounded trace CSV는 private cache에만 있다.

초기 12개 baseline의 존재와 학습 영수증이 모든 neural V 추론·결합 대조·비용 측정의 완료를 뜻하지 않는다. 이후 그림도 독립적인 일반화나 논문의 최종 기여를 자동으로 성립시키지 않는다.
