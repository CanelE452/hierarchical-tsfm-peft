# RawSmall + 동일 deep G: 마지막 E2 강한 대조 4조건

상태는 준비 완료이며 실제 학습·추론은 아직 실행하지 않았다. 원 E2 실행의 봉인 계획 `5fb3f378af2d3d2090b71d9aa34751189a14fb575af8a95c165819490093706b`에 있는 G를 그대로 쓴다. 각 자료의 기존 Raw H private spec에서 `run_id`, `g_run_id`만 달라진다. 신규 방식이나 새 데이터 조건이 아니다.

- Beijing: `primary_beijing_E1_DIRECT_G_k0_s92601__e1__e3`
- Jena: `primary_jena_E1_DIRECT_G_k0_s92601__e1`
- Electricity: `primary_electricity_E1_DIRECT_G_k0_s92601__e1`
- PeMS08: `primary_pems08_E1_DIRECT_G_k0_s92601__e1`

네 G는 A50 탐색/A_stop 선택/A60 refit과 NO_FOUNDATION을 갖는다. M에서 G를 다시 학습하지 않는다. 기존 RawSmall의 M_dense/V 캐시 8개와 위 G의 M_dense/V 캐시 8개에 대해 실제 manifest·reference bytes SHA, archive의 선언 SHA·파일 존재, source·data·scaler·model·role·cohort·A60 계약을 봉인했다. PeMS G의 M_dense도 실제 존재한다. 준비 과정에서 NPZ/weights/원자료를 열지는 않았다. 실제 실행 직전에는 모든 archive와 G artifact bytes의 SHA도 대조한다.

RAW는 BASE 영수증이 없는 고정 baseline이다. `family=RAW`, `training_source_sha=NO_TRAINING_FIXED_BASELINE` 및 source7 계약으로 검사한다. G에만 기존 extended E2의 BASE/source6/A60 검사를 적용한다. RAW 모델 식별자는 고정 baseline/scaler/data/frozen-model을 결합한 실제 cache 계약이며, raw model 객체는 실행 때 기존 ParentPool이 로컬 pinned Small로 생성한다. 설치·다운로드·새 foundation 학습은 없다.

`PROPOSED_REGISTRY_ROWS.csv`의 새 4개는 ROOT 단일 writer가 먼저 등록해야 한다. worker는 등록하지 않으며 실제 실행 전 전체 과학 컬럼을 대조한다. 현재 E2가 terminal임을 ROOT가 직접 확인하고, 동일 batch 영수증 SHA를 포함한 다음 안전 인계 JSON을 새 공개 진단에 작성해야 한다.

```json
{"allow_deep_g_raw_control": true, "previous_E2_terminal": true, "e2_batch_receipt_sha256": "PLAN.json의 e2_batch_receipt_sha256"}
```

ROOT는 환경의 `INFORMS_ASSET_ROOT`, `INFORMS_CACHE_ROOT`를 기존 campaign asset/cache로 설정하고, OMP/MKL/OPENBLAS threads=2 및 `CUDA_VISIBLE_DEVICES=0`을 유지한다. private `final_execution/raw_deep_g_control_1792090190000000000.py --execute --root-handoff <새 ROOT 공개 인계 JSON의 절대경로> --reserve-seconds 6000`를 기존 Python으로 실행한다. 환경에 상속 GPU owner가 있으면 거부하며, ACTIVE lease가 있어도 거부한다. 실행은 독립 중앙 GPUReservation(총 43,200초·training reserve 최소 6,000초·원 48시간 deadline·공개/비공개 합계 30GiB)을 갖는다. 승인·종료 신호 없이 실행하지 않는다.

원 API 순서는 ParentPool RAW/G M_dense·V 읽기 → `validate_parent_caches`의 실제 truth/mask/origin/scaler/stride 검증 → 독립 pre-target seal → `fit_combination` → COMPLETE에만 표준 V wrap이다. conditional head, seed92601, CUDA, lr0.001, 0.25/1/3 epoch, effective16/micro4를 유지한다. 실행 중 registry의 Raw parent mutable 상태와 새 4행 mutable 상태만 바뀔 수 있다. 과학 identity와 그 외 행은 종료 시 재대조한다.

개별 경로 오류는 private traceback과 공개 error class로 보존하고 독립 경로를 계속한다. 자원 오류는 남은 큐 전체를 deferred로 남긴다. 부분 디렉터리와 이전 결과는 덮거나 재개하지 않는다. 결과에는 실제 epoch/update/exposure, 선택 지점, clipping, CPU/runtime PID, 중앙 lease 비용, 수치 완료와 자원 상태를 따로 기록한다. H 학습의 F 호출 0은 frozen parent cache를 쓰는 학습 범위만 뜻하며, RawSmall 배포의 B×C foundation 스트림 비용을 0으로 뜻하지 않는다. 학습 마지막 checkpoint 선택은 수렴 증거가 아니다.

CPU metadata guard 8개 PASS 및 stdlib-only import를 실제 확인했다. 이 검사는 실제 fit/V 성공·독립 FP64 검산·비용 우위나 연구 해결을 뜻하지 않는다. 기존 CPU421/기존 source suite 검증 범위에 새 oneoff가 자동 포함됐다고 주장하지 않는다. 원 frozen source33은 불변이다. 기존 v1 준비 기록은 보존하지만 최종 실행 기준은 이 v2 계획뿐이다.
