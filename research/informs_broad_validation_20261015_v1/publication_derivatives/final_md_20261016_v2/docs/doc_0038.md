# GitHub 링크 대소문자 사전 점검

진행 중 산출물에 대한 가벼운 metadata snapshot이다. 최종 payload·staged Git·archive·과학 결과 검증이 아니다. 실제 GPU 비용 작업은 ROOT가 계속 수행했다.

[확인] Windows blind spot을 실제 재현했다. 원 publication_check.py SHA65cb9a05…의 _link/_failure 두 함수만 AST로 분리해, 실제 PUBLIC_EXCLUSIONS_KO.md 위치에서 합성 target `PUBLICATION_CHECK.PY`를 검사했다. 파일을 수정하지 않았는데 Path.exists=True, Path.resolve가 `publication_check.py`로 교정되어 failures=[]였다. Markdown/HTML img/SVG가 같은 함수를 사용한다. 이 합성 잘못된 링크는 실제 문서에 삽입하지 않았다.

승인된 routine 수정은 [SOURCE_PATCH_GITHUB_LINK_CASE.json](../../../SOURCE_PATCH_GITHUB_LINK_CASE.json)에 있다. 원문2개는 SHA 이름의 source_snapshots에 보존했다. 수정 후 함수는 resolve 전에 URL-decoded relative path를 lexical POSIX 경로로 정규화하고 payload/HEAD/virtual inventory의 정확한 case와 비교한다. 공유 inventory는 inspect마다 한 번 만든다. 정확한 case·상위 경로·공백 인코딩·anchor·directory·virtual 통계의 동작은 유지하며 raw symlink 경로도 resolve 전에 거부한다.

[확인] [RED.json](../../gzip_extra_aux_20261016_v1/files/item_0434.json.gz)은 새 회귀5개 실패/error0, [GREEN.json](../../../diagnostics/github_link_case_1792068720293/GREEN.json)은 기존 검사를 포함한 명시 test_publication_check 모듈25/25 PASS다. child 환경은 CUDA_VISIBLE_DEVICES=-1, OMP/MKL/OPENBLAS=2였고 torch/numpy/campaign/gpu_runtime import0이다. root pytest·실자료·모델·실제 전체 pack은 실행하지 않았다. RED traceback의 로컬 경로는 공개 기록에서 가렸다.

현재 case 진단은 `REPORT_FINAL.json`을 사용한다. 이전 REPORT/REPORT_V2/REPORT_V3는 중간 관찰로 보존했다. REPORT_V3의 유일한 missing은 검사 당시 아직 생성 전인 자신의 출력 JSON을 README가 먼저 링크한 경우이며, 현재는 원인을 구분했다. 현재 문서의 실제 case 오류가 있으면 report findings에 문서·행·원 링크·정규화 경로·정확한 case 후보를 남긴다. 역사적 blind spot 필드는 수정 전 source에 대한 증거이며 현 source의 실패를 뜻하지 않는다.

## 검사 방식

[check_link_case.py](../../../diagnostics/github_link_case_1792068720293/check_link_case.py)는 stdlib만 사용한다. 모델·배열·원자료·archive 내용을 열지 않으며 Git을 실행하지 않는다. 실제 directory entry spelling 또는 ROOT가 전달한 정확한 POSIX path 목록과 비교한다. 링크 target에 Path.resolve를 적용해 case를 교정하지 않는다.

- URL의 query/fragment를 먼저 분리하고 path를 한 번 decode한다. %20·anchor·상위 경로·directory를 구분한다. heading anchor 자체의 존재는 검사하지 않는다.
- Markdown inline/image/reference definition과 HTML href/src를 검사한다. fenced/inline code는 제외한다. Markdown nested literal parentheses/escaped delimiters의 전체 CommonMark 렌더 검사는 범위 밖이다.
- 알려진 최종 제외 문서는 읽지 않고 별도 목록에 둔다. raw MASTER/원 package·초기 잘못된 report·개인 경로가 있는 원 사고 JSON·수정 전 규약 사본·중간 projection README와 명시 intermediate snapshots를 구분한다.
- pack manifest의 경로 목록은 metadata로만 읽는다. final 명시 목록에 manifest와 모든 archive 이름이 포함된 경우의 원 통계 경로는 restore-only virtual로 분류한다. archive byte 검증은 하지 않는다.
- clone 직후 없는 통계 원본으로 직접 연결하는 문서는 RESTORE_ONLY_TARGET_REQUIRES_PACK_INDEX_LINK다. virtual path의 정확한 case를 검사하는 것과 clone에서 링크가 바로 작동하는 것은 별도다.
- 명시 file-list가 없으면 최종 공개 membership은 미검증이다. 이 기본 snapshot의 대소문자 PASS를 최종 게시 PASS로 쓰지 않는다.

## ROOT 최종 재검사

아래 인자는 실제 repository-relative POSIX 이름이 한 줄에 하나씩인 텍스트 목록이다. ROOT가 HEAD/index/최종 payload의 정확한 이름을 준비한다. --repository-path-list에는 필요한 기존 HEAD 경로와 staged/payload 경로의 합집합을 전달한다. --tracked-file-list에는 공개 가능한 기존 HEAD 경로를 전달한다. 이 도구가 Git 경로 목록을 대신 생성하지 않는다.

```text
python check_link_case.py --repository-root <repo> --campaign <campaign> --file-list <final_PAYLOAD_FILES.txt> --tracked-file-list <HEAD_paths.txt> --repository-path-list <exact_HEAD_index_payload_union.txt> --output-report <new_case_report.json>
```

--virtual-file-list를 추가하면 ROOT가 명시한 복원 전용 통계 경로도 검사할 수 있다. final archive의 manifest/all-parts가 payload에 있으면 그 원본 경로는 자동으로 restore-only 분류된다. 이 report는 정규화·case·membership만 다루며 publication_check의 SHA/size/privacy/SVG·실제 archive 검사를 대체하지 않는다. output은 exclusive create여서 기존 report를 덮어쓰지 않는다.

고정 scientific source6 SHA는 원값과 일치한다. 변경한 production 파일은 publication_check.py와 test_publication_check.py 두 개뿐이며 registry·기존 과학 결과·타 작업자의 변경을 보존했다.
