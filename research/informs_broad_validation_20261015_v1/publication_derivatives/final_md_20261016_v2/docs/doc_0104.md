# 같은 G의 핵심 whole-path 비용을 먼저 측정하는 scheduling 계획

상태는 준비이며 실제 비용 실행은0이다. 원 방법·자료·학습·전체 비용 범위를 바꾸지 않고, main4의 같은 G 대조를 먼저 실행하도록 ROOT가 요청했다. V 순위나 양성 결과로 뽑은 목록이 아니다. [계획 JSON](../../gzip_extra_aux_20261016_v1/files/item_0287.json.gz)과 [정확한 기존 CLI 명령](../../../diagnostics/core_breadth_cost_ready_1792092000000000000/ROOT_COMMANDS.ps1)은 ROOT 검토 후 이전 K20/비용 owner가 terminal일 때만 실행한다. 이 파일을 작성하며 GPU·모델·NPZ·weights·T·registry·기존 source·Git을 수정하거나 실행하지 않았다.

자료별 다섯 경로는 RawSmall, 동일 deep G, 그 G와 결합한 B0-H, B2-H, Raw-H다. 4자료 × 5경로 =20개의 서로 다른 actual run ID와 현재 V manifest·checkpoint/부모 artifact의 선언 SHA·fit receipt·source/cost pins를 묶었다. 세 H × main4의 실제 `g_m/g_v` metadata에서 G run ID, artifact/model/data/scaler SHA가 해당 G와 모두 같음을 [12개 head 검사](../../gzip_extra_aux_20261016_v1/files/item_0286.json.gz)로 확인했다. 이 비용20은 앞서 준비한 representative replay20(Raw/G/B0/제안/LoRA)의 목록과 다르며 같은 숫자로 혼동하지 않는다. LoRA와 다른 원리의 비용은 원 전체 큐에 계속 남는다.

기존 `cost_campaign.py:74–89`의 `condition_plan` AST 함수만 분리해 metadata route families에 실제 적용했다. 데이터/torch/numpy import 없이 계산한 예상은 자료당18조건, 총72조건이다. 자료당 B1/B8 각각 Raw 4개 row 변형(full/32/8/4) + G 1개 + H 3개 =8 fresh 조건, 동일 cuda/small의 5경로 balanced1조건으로 총9조건씩이다. 전체는 fresh64 + balanced8이며, 각 조건은 원 warmup10/timed20/stage_probe20 계약을 유지한다. 예상 조건 수와 계획은 실제 trial 완료 증거가 아니다.

공식 CLI 인자는 `--dataset`, 반복 `--run-id`, `--skip-raw-variants`, `--reserve-final-seconds`뿐이다(`cost_campaign.py:143–150`). main4의 B1 fresh를 모두 먼저 실행한 뒤 B8로 넘어가게 하는 공식 argument는 없다. 현재 CLI는 한 자료 안에서 B1 fresh 전부 → B1 balanced → B8 fresh 전부 → B8 balanced를 실행하며 stage probe는 각 조건 내부에 있다. 함수/조건 리스트를 바꾸지 않고 자료 간 균등 B1 선행 scheduling을 지원한다고 쓰지 않는다. PS1은 이 기존 CLI의 자료별5경로 호출 네 개만 담는다. 새로운 일반 launcher나 시험 프레임워크가 아니다.

원 [PLAN_V2](../../gzip_1792092403733272600_v3/files/item_0002.json.gz)와 원385 inventory는 그대로 보존했다. 원16그룹 ready231경로/예상576조건의 남은 큐를 이72조건으로 대체하거나 전체 완료로 바꾸지 않는다. 새 head가 포함된 이 선행 비교의 성공도 전체 grid·모든 K·모든 seed·전체 비용 완료가 아니다. ROOT는 실제 잔여 GPU process-wall을 확인하며 비용 ceiling39,600초와 최종 replay/T/E0 reserve3,600초를 유지한다. 시간 부족이면 경로·조건별 PARTIAL/DEFERRED를 그대로 남긴다.

기존 PeMS9 중 이 선행20과 exact ID로 겹치는 것은 RawSmall 한 개다. 같은 source/artifact/manifest와 B1/B8의 Raw 4row fresh8조건은 기존 증거로 별도 재사용 가능한 범위다. 기존9경로 balanced와 새5경로 balanced는 residency·method order가 달라 서로 대신하지 않는다. 기존 CLI에는 이전 fresh 영수증만 주입해 같은 새로운 balanced 그룹을 구성하는 공식 인자가 없다. `--skip-raw-variants`는 원4row 검사를 보존하는 reuse 기능이 아니므로 사용하지 않았다. 따라서 이 정확한 CLI 네 개를 실행하면 PeMS Raw fresh8조건은 다시 요청된다. 그 실제 중복 측정을 새 방법/새 route나 기존9 확장으로 부풀리지 않는다. 이 한계는 ROOT가 비용 배분에서 확인할 사항이며, 원 조건을 조용히 지우지 않았다.

PS1은 환경의 `INFORMS_ASSET_ROOT`, `INFORMS_PUBLIC_ROOT`, `INFORMS_CACHE_ROOT`만 사용하고 개인 절대경로를 넣지 않았다. 각 호출은 `--reserve-final-seconds 3600`을 명시하며 별도 외부 GPU owner를 만들지 않는다. 원 CLI가 자기 중앙 lease를 획득한다. ROOT는 실행 전 봉인 SHA·V/artifact·source·잔여 자원·이전 owner 종료를 확인하고, 새 actual receipt와 exit/resource 상태를 별도로 검산해야 한다. 이 문서는 선택 잠금이나 T 실행을 호출하지 않는다.
