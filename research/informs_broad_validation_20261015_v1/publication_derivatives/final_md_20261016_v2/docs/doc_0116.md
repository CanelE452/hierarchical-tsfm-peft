## 정확히 허용한 입력과 globals

[fit_base.create_model](../../../fit_base.py)과 [data_contract.fit_statistics](../../../data_contract.py)의 실제 코드를 읽었다. mean/std는 float32, observed_counts는 int64 NumPy 배열로 저장된다. 이 자체 학습 artifact에 대해 승인된 다음 다섯 global만 `torch.serialization.safe_globals(...)` context에 임시 허용했다.

```text
numpy._core.multiarray._reconstruct
numpy.ndarray
numpy.dtype
numpy.dtypes.Float32DType
numpy.dtypes.Int64DType
```

`numpy._core.multiarray._reconstruct`는 실제 설치된 NumPy C extension의 `_multiarray_umath._reconstruct`와 동일 객체임을 확인했다. NumPy 2.4.6 package initializer와 C extension의 SHA도 기록했다. static checkpoint global 목록은 앞의 세 NumPy global뿐이었고, 동적으로 생성되는 dtype은 승인한 Float32/Int64 두 타입으로 제한했다. 예상 밖 global은 없었다.

두 로드는 모두 `torch.load(path, map_location='cpu', weights_only=True)`를 유지했다. 각 context 안의 globals가 기존 집합과 승인된 다섯 개의 합집합인 것을 확인했고, 각 context 종료와 전체 작업 종료 후에는 원래 정확한 집합으로 복원됐다(기본 3→3, persistent 추가 0). weights_only=False, custom unpickler, unrestricted pickle 또는 다른 global 추가는 사용하지 않았다.

실제 checkpoint 파일 읽기와 CPU tensor state 로드는 있었다. 모델 객체 생성·forward·재학습·GPU·T·원자료 로드는 없다. model weights를 별도로 저장하거나 출력·공개하지 않았다. 모델/GPU 구현 모듈 import와 model 객체/GPU 초기화를 차단했고 physical API 실행 중에는 추가 torch.load와 raw-task/normalization fallback도 차단했다.

## identity와 수치 검산

각 artifact SHA는 receipt와 로드 전후 정확히 일치했다. bundle의 spec/source/config/data SHA·fold·normalization fit_end/train_end를 원 계약과 대조했다. 원 DATA_CONTRACT의 L/H/C/전체 columns 순서/source-array fingerprints와 spec으로 config SHA를 다시 만들어 기존 source config SHA와 일치시켰다. 추출 mean/std의 정확한 float32 dtype·shape·finite와 std>0, counts의 int64·양수도 확인했다. scaler fingerprint는 receipt의 refit_scaler_sha와 V manifest의 scaler SHA에 정확히 같았다.

```text
자료      fold       A60 끝점   V 원점   H    전체 C   관측 target cells
Beijing   secondary  10098      35       48   11       18390
Jena      secondary  10063      34       48   21       34272
```

모든 원점·채널을 보존했다. 새 private NPZ는 mean/std 두 멤버만 들어 있으며 실제 다시 읽어 원 배열과 동일한 것을 검증했다. 각각 473B와 559B다. fold/data/A60/columns/scaler/artifact 계보는 별도의 private identity JSON에 보존하고 공개에는 경로·SHA와 검증 결과만 둔다. 이 통계는 앞으로 **동일 secondary fold·data·columns·A60·scaler identity가 모두 일치하는 경우에만** 다른 모델 원단위 분석에서 재사용할 수 있다. 이번 대상은 기존 두 DIRECT_G V뿐이다.

physical API 출력은 private 원본과 동일 bytes로 새 public snapshot에 복사했다. 채널별 MSE/MAE를 독립 재집계하고 macro RMSE=sqrt(macro MSE), 관측수·원점·H·채널 수와 전체 channel 순서, 기존 normalized primary MSE/MAE 불변을 검증했다. 원 CSV를 반올림하거나 행·채널을 삭제하지 않았다. 원수치는 CSV와 VERIFICATION에 보존한다.

이질적 센서 단위의 macro 값을 하나의 물리량으로 해석하지 않으며 channel별 결과를 함께 봐야 한다. 두 secondary 결과를 primary 또는 서로 다른 자료 사이 성능 순위로 해석하지 않는다. 이는 저장된 V 예측의 보조 재분석이며 새 학습·새 추론·independent unseen 일반화·유의성 검정이 아니다.

## 자원과 이전 snapshot 구분

CUDA_VISIBLE_DEVICES=-1, CPU thread 2, CUDA initialized False→False였다. child wall은 1.568초, sampled RSS peak는 503,320,576B(약 480.00MiB), resource stop은 없다. private/public 신규 파일은 약 0.32MiB로 200MiB 제한 안이며 source9 전후와 frozen source18이 일치했다. 공개 파일은 모두 20MiB 미만으로 추가 gzip 파생은 필요하지 않았다.

앞선 primary 332 원단위·334 시간블록 snapshot과 기본 weights-only 실패 snapshot은 그 당시 범위를 그대로 보존했다. 이 결과가 이전 미실행을 소급해 실행으로 바꾸는 것은 아니다. 최종 보고에서 이번 **별도 성공 snapshot**을 추가로 연결해야 한다. primary 보조 분석 시작 뒤 생긴 다른 V나 다른 secondary 모델은 이번 대상에 포함하지 않았다.
