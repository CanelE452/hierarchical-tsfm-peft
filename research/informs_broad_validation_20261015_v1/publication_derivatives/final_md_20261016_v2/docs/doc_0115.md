# secondary frozen A60 통계의 안전 로드 시도

실제 상태는 **BLOCKED_SAFE_WEIGHTS_ONLY_LOAD_NO_STATS_NO_ANALYSIS**다. 두 immutable selected_bundle.pt의 SHA가 각 COMPLETE_VALID receipt와 정확히 같은 것을 확인한 후 `torch.load(..., map_location='cpu', weights_only=True)`를 실제 호출했다. 두 호출 모두 `UnpicklingError`로 종료했다. 통계 추출 0, 새 frozen-stats NPZ 0, 신규 physical 분석 0이다.

```text
run                                      실제 secondary A60 끝점   안전 로드 결과
secondary_beijing_E1_DIRECT_G_k0_s92601    10098                     BLOCKED
secondary_jena_E1_DIRECT_G_k0_s92601       10063                     BLOCKED
```

끝점은 DATA_CONTRACT의 실제 secondary A_stop과 receipt의 refit/normalization fit_end에서 확인했으며 추정값을 사용하지 않았다. data SHA, fold, receipt의 scaler SHA와 현재 V manifest의 scaler SHA도 로드 전에 일치했다. 로드가 차단됐으므로 checkpoint 안 mean/std·canonical channel order를 추출·검증했다고 주장하지 않는다.

두 오류의 원인은 기본 weights-only unpickler가 `numpy._core.multiarray._reconstruct` global을 허용하지 않는다는 것이다. [fit_base.py](../../../fit_base.py)의 실제 저장 흐름은 NumPy mean/std를 normalization dictionary에 넣어 model tensor state와 함께 bundle로 저장한다. 이번 실패는 이 구조와 부합하지만, 실패한 전체 bundle 내용을 임의 unpickler로 추가 열어 확인하지 않았다.

caller는 safe_globals를 추가하지 않았다(기본 개수 전후 3). `weights_only=False`, custom unpickler, unrestricted fallback을 사용하지 않았다. 오류 메시지의 allowlist 추가 제안도 실행하지 않았다. 실제 checkpoint artifact 파일 읽기는 있었으며 weights-only 로더 내부에서 CPU tensor state 일부가 처리됐을 가능성을 배제하지 않는다. 모델 객체 생성·forward·모델 파라미터 출력·공개, 새 원자료·T·GPU·재학습은 없다. 원 checkpoint를 수정하거나 새 모델로 저장하지 않았다.

이 진단은 [앞선 V 보조 분석 snapshot](doc_0103.md)과 별도다. 앞선 snapshot은 selected checkpoint 읽기를 하지 않는 범위에서 primary 332개 원단위 분석과 V 334개 시간블록 검산을 수행했다. 이번에는 ROOT가 명시한 확장된 입력 허용에 따라 secondary checkpoint bytes를 실제 읽으려 했으므로 앞선 무checkpoint읽기 범위와 섞지 않는다. 그 snapshot의 secondary 원단위 미실행 상태는 그대로 남는다.
