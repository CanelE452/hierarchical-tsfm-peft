# 그림 생성 비용 namespace 교정: 실행 전 검증

상태는 **ROOT 검토 대기**다. 이 진단에서 새 variant의 실제 V/T 그림은 생성하지 않았다. 원 `report_figures.py`와 기존 결과는 변경하지 않았다.

원 V와 T CLI는 저장예측을 검산하고 일부 그림을 만든 뒤, `diagnostics/final_cost_queue_ready_1792088347039621300/EXACT_PEMS9_REUSE.json`의 정상적인 최상위 JSON 목록을 비용 영수증으로 취급해 `list.get` 오류로 종료했다. 원 V 부분 폴더는 `figures/snapshot_20261015T215844Z_1792101524808062000`, T 부분 폴더는 `figures/snapshot_20261015T220221Z_1792101741972942600`이며, 각각 실패 영수증과 생성 파일을 보존했다. 완성 `FIGURE_MANIFEST.json`은 없다. 이 실패는 저장예측의 수치 불일치를 뜻하지 않는다.

[새 variant](../../../report_figures_cost_namespace_v2.py)는 원본의 `_costs` 탐색 위치만 `public/costs`로 제한하고, 기존 경로명 휴리스틱의 `if/continue` 두 줄을 제거했다. `relative` 대입은 그대로 보존했다. [전체 byte diff](../../../diagnostics/publication_safe_aux_views_20261016_v1/views/figure_cost_namespace_fix_20261016_v1__SOURCE_NAMESPACE_ONLY.diff.txt)와 [AST 검증](../../../diagnostics/figure_cost_namespace_fix_20261016_v1/SOURCE_DIFF_PROOF.json)은 다른 함수, 점수 계산, 허용오차, 사례 선택, 그림 생성 코드를 변경하지 않았음을 확인한다. 원본 수정이나 merge는 하지 않았다.

[namespace 메타검사](../../gzip_extra_aux_20261016_v1/files/item_0377.json.gz)에서 실제 `trials_file`과 `COMPLETE_PROTOCOL`을 가진 영수증은 96개였으며, 전부 `costs/` 안에 있었다. 그 밖의 동일 조건 영수증은 0개이고 JSON 파싱 오류도 0개였다. 이 96개는 fresh 82개와 balanced 14개이며, timed 조건 행은 137개다. [공식 비용 집합 대사](../../gzip_extra_aux_20261016_v1/files/item_0378.json.gz)는 원 최신 보고서 `COSTS.csv` 137행과 `(receipt_relative_path, cost_run_id)` 집합이 정확히 같음을 확인했다. 새 variant의 빈 예측목록 probe는 실제 96개 영수증과 96개 trials 파일의 SHA를 확인했고 그림을 생성하지 않았다. 137은 조건 행 수이고 96은 영수증 파일 수다.

[실제 RED](../../../diagnostics/figure_cost_namespace_fix_20261016_v1/RED_RESULT.json)는 정상 비용 영수증과 진단 JSON 목록이 공존할 때 원 함수가 같은 `AttributeError`로 실패함을 확인했다. [GREEN 결과](../../gzip_extra_aux_20261016_v1/files/item_0376.json.gz)는 다음을 별도로 기록한다.

- 새 namespace 회귀 6개: 6 PASS, exit 0. 진단 목록 제외, 정상 영수증 보존, 실제 비용 namespace 안의 잘못된 목록 거부, trials SHA 변경 거부, 원 오류 재현, byte/AST 변경 범위 검증.
- 기존 관련 그림 검사 20개를 새 variant로 연결: 20 PASS, exit 0. 합성 저장예측과 임시 렌더를 사용했으며 실제 연구 V/T 재렌더 결과가 아니다.
- source39, 원 그림 모듈과 관련 원 테스트, registry, selection lock의 전후 SHA가 동일했다.

CPU 검사는 `CUDA_VISIBLE_DEVICES=-1`, BLAS/OMP 2 threads로 실행했고 차용 GPU owner 환경키는 제거했다. 새 학습, 실제 모델 예측, T 재추론, 새 선택, Git 변경은 없다. 이 수정 검증을 실제 연구 그림 완성이나 독립 일반화 증거로 해석하지 않는다.

## ROOT 검토 후 사용할 명령

`R`은 campaign 공개 폴더, `C`는 승인된 private cache를 뜻한다. 자산과 캐시 환경변수는 기존 로컬 설정을 유지한다. 아래 두 명령은 아직 실행하지 않았다.

```powershell
python -X utf8 -u -B "$R/report_figures_cost_namespace_v2.py" --public-root "$R" --private-root "$C" --split V_select
python -X utf8 -u -B "$R/report_figures_cost_namespace_v2.py" --public-root "$R" --private-root "$C" --split T_final
```

실행한다면 각 CLI의 실제 종료코드와 새 `FIGURE_MANIFEST.json`, 제외 항목, 그룹별 실제 파일을 다시 확인해야 한다. 원 실패 폴더를 성공 폴더로 재사용하거나 덮어쓰지 않는다. 이 변경은 원 report API의 비용 해석을 바꾸지 않으며, 별도 K 전환 비용을 일반 배포 비용으로 합치지 않는다.
