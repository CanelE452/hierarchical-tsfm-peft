# replay44와 최종 선택 검토40: 미실행 metadata 입력

기존 [REPLAY_MATCHED_FULL40](../../gzip_aux95_1792094747124151400/files/item_0074.json.gz)은 변경하지 않았다. [REPLAY44.json](../../gzip_aux95_1792094747124151400/files/item_0072.json.gz)은 원40에 Beijing/Jena/Electricity/PeMS08의 RawRidge 네 actual ID를 더한 명시적 입력이다. 추가4개의 실제 V manifest/reference, RIDGE_FIT_RECEIPT, data/scaler/source, coefficient artifact의 선언 SHA·상대경로와 파일 존재를 [작은 metadata 증거](../../gzip_extra_aux_20261016_v1/files/item_0631.json.gz)에 묶었다. NPZ·계수·weights·모델은 열거나 대량 hash하지 않았다.

기존 `replay_explicit.py` SHA `8dee2e5a902a17535962f28ae7a06a8675b29dbadb16357d0a341e4b5bf61e30`의 입력형식과 source18을 그대로 사용했다. 같은 [공개 wrapper](../../../diagnostics/final_replay_readiness_1792091200000000000_v3/replay_explicit.py)를 `--execute` 없이 metadata CLI로 실제 호출해 exit0, READY44, numpy/torch/pandas import0을 확인했다. [실행 증거](../../gzip_extra_aux_20261016_v1/files/item_0630.json.gz)는 실제 GPU checkpoint replay가 아니다. 기존 exact portable-route PASS는6개이고 새 replay가 필요한 ID는38개다. 추가 Ridge4 중 Beijing/Electricity/PeMS는 기존 portable PASS가 있지만 Jena는 없다. ridge의 별도 closed-form 학습 재현 영수증을 portable V replay PASS로 세지 않았다.

```text
python -X utf8 -B research/informs_broad_validation_20261015_v1/diagnostics/final_replay_readiness_1792091200000000000_v3/replay_explicit.py --plan-json research/informs_broad_validation_20261015_v1/diagnostics/replay44_selection_review40_1792093500000000000/REPLAY44.json
```

위 기본 명령은 환경의 INFORMS_PUBLIC_ROOT/INFORMS_CACHE_ROOT/INFORMS_ASSET_ROOT를 사용한 metadata 확인이다. ROOT만 이전 비용 owner 종료·잔여 자원을 확인한 후 `--execute`를 추가해 실제 replay를 실행한다. 이번 작업은 GPU·학습·T·선택 잠금·registry·과학 source·기존 계획·Git을 변경하거나 실행하지 않았다.

[SELECTION_REVIEW40.json](../../gzip_aux95_1792094747124151400/files/item_0090.json.gz)은 **검토 후보**다. 원 full40에서 standalone B2 parent4를 빼고 RawRidge4를 더했다. 제외한 B2 parent4는 replay44에서 계속 실제 검증할 대상이며, 여기서는 최종 T 검토 범위 밖임을 명시한다. 자료별10개는 Raw/G/B0/LoRA, 동일 G의 B0-H/B2-H/Raw-H/Hpast/alpha, native RawRidge다. V 최고점을 자동으로 고른 목록이 아니며, 정보량·학습 노출이 다른 강한 기준선도 드러내기 위한 비교다. ridge는 FP64 CPU·모든 합법 A 원점 closed-form 적합이므로 neural의 짧은 학습과 같은 노출/장치 조건이라고 주장하지 않는다.

ROOT가 실제 비용·최신 공개 공간·실제 replay44 PASS 및 독립 감사를 검토한 뒤에만 최종 T 선택을 확정한다. JSON 생성이나 metadata READY가 lock/T 또는 실제 재추론 완료를 뜻하지 않는다. 원 자료의 protected TEST는 열지 않았다.

[T40 공간 대사](../../gzip_extra_aux_20261016_v1/files/item_0632.json.gz)는 기존 publisher의 44경로 metadata 표에서 이 정확한40만 선택했다. Ridge4의 원 V gzip 크기와 manifest SHA를 실제 네 파일에 대조했다. T 원점 수는 기존 분할 산술만 재사용했고 T 값은 읽지 않았다. 기존 모형의 T40 예상은 scaled gzip58,556,224B, 경험 pack40,353,786B, 보수 planning pack79,667,149B다. 모두 추정이며 상한이 아니다.

이전 서로 다른 pack의 압축률이 새 T에 맞는다는 보장은 없다. [추가 시나리오](../../../diagnostics/replay44_selection_review40_1792093500000000000/NEW_E2_PACK_SCENARIO_NOTE.json)는 방금 실제 완성한 E2 canonical20의 압축률0.788277을 사용하면 T40 archive46,158,529B + 같은 metadata reserve3,145,728B =49,304,257B가 됨을 보인다. 새 그림·보고서와 계속 생성되는 비용 파일은 이 합계에 포함되지 않았다. 따라서 공간 충분을 선언하지 않으며 ROOT의 최신 actual payload 검사가 필요하다. 정밀도·행·채널을 줄여 게시 상한을 맞추는 계획이 아니다.
