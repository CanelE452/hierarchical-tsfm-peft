# 합성 오류 경로 fixture 교정과 CPU 재검산

`test_native_cpu_depth.py`의 `test_asset_absolute_error_stays_private` 입력에서 실제 작업 경로를 없애고 사용자와 무관한 합성 drive/root를 실행 중 조합하도록 바꿨다. 실제 사용자의 경로를 숨기거나 인코딩한 것이 아니다. 공개 오류에서 drive와 root가 모두 제거되는 두 단언과 `completed_routes == 8` 검사는 유지했다. 기존 파일 원본과 SHA는 private cache에 보존하고 이 공개 기록에는 기존 경로 문자열을 복제하지 않았다.

원본 파일의 개인정보 검사는 2건을 검출했고 합성 입력으로 교정한 파일에서는 0건이었다. 변경한 테스트 메서드 밖 AST는 정확히 같고, 같은 폴더의 다른 Python 소스와 실제 연구 구현은 바꾸지 않았다. [원/신 SHA·변경 줄 범위](../../gzip_extra_aux_20261016_v1/files/item_0542.json.gz)와 [실행 검증](../../gzip_extra_aux_20261016_v1/files/item_0543.json.gz)을 참고한다.

실제 검사는 단독14/14 PASS, Torch 사전 import14/14 PASS, [명시된 campaign 전체421/421 PASS](../../gzip_extra_aux_20261016_v1/files/item_0022.json.gz)다. 실패·오류·skip은0, 전체 suite exitcode0이며 실행 전후 모든 campaign root Python SHA가 같았다. [기존421 영수증](../../gzip_extra_aux_20261016_v1/files/item_0021.json.gz)도 보존했다. 테스트 추가나 연구 조건 변경은 없다.

CUDA_VISIBLE_DEVICES=-1, CPU threads2에서 실행했다. CUDA available=false/device_count0/initialized=false가 전후 동일했다. Torch CPU profiler가 장치 수 조회 경고를 남겼으므로 CUDA API 호출0이라고 주장하지 않는다. 실제 GPU 학습·추론·lease 및 registry/Git 쓰기를 실행하지 않았다. 저장 결과 재채점·checkpoint 재추론·독립 일반화 검증의 증거로 이 CPU 검사를 사용하지 않는다.

교정된 [테스트 소스](../../../test_native_cpu_depth.py)를 게시 후보에 복원하고, 원래 이 파일을 연결하던 설명문 두 개를 함께 복원할 수 있다. 원 개인 경로가 있는 private backup과 실제 실행 로그는 공개하지 않는다.
