# Launcher 최종 owner 판정 보완 — 실제 GPU 비용은 아직 미측정

[기존 실행·재개 runbook](doc_0045.md)의 API·20개 scope·입력 pins·V3 helper를 그대로 사용한다. private `multik_launcher.py`와 그 CPU test만 보완했다. 기존 364e3… launcher와 58개 시험 증거는 보존했으며, 현재 코드를 실행하기 전에는 **이 폴더의 새 [SOURCE_FREEZE.json](../../gzip_extra_aux_20261016_v1/files/item_0503.json.gz)**과 대조해야 한다. [기존 INPUT_PINS](../../gzip_aux95_1792094747124151400/files/item_0078.json.gz)의 SHA는 바뀌지 않았다.

[확인] 마지막 20번째 child가 끝난 뒤 owner 확인이 실패하거나, 최종 metadata/SHA 검사 중 owner deadline을 넘기면 전체 결과는 미완료다. `resource_status=OWNER_RESOURCE_LIMIT`, `stop_reason=OWNER_RESOURCE_LIMIT`, `actual_cost_raw_statistics_complete=false`를 남긴다. 마지막 child 뒤의 실패 이력은 최종 owner 재검사가 통과하더라도 지우지 않는다. 최종 metadata 검사 반환 뒤에도 실제 owner를 다시 검사한다.

이미 실행한 수치·child 결과·transition ledger는 보존한다. 따라서 child 자체 protocol 완료20개·numeric trial3600개·numeric remaining0이면서 **전체 owner 자원 내 완료는 false**일 수 있다. `actual_resource_valid_trials`는 child의 관측된 guard 안에서 반환된 trial 수이며, 전체 owner의 마지막 검사와 별개임을 `trial_resource_counts_scope`에 명시했다. 최종 완료 판단에는 `resource_status`, `owner_resource_events`, `final_owner_check`를 함께 사용한다.

local `max_seconds`는 다음 child의 admission만 제한한다. 마지막 child가 local admission window 이후 정상 반환해도 global owner가 유효하고 20개 scope를 모두 마쳤으면 완료가 가능하다. 이 동작을 global owner deadline 초과와 구별하는 CPU test를 추가했다. timeout/kill·새 owner·새 예산은 추가하지 않았다.

실제 RED에서는 마지막 child 뒤와 postflight 중 만료 두 주입 모두 잘못 `COMPLETE_EXACT20_SCOPES`를 반환했다.
