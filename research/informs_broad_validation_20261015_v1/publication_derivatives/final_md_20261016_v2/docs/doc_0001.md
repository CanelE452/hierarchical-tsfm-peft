# 확장 A 전용 부모와 E2 연결 실행 프로토콜

이 bridge는 main4의 새 A 전용 부모를 기존 E2 API에 명시적으로 연결한다. 작성·검증 단계에서는 메타데이터 계획과 임시 합성 회귀만 실행했다. 실제 GPU, 학습, 부모 예측, 모델·원자료·배열 로드, registry 변경, T 평가를 실행하지 않았다. 진행 중인 campaign의 중간 snapshot이며 실험 또는 전체 계획의 완료 증거가 아니다.

## 소유 파일과 검증 범위

- `extended_parent_e2.py`: 기본 메타데이터 계획 및 명시적인 `--execute` 실행 경로.
- `test_extended_parent_e2.py`: 표준 라이브러리와 임시 파일로 수행하는 합성·mock 회귀.
- 이 문서: 실행 조건, 실제 API, 검증 범위와 미해결 부모 상태.

기존 과학 source6/source18, 다른 작업자 파일, registry, 기존 receipt·결과를 수정하지 않았다. 새 bridge와 테스트는 이전 파일이 없는 것을 확인한 후 생성했다. source18의 기준은 [READINESS_AUDIT.json](../../gzip_extra_aux_20261016_v1/files/item_0388.json.gz)의 최상위 `final_evaluation_source18_sha256`이다. 구형 runbook의 report pin은 사용하지 않는다. 실제 source18 일치와 plan 읽기 전후 registry·DATA_CONTRACT SHA 일치를 확인했다.

## 부모 선택과 누출 제한

자료별로 primary DIRECT_G, B0 quarter K, B2 quarter K의 `COMPLETE_VALID` BASE_FIT_RECEIPT를 찾는다. quarter K는 채널 수의 올림 나눗셈 `ceil(C/4)`이며 DIRECT_G의 registry K는 0이다. 이름이 원래 E1 ID 또는 그 뒤 `__e1`, `__e3` 연쇄인 후보만 포함한다. LR followup이나 A+M control은 이 선택 경로에 포함하지 않는다.

세 family의 **요청 endpoint** 공통집합에서 3 → 1 → .25 순으로 하나를 선택한다. receipt의 `selected_epoch`는 별도 기록한다. endpoint 3을 요청해 epoch 0을 선택한 부모를 endpoint 0 부모라고 바꾸지 않는다. 실제 chained run ID, 선언된 selected artifact SHA, receipt SHA, source contract SHA를 plan에 고정한다. 계획은 artifact bytes를 읽지 않는다.

각 부모는 다음 조건을 모두 만족해야 한다.

- registry와 source spec의 dataset/family/primary/seed/K/L/H/C가 일치한다.
- role은 A 전용 `base_parent`이며 lr은 .001이다.
- 실제 search fit end는 A50, refit 및 normalization fit end는 A60이고 A60은 M_cal 시작점이다.
- source contract의 6개 파일 SHA와 source fingerprint가 현재 source6에 정확히 일치하고 receipt가 같은 fingerprint를 선언한다.
- data SHA와 요청 epoch 목록, selected artifact의 상대 경로·SHA 형식이 일치한다.
- 같은 자료 B0/B2의 foundation identity와 기록된 A60 scaler identity가 일치한다.

과거 candidate의 source 불일치는 `parent_omissions`에 actual/current SHA와 사유를 남기고 다음 후보·자료 탐색을 계속한다. 과거·현재 모델이 같았다는 추정은 하지 않는다. 유효 공통 endpoint가 없고 이런 후보 누락이 있으면 `DEFERRED_SOURCE_PARENT`이며 새 fit을 우회 실행하지 않는다. 같은 endpoint에 여러 유효 부모가 있으면 모호한 선택을 거부한다.

공통 endpoint가 .25뿐이면 `REUSE_INITIAL_E2_SKIP`으로 기존 초기 E2의 증거를 그대로 유지한다. 새 fit과 새 registry row는 0이다. 이는 초기 E2 완료를 재검증한 결과가 아니며 `initial_E2_completion_claimed=false`를 명시한다.

## 고정되는 신규 비교

공통 endpoint가 1 또는 3이면 같은 새 DIRECT_G를 사용해 자료당 다음 네 fit을 계획한다.

```text
CONDITIONAL / B2q : b = 새 B2 quarter, g = 새 DIRECT_G
CONDITIONAL / B0q : b = 새 B0 quarter, g = 새 DIRECT_G
PAST_CONTROL     : b = g = 새 DIRECT_G
ALPHA_FIT family : b = 새 B2 quarter, g = 새 DIRECT_G
```

alpha family는 한 번의 fit 호출로 ALPHA0/ALPHA05/ALPHA1/ALPHA_FIT 네 출력을 만든다. 따라서 자료당 fit 4개와 registry row 7개이다. 실행 receipt는 fit 호출, 완료 fit, 신규 표준 출력, 기존 fit·출력 재사용을 각각 센다. 고정 alpha 출력의 무학습 상태와 실제 head 업데이트 여부도 구분한다.

head의 epoch endpoints는 `[.25, 1, 3]`, learning rate .001, microbatch 4, effective batch 16, seed 92601, device cuda, fold primary이다. loss와 구조는 기존 `combination.fit_combination`을 그대로 사용한다. 각 private spec에 실제 `parent_run_id`, `g_run_id`를 넣으며 기존 postfit CLI의 초기 부모 하드코딩을 재사용하지 않는다. route_catalog가 이 명시적 부모를 이미 읽으므로 core 수정은 필요하지 않다.

새 ID는 다음 모양이다.

```text
primary_<dataset>_E2_<family>_k<K>_s92601_<B0|B2|G>__xp_e<1|3>_<binding SHA 앞 12자리>
```

binding은 세 부모의 실제 ID, artifact SHA, source contract SHA로 계산한다. ALPHA_FIT 토큰만 바꾸어 alpha alias를 만들고 나머지 suffix는 유지한다. 기존 registry ID의 과학적 identity가 다르면 거부한다. mutable 실행 상태는 계획의 identity를 대체하지 않는다.

## 기본 실행은 읽기 전용 계획

`--execute`가 없으면 표준 라이브러리로 source·registry·DATA_CONTRACT·부모 JSON만 읽고 JSON을 stdout에 출력한다. registry/receipt/model/cache를 쓰지 않고 torch/numpy/pandas나 실행 helper를 import하지 않는다. 출력 저장은 호출자가 redirect로 결정한다.

다음은 public root를 현재 디렉터리로 둔 PowerShell 예시다. 실제 개인 경로는 문서에 기록하지 않으며 ROOT가 기존 변수의 정확한 위치를 사용한다.

```powershell
# CPU 계획: $Python은 사용 중인 가상환경 python.exe, $R은 이 public root
$env:CUDA_VISIBLE_DEVICES = '-1'
$env:OMP_NUM_THREADS = '2'
$env:MKL_NUM_THREADS = '2'
$env:OPENBLAS_NUM_THREADS = '2'
& $Python -B -X utf8 "$R/extended_parent_e2.py" --public-root $R `
  --cache-root $C --asset-root $AssetRoot > $SavedPlan
```

`--dataset`은 beijing/jena/electricity/pems08에서 반복 지정할 수 있다. 미지정 시 main4 전부다. `--plan-json`은 저장된 계획을 읽어 현재 계획과 signature를 비교하는 입력 옵션이다. 서명에는 source22, bridge 자체 SHA, 선택한 실제 부모·receipt·source SHA, route spec이 포함된다. 과학 identity가 달라졌으면 새 계획을 검토해야 한다.

## 실제 실행 순서: ROOT의 GPU 인계 후에만

아래 명령은 구현된 미래 실행 인터페이스이며 이 작업에서는 실행하지 않았다. CPU 계획 환경의 `CUDA_VISIBLE_DEVICES=-1`을 그대로 두면 bridge가 실행을 거부한다. 활성 GPU owner가 종료·정산되고 ROOT가 인계한 후 독립 프로세스에서만 사용한다.

```powershell
# 기존 lease를 상속한 셸에서 실행하지 않는다. ROOT가 인계한 독립 셸에서만 설정한다.
$env:CUDA_VISIBLE_DEVICES = '0'
& $Python -B -X utf8 "$R/extended_parent_e2.py" --public-root $R `
  --cache-root $C --asset-root $AssetRoot --plan-json $SavedPlan `
  --reserve-seconds 6000 --execute
```

1. selection lock과 상속 owner 환경변수를 먼저 확인한다. 활성·손상된 selection lock 또는 nested lease 환경변수를 발견하면 모델 import와 registry 변경 전에 거부하고 batch receipt를 보존한다.
2. 현재 metadata plan을 다시 만들고 저장 plan의 signature와 비교한다. 신규 유효 부모가 없으면 resource·model import 없이 skip/deferred receipt를 쓴다.
3. C와 R의 합계 30 GiB, pending 1 GiB, 각 볼륨 free space, disjoint roots를 확인한다. 이 확인은 파일 내용 대신 stat만 사용한다.
4. `GPUReservation(C, total_gpu_seconds=43200, reserve_seconds=6000, wall_deadline=1792050350+172800, purpose='training', kind='extended_parent_e2')`를 단 한 번 연다. 예산은 누적 process-wall seconds이며 금액이 아니다. 현재 ledger와 campaign hard wall을 central API가 적용한다.
5. lease 안에서 deadline·source22·selection·storage를 재확인하고 실제 selected artifact bytes를 opaque SHA로 검증한다. 이 artifact 검증은 미래 `--execute` 경로에서만 수행한다.
6. `registry_extension.require_pre_selection` 다음 `register`로 7 rows/dataset을 모든 신규 fit 전에 등록한다. 그 뒤에만 postfit/data/combination/audit를 import하고 실제 task를 로드한다.
7. 실제 task의 data SHA, L/H/C, A60을 검증한 후 `data.fit_statistics(task, A60)`과 `postfit.ParentPool(task, fold='primary', deadline=lease.deadline-5)`를 사용한다.
8. 부모별 `pool.predict(actual_id, 'M_cal', True)`와 `pool.predict(actual_id, 'V_select', False)`를 호출한다. 자료 내 G/B0/B2의 M/V는 각각 한 번만 요청한다. 명시한 actual ID/artifact/family/source6/A60/scaler/cohort, M/V의 동일 selected model identity를 검증한다. A+M G는 calibration parent로 허용하지 않는다.
9. route별로 `audit_campaign.prepare_combination_reference(new_id, task, b_v, g_v, mean, std, C, R, spec=spec)`를 fit 전에 호출해 독립 V truth/cohort를 고정한다.
10. `combination.fit_combination(spec, task, b_m, b_v, g_m, g_v, mean, std, C, R/'combinations', lease.deadline-5)`를 호출한다. COMPLETE_VALID에만 `audit_campaign.wrap_combination_output(receipt, refs, C, R)`를 호출해 실제 표준 V manifest를 만든다. BUDGET_LIMIT는 완료 출력으로 감싸지 않는다.
11. 신규 alias별 실제 manifest SHA를 기록하고 mutable registry 상태만 갱신한다. root SCORES, T 후보 선택·잠금·평가는 생성하지 않는다.
12. parent pool과 lease를 닫은 뒤 saved lease_id로 실제 `gpu_receipts/<lease_id>.json` 경로·SHA를 연결한다. 종료 후 false인 `lease._entered`를 링크 조건으로 사용하지 않는다. 종료 source pin도 확인한다.

각 parent predict 직후, prepare 전후, fit 또는 완료 receipt 재사용 전후, wrap 전후에 lease/deadline·storage·source·selection guard를 실행한다. 마지막 parent pool close 뒤에도 완료 판정 전에 guard를 실행한다. guard 자체의 source hash·storage stat 동안 deadline이 지날 수 있으므로 guard 끝에서도 lease와 5초 headroom을 다시 확인한다. 기존 combination alpha export 내부는 수정하지 않았고, bridge가 반환 직후 제한 위반을 포착한다.

## 재사용·실패·공개 영수증

정확한 기존 COMPLETE_VALID receipt와 동일 private spec만 `validate_completed_receipt`로 검증해 재사용한다. 기존 partial public/private combination 디렉터리를 덮어쓰지 않는다. pre-target seal과 표준 alias도 기존 audit API의 identity·SHA 검증을 통과해야 한다.

일반 fit 실패는 partial 파일을 보존하고 독립 route를 계속한다. fit 호출에 진입한 뒤 예외가 나면 이미 업데이트가 있었을 가능성을 배제하지 않는다. `fit_call_attempted_now=true`, `executed_now=true`, `training_executed_now=null`, `EXECUTION_UNKNOWN_PARTIAL_PRESERVED`로 불확실성을 기록한다. 반환된 receipt가 있을 때는 그 실제 updates/training_status를 기록한다. fit 이전 실패를 기존 학습 상태의 초기화 근거로 삼지 않는다.

V timeout, central ResourceBusy/BudgetExceeded, 저장 공간 제한은 DEFERRED_RESOURCE이며 미진입 route도 별도로 기록한다. import 실패, 종료 source 검증 실패도 public batch receipt를 남긴다. 일부 자료가 source/metadata 때문에 deferred이면 전체 batch를 자료 전체 완료로 표시하지 않는다.

수치 완료와 자원 상태는 별도 기록이다. fit이 실제 receipt를 반환하면 `numeric_status`, 실제 updates/training status, fit receipt SHA와 완료 fit count를 post-fit guard보다 먼저 기록한다. wrap이 완료되면 실제 manifest SHA와 출력 count를 post-wrap guard보다 먼저 기록한다. 이후 자원 제한을 발견하더라도 이 수치·출력을 미실행으로 바꾸거나 원본 receipt를 수정하지 않는다. 표준 출력까지 생성된 row의 독립 검산 대기 상태도 유지한다. `standard_outputs_complete`와 batch의 `numeric_completion`은 실제 완료 범위를, 별도의 `resource_status`/`resource_events`는 제한 위반 범위를 나타낸다.

종료 source 검사 뒤에도 실제 closed lease receipt를 읽어 lease ID, deadline, CLOSED/FAILED 상태와 유한한 charge/overrun 숫자를 확인한다. 공개 batch에 `charged_process_seconds`, `deadline_overrun_seconds`, `lease_finished_unix`를 남긴다. 선언된 overrun과 `finished_unix-deadline` 중 양의 최댓값이 있으면 `resource_status=LIMIT_VIOLATION`이다. 기존 COMPLETE batch는 `RESOURCE_LIMIT_VIOLATION`으로 바뀌지만 완료된 fit·출력 count는 유지된다. 이미 DEFERRED_RESOURCE나 SOURCE_CHANGE인 주 상태는 그대로 두고도 LIMIT_VIOLATION을 별도 표시한다. 닫힘 영수증이 없거나 identity/숫자를 검증할 수 없으면 `UNVERIFIED_CLOSED_LEASE`이며 완료 주장은 `RESOURCE_ACCOUNTING_UNVERIFIED`로 제한한다.

공개 batch 경로는 `execution_batches/extended_parent_e2_<stamp>_<uuid>.json`이다. relative path·SHA, 선택 부모/고정 source, 실행·재사용·실패·deferred와 실제 count를 담는다. private exception message/traceback은 C의 `extended_parent_e2_failures/`에만 저장하고 공개 receipt에는 상대 경로·SHA·오류 type만 둔다. weights/raw arrays는 private 위치에 그대로 남는다. public receipt가 private 파일을 링크한다고 그 private 파일을 공개 payload에 포함하지 않는다.
