# K 전환 비용 실행 준비 — 실제 비용은 아직 미측정

[확인] 이 폴더는 metadata·파일 SHA 사전 검증과 CPU 합성 시험의 결과다. **실제 GPU child 0개, 실제 전환 trial 0개**다. 비용 완료나 캠페인 완료를 뜻하지 않는다. ROOT가 기존 학습·CPU worker를 마친 뒤 기존 audit owner를 넘겨 실행할 수 있도록 준비했다. [V3 독립 검토](../../gzip_extra_aux_20261016_v1/files/item_0259.json.gz), [기존 측정 protocol](../../../MULTIK_TRANSITION_PROTOCOL_KO.md)을 따른다.

## 고정된 전체 큐

[INPUT_PINS.json](../../gzip_aux95_1792094747124151400/files/item_0078.json.gz)에 source20·source18·실행 의존 파일, 초기 24개 route의 실제 V manifest/reference·선택 artifact·foundation snapshot byte SHA를 봉인했다. 배열/weights를 역직렬화하지 않았다. V 예측의 data/scaler/cohort와 원 target/mask/origin/channel fingerprint가 같은지 metadata로 검사했다. 학습 epoch를 새 대표 e3로 바꾸지 않는다.

[Beijing plan](../../gzip_extra_aux_20261016_v1/files/item_0500.json.gz)은 K=3/6/11, [Electricity plan](../../gzip_extra_aux_20261016_v1/files/item_0501.json.gz)은 K=81/161/321이다. 각 자료에서 아래 10개씩 **총 20개** fresh process scope를 순차 실행한다. exact ID는 plan과 INPUT_PINS에 있다.

```text
자료         batch  전략(각각 별도 child)
Beijing      1      shared / posthoc / nested / independent_hot / independent_cold
Beijing      8      shared / posthoc / nested / independent_hot / independent_cold
Electricity  1      shared / posthoc / nested / independent_hot / independent_cold
Electricity  8      shared / posthoc / nested / independent_hot / independent_cold
```

각 scope는 6개 directed transition × warmup10/timed20 = 180개 요청이다. 전체 요청은 warmup1200/timed2400이나 **이 숫자는 실행 계획**이다. B1/B8은 같은 V의 앞 1/8개 서로 다른 과거 창을 사용한다. 실제 canonical parity/F stream 검사가 먼저이며, T나 저장 예측을 읽는 시간을 추론 비용으로 재지 않는다.

## 코드와 metadata-only CLI

실행 코드와 CPU tests는 비공개 cache 아래에만 있다. 개인 절대경로를 이 문서에 넣지 않는다.

```text
<cache_root>/final_execution/multik_execution_ready_1792086454973961300/multik_launcher.py
<cache_root>/final_execution/multik_execution_ready_1792086454973961300/test_launcher.py
<cache_root>/final_execution/multik_execution_ready_1792086454973961300/prepare_metadata.py
```

아래 CLI는 owner를 만들지 않으며 **metadata/SHA 확인만** 한다. ROOT가 이미 사용하는 정확한 세 root 변수를 전달한다.

```powershell
& <original_python> -X utf8 -u -B <cache_root>/final_execution/multik_execution_ready_1792086454973961300/multik_launcher.py --asset-root <asset_root> --cache-root <cache_root> --public-root <public_root>
```

코드·tests·preparation의 exact SHA와 실제 시험 로그는 [LAUNCHER_SOURCE_FREEZE.json](../../gzip_extra_aux_20261016_v1/files/item_0499.json.gz), [CPU_TEST_REPORT.json](../../gzip_extra_aux_20261016_v1/files/item_0498.json.gz)에 있다. 기존 379개 suite에 이 새 private launcher가 포함됐다고 주장하지 않는다.

## ROOT의 기존 owner를 넘기는 API

새 owner·nested lease·새 예산·자원 장부를 생성하지 않는다. `lease`는 같은 PID에서 이미 열린 ROOT audit owner여야 한다. 전역 GPU ceiling43200초 중 audit 누적39600초까지만 사용하도록 deadline을 검사하여 final3600초를 보존한다. 더 작은 유한 subset deadline도 가능하다. CPU1/2나 다른 GPU로 우회하지 않고 child에 owner의 `child_environment()`와 CUDA_VISIBLE_DEVICES=0, threads2를 전달한다. token 값을 영수증에 쓰지 않는다.

```python
# 기존 ROOT API 세션에서만 실행. 아래 코드는 owner를 생성하지 않는다.
import importlib.util
from pathlib import Path
launcher_path = Path(cache_root) / "final_execution/multik_execution_ready_1792086454973961300/multik_launcher.py"
# 먼저 공개 LAUNCHER_SOURCE_FREEZE.json의 SHA와 launcher bytes를 대조한다.
spec = importlib.util.spec_from_file_location("multik_cost_launcher", launcher_path)
module = importlib.util.module_from_spec(spec)
spec.loader.exec_module(module)
receipt = module.run_with_owner(existing_audit_lease, asset_root, cache_root, public_root,
                                max_seconds=None)
```

`max_seconds`를 줄 경우 **다음 child를 시작할 admission window**만 제한한다. metadata 검사 반환 후에도 재검사한다. 실행 중 child는 timeout/kill로 중단하지 않으므로 마지막 child가 이 local window를 넘을 수 있다. 실제 child의 global deadline은 기존 owner의 deadline 그대로이며 helper가 각 반환 경계에서 상한을 판정한다. 짧은 global 범위가 필요하면 ROOT가 기존 owner 자체를 그 deadline으로 제한해야 한다.

## 산출물·중단·정확한 재개

새 실행마다 공개 `costs/multik_transition_<ns>/`와 비공개 `final_execution/multik_runs_<ns>/`를 생성한다. 공개 FULL_QUEUE_PLAN, 각 SCOPE_ADMISSION/SCOPE_RESULT, child의 BATCH_RECEIPT·RESULT·actual_trials JSON·TRIALS.csv를 보존한다. 로그는 private에만 둔다. launcher의 최종 파일은 `BATCH_LAUNCHER_RECEIPT.json`이다. 완료된 rows를 후처리 오류로 지우지 않는다.

child exit0만으로 완료하지 않는다. 180개 durable JSON/CSV 및 12개 transition ledger, numeric/resource/post-validation 상태, canonical selected-model/data/scaler/foundation/manifest binding을 확인한다. 마지막 trial의 numeric 완료180과 자원 내 완료179는 다르며 resource 초과면 다음 child를 시작하지 않고 나머지 전체 큐를 미시작으로 기록한다. 개별 canonical/전략 오류는 다른 독립 조건을 계속한다. wait가 끊기면 child 상태 미확인으로 기록하고 kill하지 않으므로 ROOT가 OS 상태를 확인하기 전 새 GPU 작업을 시작하면 안 된다.

재개는 **같은 pins와 이전 완료 산출물의 모든 SHA가 일치하는 scope만** 재사용한다. partial/실패 scope는 새 폴더에서 180개 요청을 처음부터 실행한다. 이전 partial trial을 신규 trial과 합쳐 하나의 최소 protocol을 완료했다고 세지 않는다.

```python
receipt = module.run_with_owner(existing_audit_lease, asset_root, cache_root, public_root,
    max_seconds=None,
    resume_from=Path(public_root) / "costs/multik_transition_<previous_ns>/BATCH_LAUNCHER_RECEIPT.json")
```

최종 ledger는 미실행 조건도 20개 전체를 유지한다. `newly_executed_numeric_trials`와 `reused_verified_numeric_trials`를 분리한다. 미완료 child나 scope가 남으면 실제 cost raw statistics 완료가 아니다. guard가 포함된 instrumented transition 시간, warmed predict, model-reload scope를 섞어 평균내지 않는다. 보호 TEST·T·모델 학습·registry/Git 변경은 이 launcher 범위에 없다.
