# aux95 바이트 보존 gzip 실행 준비

현재 상태는 **PLAN_ONLY_NO_COMPRESSION**이다. 고정 CSV 목록과 기존 복원 helper를 확인했으며 실제 95개 압축·전수 복원은 아직 하지 않았다. 정밀 비용 측정 종료가 확인된 뒤 ROOT가 별도 실행한다. 이 준비물은 기존 후보 4,600파일·원본·기존 v3 gzip 폴더를 변경하지 않는다.

입력은 [AUX_GZIP_CANDIDATES.csv](../../gzip_extra_aux_20261016_v1/files/item_0598.csv.gz) 하나다. SHA는 `a5ce96b2cf13f00f38598f67a3683bc496a6cf32f11e3eae31c87441db9cfd9d`, 목록은 정확히 95개·20,071,038B, 최대 원파일은 920,074B다. 임의 파일 추가·삭제나 조건 축소는 허용하지 않는다. 이름에 MANIFEST·REFERENCE·BINDING·PLAN·QUEUE가 있는 핵심 탐색 파일은 이 목록에 포함하지 않았다.

기존 [restore_originals.py](../../gzip_1792092403733272600_v3/restore_originals.py)를 바이트 그대로 복사하며 SHA `e88b5cf8d37a667ba60b1666982924be7e1aa796d86101ab64a2a7834b59ab5b`로 확인한다. 새 manifest는 기존 `exact_auxiliary_gzip_v1` 형식을 그대로 사용한다.

실행 helper는 private cache 상대경로 `publication_aux95_ready_1792094747124151400/pack_aux95.py`다. 고정 source SHA와 실제 metadata 테스트 결과는 [READINESS.json](../../gzip_extra_aux_20261016_v1/files/item_0597.json.gz)에 기록한다. 원자료·모델·배열을 읽거나 학습·추론·GPU owner·새 자원 예약을 만들지 않는다.

## 명령

`$Python`은 기존 프로젝트 Python, `$Repo`는 저장소 루트, `$Cache`는 기존 private campaign cache다. 실제 개인 절대경로를 공개 문서에 적지 않는다.

```powershell
$Campaign = Join-Path $Repo 'research/informs_broad_validation_20261015_v1'
$Helper = Join-Path $Cache 'publication_aux95_ready_1792094747124151400/pack_aux95.py'
$Output = Join-Path $Campaign 'publication_derivatives/gzip_aux95_1792094747124151400'
# 메타데이터 확인만: 압축 및 출력 폴더 생성 없음
& $Python -X utf8 -u -B $Helper --repo-root $Repo --output $Output
# 정밀 비용 측정 종료 후 ROOT가 실행할 명령
& $Python -X utf8 -u -B $Helper --repo-root $Repo --output $Output --execute
```

목록·helper SHA와 95개 파일의 존재·크기를 먼저 검사한다. `--execute`가 있어야 모든 원본 바이트를 읽어 각각 고정 SHA와 비교한다. 하나라도 다르면 출력 폴더를 만들지 않는다. 모든 입력이 일치한 뒤에만 고유한 새 폴더와 95 gzip을 만든다. 원문은 그대로 보존한다.

gzip은 원본 바이트 전체를 level9·mtime0·빈 filename 헤더로 저장한다. JSON이나 CSV를 파싱해 다시 쓰거나 행·열·숫자 정밀도를 줄이지 않는다. manifest의 각 항목은 원 상대경로·원 크기/SHA·gzip 상대경로·gzip 크기/SHA를 담는다. 고정 입력 CSV와 복원 helper도 그대로 보존한다.

별도 임시 저장소 경로에서 기존 helper로 95개를 실제 복원한다. 복원된 모든 파일을 원 바이트·SHA와 직접 비교하고, 같은 경로에서 재실행하여 `restored=0, already_matching=95`를 확인한다. 마지막으로 원본 95개·고정 목록·기존 helper가 바이트 그대로인지 다시 확인한다. 이 단계들이 모두 통과해야 `AUX_RESULT.json`에 `PASS_ALL95_BYTE_EXACT`를 쓴다. 실패한 새 폴더는 남겨 두며 원문을 덮거나 삭제하지 않는다.

## clone 복원

실제 생성된 새 gzip 폴더에서 다음을 실행한다. 목적지는 campaign 폴더가 아니라 **저장소 루트**다. manifest의 원 상대경로가 `research/...`부터 시작하기 때문이다.

```powershell
& $Python -X utf8 -u -B (Join-Path $Output 'restore_originals.py') --destination $Repo
```

기존 helper는 모든 gzip·원본 SHA와 경로를 먼저 검사한 뒤 쓴다. 다른 내용의 기존 파일은 덮지 않고 실패한다. 이미 정확한 파일은 건너뛴다. 소스 API가 원 JSON/CSV 경로를 요구하면 이 복원부터 실행한다.

현재 단계는 numeric pack 준비에 한정한다. 최종 candidate 전체 입력이 봉인된 뒤 원 Markdown을 보존하는 새 safe projection을 만들고 직접·전이 링크를 정리해야 한다. 그 전에 이 gzip만으로 원문 후보를 제외하거나 링크가 완성됐다고 주장하지 않는다. 실제 크기 절감은 gzip뿐 아니라 manifest·복원 helper·원 목록·검증 증거·후속 Markdown 파생물까지 합쳐 계산한다.

## 검증 범위

준비 단계 테스트 4개는 고정 목록의 수·합계·최대 크기, 목록 변조 거절, 소유 출력 경계, plan 모드 압축/출력 금지를 확인한다. 실제 95개 바이트 SHA나 gzip 복원을 검사한 결과가 아니다. T·NPZ·모델·원 시계열 읽기, registry/기존 후보 수정, Git stage/commit/push는 수행하지 않았다.
