# 비용 계획 V2 — 설명 metadata 교정

실행에는 [PLAN_V2.json](../../gzip_1792092403733272600_v3/files/item_0002.json.gz)과 private `cost_dispatcher_v2.py`를 사용한다. [V1 PLAN](../../gzip_1792092403733272600_v3/files/item_0001.json.gz)과 [원 runbook](doc_0105.md), old READY/test31 증거는 이력으로 보존했다. V1의 `smallK4_preserved`는 설명 필드가 잘못됐다.

실제 smallK4는 **Electricity K41의 B0/B2와 PeMS K22의 B0/B2**다. [원 실제 실행 영수증](../../gzip_extra_aux_20261016_v1/files/item_0763.json.gz)과 대조했다. Beijing K2를 이번 small4의 결과로 부르지 않는다.

[재귀 diff 증거](../../gzip_extra_aux_20261016_v1/files/item_0385.json.gz)에서 달라진 최상위 key는 설명용 `smallK4_preserved` 하나다. 원 groups·argv·1458 bindings·source·과학 조건·예산은 동일하다. 실행 argv에는 원래부터 올바른 Electricity41/PeMS22 네 조건이 모두 있었으며 이번 변경으로 실행 조건을 추가·삭제하지 않았다.

private 코드 경로는 다음과 같다. 원 helper와 비교해 PLAN 상대경로와 PLAN_SHA 상수 두 곳만 바뀌었고, 그 두 문자열을 되돌리면 byte가 원 helper와 정확히 같다. 명령 실행 로직은 바꾸지 않았다.

```text
<cache_root>/final_execution/final_cost_queue_ready_1792088347039621300/cost_dispatcher_v2.py
```

metadata-only 및 실제 ROOT-trigger CLI는 [원 runbook](doc_0105.md)의 `<private_dispatcher.py>` 자리에 위 V2를 넣는다. `--execute` 없이 실행하면 metadata 확인만 하며 새 owner를 만들지 않는다. ROOT trigger 이전 실제 비용 0을 유지한다. 기존39600 누적 ceiling/final3600, group 경계, retry1 HOLD, error·resource handling은 그대로다.

[V2 source freeze](../../gzip_extra_aux_20261016_v1/files/item_0387.json.gz), [실제 CPU 회귀 및 source-small4 대조](../../gzip_extra_aux_20261016_v1/files/item_0381.json.gz), [실제 metadata CLI](../../../diagnostics/final_cost_queue_ready_1792088347039621300/METADATA_CLI_RESULT_V2.json)에 현재 SHA와 범위가 있다. V1의 설명 오류가 전체 원 과학 결과나 실행 argv 오류였다고 확대하지 않는다.
