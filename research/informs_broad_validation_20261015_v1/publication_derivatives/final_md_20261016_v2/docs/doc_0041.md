# Electricity V 초기화·현재값 anchor 산술 검토

실제 기존 파일 58개를 SHA로 먼저 봉인한 읽기 전용 CPU 진단이다. [REVIEW.json](../../gzip_extra_aux_20261016_v1/files/item_0467.json.gz)에 상대 provenance·원수치·식·한계를 기록했다. 실제 F 추론·학습·새 T 평가는 0회이며 저장 배열은 게시하지 않았다.

B0/B2/B4의 선택 모델은 CP0이고 해당 temporal residual output은 0이며 V 예측도 서로 byte-identical하다. DIRECT_G는 예외로 .25 epoch/219 refit update를 선택했다. K81/161에서 B0와 FixedPCA의 차이는 현재 시점의 버린 부분공간을 유지하는 anchor로 거의 전부 설명된다. K321 B0는 identity 초기화이지만 FixedPCA는 full-rank 회전이어서, K 증가 곡선의 마지막 점은 같은 초기화 계열이라고 해석하면 안 된다. full PCA의 정보 보존과 frozen 단변량 F의 좌표 호환성은 별개다.

재현 산술은 기존 private cache NPZ와 checkpoint의 mean/std/E/center/D0 및 같은 origin의 과거 x_last만 사용한다. 모든 곱은 마지막 축의 행벡터 규약이다.

```python
z_last = (x_last - center) @ E
fixed = saved_fixed_predictions
anchor = x_last - center - z_last @ D0
max_difference = abs(saved_b0_predictions - (fixed + anchor[:, None, :])).max()
# D0=pinv(E)이며 E.T와 FP32에서 미세하게 다르므로 latent 역복원으로 교차 확인
latent_from_decoded = (fixed - center) @ np.linalg.pinv(E.T)
reconstructed_b0 = x_last[:, None, :] + (latent_from_decoded - z_last[:, None, :]) @ D0
# full-rank 정보 보존 산술: F를 부르지 않음
rank = np.linalg.matrix_rank(E.astype(np.float64))
roundtrip = ((x_last-center) @ E) @ E.T + center
```

full-C에서는 square orthogonal E의 anchor가 상쇄되지만 F(xE)E.T=F(x)는 일반적으로 보장되지 않는다. 다만 이번 비교는 full-PCA/identity와 decoder 클래스가 다른 저장 결과의 진단이며, 좌표 회전만을 유일 원인으로 확정하지 않는다. 기존 E4의 동일 ForecastAdapter full-PCA 초기화와 max-only/ordered 비교, 기존 계획의 학습률·예산 비교가 다음의 더 공정한 확인이다. 단일 V 선택 결과를 미래 일반화 주장으로 바꾸지 않는다.

## dtype 검증 보정

이 snapshot은 앞 로컬 검토의 FP64 표기 한 개를 바로잡은 게시용 결과다. 앞 snapshot은 보존한다. `anchor_residual_FP32_subtract_then_FP64_inverse_max_abs`는 FP32에서 차를 먼저 구한 혼합 precision 값이다. `anchor_residual_all_operations_FP64_inverse_max_abs`는 두 피연산자를 모두 FP64로 바꾼 뒤 뺀 값이다. 나머지 58개 입력 SHA·점수·실제 예측·산술 결과는 바뀌지 않았다.

```python
x64 = x_last.astype(np.float64)
c64 = center.astype(np.float64)
E64 = E.astype(np.float64)
z64 = (x64 - c64) @ E64
anchor_full64 = (x64 - c64) - z64 @ np.linalg.inv(E64)
```
