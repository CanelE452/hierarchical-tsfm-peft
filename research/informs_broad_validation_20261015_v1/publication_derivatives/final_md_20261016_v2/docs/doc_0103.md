## 실제 범위와 미실행

시작에 있던 334개 V manifest만 private metadata projection에 고정했다. 원 public root 아래에 복제 prediction manifest를 만들지 않았다. API 원출력은 private 원본과 동일 bytes로 새 public snapshot에 복사했으며 기존 결과는 수정하지 않았다. 기존 65/71은 이번 비교 집합을 위해 재계산했고 실제 산출 수에 중복 신규로 세지 않았다.

원단위 primary의 전체 채널·원점은 다음과 같다. 동일 cohort를 여러 run이 공유하므로 이를 합쳐 독립 표본수라고 해석하지 않는다.

```text
자료          V run수   V 원점수/각 run   H    전체 C
Beijing       83        43               48   11
Jena          67        43               48   21
Electricity   78        50               48   321
PeMS08        70        148              12   170
Robin         34        3                48   17
```

secondary Beijing/Jena 두 V의 원단위 환산은 별도 frozen A60 통계가 안전한 NPZ 형태로 없어 **명시 미실행**이다. primary 통계를 재사용하거나 모델 .pt를 열어 해결하지 않았다. 시간블록 API는 이 두 입력도 수치·cohort 검산했지만 secondary에는 각 DirectG 하나만 있어 대응 비교쌍은 없다. secondary의 원점수는 Beijing 35, Jena 34이며, 127개 비교쌍은 primary 범위다.

고정 목록 뒤 추가된 `primary_beijing_E1_B0_k3_s92601__e1`, `primary_beijing_E1_B2_k3_s92601__e1` 두 V는 이번에 분석하지 않았다. 정확한 경로·SHA는 종료 검산의 `later_V_not_analyzed`에 있다. 이후 추가 V까지 완료됐다는 의미가 아니다.

## 입력·해석·자원 한계

primary 다섯 자료의 기존 COMPLETE_VALID Ridge NPZ에서 **mean/std/data_sha/canonical_A60_end 네 멤버씩 총 20회**만 읽었다. receipt의 exact A60·data/scaler SHA, 전체 channel 수와 예측 channel order를 검증했다. coefficients·다른 모델 멤버·raw task·모델을 로드하지 않았다. timeblock은 기존 API가 필요한 period/H/columns/data SHA만 frozen DATA_CONTRACT와 기존 load_task의 period 규칙에서 공급했다. 알고리즘·block 규칙·수치를 바꾸는 source 수정은 없다.

물리단위 오차는 heterogeneous channel의 단위를 섞어 새로운 물리량으로 해석하지 않는다. PeMS는 5분 flow counts이며 시간당 변환을 하지 않았다. legacy FP32 역정규화 계보와 Robin의 원점 3개 한계는 남는다. 시간블록은 IID 표본이 아니며 CI·bootstrap·유의성 검정을 하지 않았다. 마지막 짧은 블록도 그대로 보존했다.

CUDA=-1, OMP/MKL/OPENBLAS=2, 모델 import·학습·추론·F 호출·T/보호 TEST·raw task 로드 모두 0이었다. caller wall은 272.610초이며 capture부터 독립 종료 검산까지 537.178초로 15분 제한 안이었다. 0.2초 간격 sampled RSS peak는 231,084,032B(약 220.38MiB), resource stop은 없다. 종료 C+R+pending 1GiB는 16,941,504,806B로 30GiB 제한 안이었다.

독립 종료 검산 시 이 작업의 private·public 새 파일 합계는 231,108,730B로 1GiB 미만이었다. driver의 `peak_added_bytes`는 private workspace와 이 진단 폴더만 세므로 두 public API snapshot을 합친 독립 검산 수치도 함께 제시했다. 파일은 추가·증가만 했으며, private+진단 sampled peak의 두 배 449,988,930B를 public 원출력 복사를 포함한 보수적 상한으로 확인했다.

두 새 public API snapshot은 합계 5,820,216B다. 새 공개 파일은 모두 20MiB 미만이므로 추가 gzip 파생은 필요하지 않았다. 원 CSV·API manifest를 반올림·삭제·편집하지 않았다. 전체 최종 payload 검사·게시·Git 작업은 수행하지 않았다.
