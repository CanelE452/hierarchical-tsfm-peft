# 최소 학습의 문언과 대표 실험 우선순위

[확인] [공개 MASTER](../../plan/MASTER_PLAN_PUBLIC.md)의 276행은 모든 핵심 가족의 0.25→1→3 epoch를 최소 커버리지로 정한다. 302행은 주 자료군별 Raw/G/LoRA/PCA/B0/B2, B0/B2의 quarter/half/C와 기존 작은 K, B4의 quarter/C를 필수 최소 실행으로 지정한다. 386행은 Beijing/PeMS의 지연 quarter/half/C, 393행은 Beijing/Electricity의 다중K 파일럿을 별도로 요구한다. 225행의 추가1/8·3/4 K는 우선 최소K 다음의 전체 grid다.

대표 한 자료에서 가족별3epoch를 수행하면 나머지 자료와K의 최소 학습을 대체할 수 있다는 예외는 문서에 없다. 반대로 276행 자체에 '4자료 모든 최소K 각각3epoch'라는 문장이 직접 쓰인 것은 아니다. 따라서 **공통 학습계약과 자료/K 최소 실행표를 함께 적용하는 보수적 판정**과 명시 문구를 구분한다. 전체 최소 학습 완료를 주장하려면 어떤 자료·K·가족이 실제1/3epoch를 채웠는지 제시하거나, 남은 셀을 예산 미완료로 명시해야 한다.

[판단] 남은 GPU가 모든 셀을3epoch까지 보강하기에 부족하다면, 아직3epoch 증거가 전혀 없는 B4·LoRA·지연·공유K와 직접 예측기의 대표 자료 보강은 이미 quarter/half/C에서 구조가 실행된 B0/B2의 추가1/8·3/4 grid보다 '방법 실패인지 짧은 학습 문제인지'를 구분하는 데 직접적일 수 있다. 이는 대표 자료 보강을 우선하자는 자원 배분 판단이며, 기존 grid·다른 자료·seed·subset 요구를 삭제하는 승인이나 전체 완료 판정이 아니다.

ROOT가 알려준 닫힌GPU 사용24,603초와 당시 활성 PeMS 약700초는 이 감사의 직접 장치 측정값이 아니다. 대략 남은5시간이라는 운영 판단 아래 비용90–150분과 replay/T60분을 먼저 남긴다면 모든3epoch70+28조건을 채운다고 약속할 근거가 없다. 자원 장부와 실제 probe로 다시 확인하고, PARTIAL로 정확한 미해결·재개목록을 게시하는 것이 필요하다. CPU의 새3epoch 직접 예측기 실험도 명시된 새 ID/device 조건에서 실행한 경우에만 별도 증거이며 GPU 대조와 동일한 실행조건으로 단정하지 않는다.

이번 감사는 학습을 새로 실행하지 않았다. 대표자료 보강의 실제 성공/충분수렴/성능개선도 아직 주장하지 않는다.
