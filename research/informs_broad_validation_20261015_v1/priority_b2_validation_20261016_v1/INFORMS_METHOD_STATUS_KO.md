# B2 우선 검증 결과: 무엇을 주장할 수 있는가

**[확인] B2의 계산 경로는 의도와 일치했다. Jena K6에서 B0와 두 full-history no-Bolt 대조보다 예측 오차가 낮았지만, native ridge·G·제한 학습 LoRA보다 나빴다. 직접 head보다 높은 정확도를 얻는 대신 CPU 배포 비용은 크게 증가했다. 따라서 방법론 후보는 설명할 수 있지만 정확도–비용 우위와 Bolt 유지의 일반적 근거는 확보하지 못했다.**

이 보고서는 사용자 우선순위 변경 후의 핵심 판단 보고다. [수식·학습/동결·비교 계약](METHOD_CONTRACT.md), [중단한 작업과 checkpoint·복구 한계](PAUSE_AND_RESUME.md), [원정밀도 결과 CSV](PRIORITY_RESULTS.csv), [봉인된 사전 계획](PREREG_PLAN.json), [독립 R5 검토](INDEPENDENT_R5_REVIEW.json)를 함께 읽는다. 새로운 그림·PPT/PDF·대규모 포장은 만들지 않았다.

## 1. B2 계산 구조가 맞는가

[P0 실제 실행](diagnostics/p0_root_v1/RESULT.json)에서 `[8,512,21] → [8,512,6] → frozen Bolt → [8,48,6] → [8,48,21]`을 확인했다. Bolt에는 실제 48개 stream이 한 번에 입력됐다. 실제 Bolt 입력에서 역전파 hook이 발생했고 P/E/D의 기울기가 유한하고 0이 아니었다. Bolt의 모든 requires_grad는 false, 파라미터 grad는 없었으며 실행 전후 가중치 SHA가 같았다. optimizer update는 0이므로 학습 성공 검사가 아니다.

고정 A60 scaler 아래 origin14675 이후의 materialized V 값과 mask를 바꿔도 과거 입력과 최종 출력은 정확히 같았다. 이번 로더는 T의 수치를 파싱하지 않았다. 다만 legacy 원자료 정규화의 계보는 남아 있으며, 한 원점 교란 검사를 역사 전체 무누출·과거 창 내부 strictly causal 표현의 증명으로 확대하지 않는다. Transparent Raw는 같은 F·row128에서 수동 경로와 출력 maxabs0이었다. 기존 Raw 비용의 row-variant parity 실패를 해결한 것은 아니다.

현재값 anchor는 원 C 정보를 별도 보존한다. 따라서 원채널 정보가 모두 K를 통과한다거나 전체 시스템의 통신량이 정확히 C/K로 감소한다고 주장하지 않는다.

## 2. B0보다 추가 가치가 있는가

같은 Jena primary, L512/H48/C21/K6, seed92601, V43 origins·43,344 관측 정답, 같은 A60 scaler/target/mask/origin/channel을 비교했다. 주지표는 사전에 정한 정규화 채널 균등 MSE이며 MAE를 함께 보고한다. 이미 여러 번 개발에 사용한 V이고 새 보호 T를 사용하지 않았다.

## 3. 직접 head·G·Ridge·LoRA 대비 Bolt 유지 근거

R5a는 정확한 R4 최종 P/E/D와 scaler를 고정하고 전체 Z[512,6]를 채널 공유 Linear(512,48)에 입력했다. direct 쪽에 짧은 과거나 몇 개 요약값만 주지 않았다. A60에서 head 24,624파라미터만 사전 고정3epoch, 2,254 update/36,060 origin 노출로 학습했다. A_stop은 고정 표현이 이미 본 자료이므로 미노출 선택 구간으로 사용하지 않았고 M_cal 정답도 추가 사용하지 않았다.

R5b는 같은 P/E/D·K·anchor 구조를 fresh 초기화해 no-Bolt head와 함께 미래 MSE로 학습했다. A50 검색3epoch(1,863 update/29,769 노출), A_stop 선택1epoch, fresh A60 refit752 update/12,020 노출이다. 최종 P/E/D는 R4와 다른 가중치다. R4도 동일한 검색 범위에서1epoch를 선택했다. R5a/b를 하나의 ‘동일 표현’ 비교로 합치지 않는다.

B2는 R5a 대비 MSE 7.374%, 별도 적합 R5b 대비 5.103% 낮았다. 이는 이번 두 선형 직접 대조에 대한 조건부 근거다. 모든 direct 예측기보다 우월하거나 Bolt가 필수라는 증거는 아니다. Ridge/G/LoRA는 여전히 B2보다 낮은 MSE·MAE를 보였다. LoRA는 .25epoch 제한 screen으로 충분한 학습이나 동등 학습량 비교라고 부르지 않는다.

현재 후보는 이미 원채널 미래 MSE로 학습됐다. 실패를 재구성 학습의 실패라고 설명하지 않는다. P0 통과·3epoch 검색 완료·선택1epoch는 충분 수렴의 증거도 아니다.

## 4. 정확도와 실제 전체 비용의 이득·한계

아래는 CPU2 threads, 실제 physical 입력부터 fill·정규화·P/E·예측기·D·FP64 역변환을 포함한 **초/배치** median이다. B1/B8, warm10·timed20·별도 intrusive stage20, row128·checkpoint-input off의 호환 프로토콜을 사용했다. 기존 유효 기록을 재사용했고 새 비용은 학습·추론과 동시에 실행하지 않았다. 캐시 Z나 저장 forecast를 비용 입력으로 사용하지 않았다.

B2의 기록 median은 R5a/b 대비 B1 약119–123배, B8 약431–436배였다. 같은 시점의 paired benchmark나 범용 가속비가 아니라 호환 프로토콜의 기록 비율이다. 배포 resident weights는 B2 약182.166MiB, no-Bolt 약0.230263MiB다. no-Bolt 실제 CPU RSS도 약490–496MiB로 0이 아니다. 모델 로딩·cold start·서버 전체 전력은 이 timed 범위 밖이다.

R5a fit+V process wall14.487초, CPU25.516초; R5b24.017초, CPU44.875초다. 순수 최적화 시간은 각각11.560초 및 검색15.221초+refit6.128초다. R5a는 기존 B2 표현을 얻은 학습 비용에 추가되는 비용이다. B2 기존 검색만5,017.993초였으며, 이러한 차이를 동일 연산량 비교로 숨기지 않는다. 배포 비용에 학습 비용을 합친 숫자를 추론 시간으로 쓰지 않았다.

Raw의 기존 비용 실패는 숫자나0으로 대체하지 않고 Raw 대비 가속비도 계산하지 않는다. 정확도와 현재 CPU 비용을 함께 보면 ridge/G 대비 실용적 우위는 없다.

## 5. 검산과 불확실성

두 새 모델의 전체 V43 저장 예측을 별도 프로세스에서 FP64로 재채점하고 각2,709 충분통계 행도 재집계했다. 선택6 origins를 새 checkpoint에서4+2 batch로 실제 CPU 재추론해 고정 공차1e-5/1e-4를 통과했다. 이는 전체 V 재추론이나 독립 재학습 검증과 다르다. 새 no-Bolt 비용4영수증·200trial도 독립 재집계했으며 원 source39·immutable9·PLAN SHA가 유지됐다. fit 영수증의 pending 표시는 생성 당시 snapshot이고 후속 PASS가 현재 검증 상태다.

단일 seed·한 시간 분할·반복 개발 V, 학습량과 모델 용량 차이, legacy 전처리 계보, 수렴 미확정이 남는다. 통계적 독립 일반화·인과관계·논문 신규성은 입증되지 않았다. 시험 T를 다시 보며 K·epoch·주지표를 고르지 않았다.

## 6. 무엇을 재개하고 무엇을 보류하는가

이 보고 작성 시 기존 전체 큐는 재개하지 않았다. 기존 Beijing shared/max-K는 마지막 정상 search3/refit0 checkpoint만 보존하며, fresh-only CLI로 자동 재시작하지 않는다. 다음은 이번 근거에서 필요한 PeMS08 또는 추가 seed의 핵심 경로만 별도 큐로 명시하고 원 예산 안에서 순차 진행한다. [우선순위 큐 snapshot](PRIORITY_QUEUE.json)은 실행 완료와 예정 상태를 구분한다.

전체56·모든 K·G/H 주 방법 전환·새 그래프·대규모 포장·M5 인증 재시도는 보류한다. 중단 작업 전체와 과거 T 잠금 위반 명령은 자동 재개하지 않는다. 전체 MASTER의 미완료 항목은 없어지지 않았으며 이 보고는 연구 전체 완료 선언이 아니다.
