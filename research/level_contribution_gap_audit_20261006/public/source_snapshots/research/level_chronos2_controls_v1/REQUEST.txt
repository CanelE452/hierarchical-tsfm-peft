# LEVEL에 Chronos-2 비교 추가 — CLI 실행 지시문

## 0. 목표와 승인 범위

최상위 목표는 **“동일한 예측 정보와 평가 조건에서, 최신 네이티브 다변량 모델을 그대로 쓰는 대안까지 고려해도 LEVEL의 정확도–추론 메모리–처리량 절충이 남는가?”**를 판단하는 것이다. 사용자는 이 결과로 INFORMS 발표에서 LEVEL의 실용적 기여를 유지할지, 더 좁힐지 결정한다. LEVEL을 이기게 만드는 것이 목표가 아니다.

이번 작업은 `CanelE452/hierarchical-tsfm-peft`의 기존 LEVEL 평가에 **Chronos-2 계열의 zero-shot 비교**를 추가하는 범위다. zero-shot은 이번 대상 자료에 추가 적합·미세조정을 하지 않는다는 뜻이며, 사전학습 데이터와의 비중복을 보장한다는 뜻이 아니다.

아래 범위의 계약 확인 → 최소 구현 → 사전 검사 → 고정 평가 → 같은 회차 비용 측정 → 검산 → 결과 보고까지 진행한다. 계약·접근·예산 문제가 없다면 계획만 작성하고 끝내지 않는다. 반대로 확인되지 않은 핵심 계약을 실행 편의로 추정하여 진행하지 않는다.

추가 신경망 학습, optimizer update, LoRA 적합, PCA 재적합, 새 보정기, 새 데이터, 새 기간, 새 채널, 기존 모델 재선택은 **0회**다. 기존 표의 체크포인트와 방법 정의를 유지한다. Chronos-2에 LEVEL을 붙이는 새 연구도 이번 범위에 포함하지 않는다.

## 1. 최소 비교와 각각의 이유

다음 모델 별칭은 이번 지시문에서 새로 정의한다. 기존 저장소에 이미 존재하는 이름이라고 가정하지 않는다.

| 새 별칭 | 공식 가중치 | 입력 관계 | 역할 |
|---|---|---|---|
| C2_MV | amazon/chronos-2 | 같은 예측 원점의 원채널 전부를 하나의 다변량 과제로 처리 | “그냥 Chronos-2를 쓰면 되지 않나?”에 대한 주 비교 |
| C2_SMALL_MV | autogluon/chronos-2-small | 위와 동일 | 큰 모델만 비교해 LEVEL의 비용을 유리하게 보이는 것을 방지 |
| C2_UNI | C2_MV와 동일한 가중치·정밀도·예측 규칙 | 채널별로 독립 처리 | 같은 모델 안에서 동시 채널 정보 사용의 추가 효과 확인 |
| C2_SMALL_UNI | C2_SMALL_MV와 동일한 가중치·정밀도·예측 규칙 | 채널별로 독립 처리 | 소형 모델에서도 위 비교 확인 |

C2_MV와 C2_SMALL_MV는 본문 비교 대상이다. UNI 두 개는 보조 대조이며 나쁜 결과라고 삭제하지 않는다. 두 크기를 모두 사전에 고정하고, TEST 점수를 보고 하나만 남기지 않는다. UNI 대비 MV의 차이는 같은 체크포인트의 추론 정보 공유 차이이며, 전체 다변량 학습법의 우열이나 사전학습 인과 효과로 확대하지 않는다.

대상은 발표 표의 Robin, Peacock Education, Jena 세 자료다. 기존 참조는 압축만 한 예측 b, 기본 LEVEL, 원채널 Bolt F0, 발표 표와 일치하는 원채널 MSE-LoRA, 직접 NLinear다. 과거 native-quantile LoRA와 MSE-LoRA, 기본 LEVEL과 내부 LoRA를 추가한 A를 혼동하지 않는다.

이번 비교는 이미 노출된 자료에 새 기준선을 추가하는 후속 비교다. 새로운 독립 확인, 미사용 데이터 평가, 사전학습 비중복을 주장하지 않는다. 기존 Peacock 최초 확인의 기록은 변경하지 않는다.

## 3. 데이터·평가 정보 계약

- 기존 TRAIN/VAL/TEST-A/TEST-B 날짜, 모든 평가 원점, 목표 구간, 원채널 순서, 단위, 집계 규칙을 그대로 사용한다. 원점마다 바로 직전 512개 관측으로 다음 48개를 예측한다.
- 모든 원채널의 같은 시점 과거를 제공한다. 미래 채널값, 실제 미래 기상값, 미래 target, 외부 공변량, 알려진 미래값, 추가 달력 특징, 다른 데이터셋의 문맥을 추가하지 않는다. 모든 원채널은 예측할 target이며 미래 관측이 제공된 covariate가 아니다.
- 기존 TRAIN 전용 표준화와 입력 결측 대체를 그대로 사용한다. 관측된 0은 유지한다. 결측 입력은 기존 계약대로 TRAIN 평균, 즉 표준화 후 0으로 대체한다. 이번에만 NaN-native 입력이나 새로운 보간을 적용하지 않는다.
- Chronos-2 자체의 기본 내부 정규화·역변환은 공식 구현대로 유지한다. 모델 출력이 어느 단위인지 검사해 평가 때 이중 역표준화하지 않는다. 주 지표는 기존 TRAIN-표준화 좌표에서 계산한다.
- Chronos-2의 기본 최대 문맥이 더 길어도 이번 주 비교에는 512개만 제공한다. 문맥 8192, 추가 미래 특징, 시점별 온라인 갱신 등은 별도 실험이며 이번에는 하지 않는다.
- 다른 평가 원점의 입력 이력도 현재 원점보다 미래의 관측을 포함할 수 있다. 따라서 서로 다른 원점끼리 정보가 공유되면 누출이다. 뒤쪽 원점이 자기 예측 시점 이전의 이미 관측된 TEST 이력을 쓰는 것은 기존 rolling 평가 계약 안에서 허용하지만, 앞 원점이 그 정보를 보는 것은 금지한다.

## 4. 모델·환경 고정

- 공식 가중치 ID는 `amazon/chronos-2`, `autogluon/chronos-2-small`이다. 실행 전 각각의 실제 revision SHA, config, 모델 파일 hash, 파라미터 수, 파라미터·버퍼 바이트 수를 기록하고 고정한다. 이름의 small이나 문서상의 대략적 파라미터 수를 비용 측정값으로 대신하지 않는다.
- 설치된 `chronos-forecasting`의 버전과 소스를 확인한다. 현재 공식 API와 차이가 있으면 호환되는 공식 경로를 확인하고 선택을 TEST 전에 봉인한다. 모델 두 개의 revision은 점수를 보고 바꾸지 않는다.
- 기존 환경을 무조건 upgrade하지 않는다. 호환성 때문에 새 환경이 필요하면 프로젝트 전용 격리 환경을 사용한다. 기존 Torch/CUDA/precision/스레드 조건을 가능한 한 유지하고 차이를 명시한다.
- 비용 비교는 같은 장치·같은 회차에서 수행한다. 같은 실행 환경으로 맞출 수 없다면 환경 차이를 공개하고, 그 결과를 순수 구조 차이의 비용 효과라고 주장하지 않는다.
- 주 비교는 기존과 같은 FP32, TF32 off, CPU thread 4, 평가 모드, 기울기 비활성화를 사용한다. 원래 백본 출력과 모델 내부 정규화는 수정하지 않는다. 특정 모델에만 양자화·BF16·compile·CPU offload·캐시를 적용해 주 비교와 섞지 않는다.
- Chronos-2는 한 번 고정된 예측만 계산한다. 학습 seed 2개를 붙여 동일 zero-shot 출력을 두 개의 독립 실험으로 세지 않는다. 반복 호출은 재현성 검사이지 학습 반복이 아니다.

## 5. 가장 중요한 구현 계약 — 다변량 그룹과 원점을 분리

현재 공식 Chronos2Pipeline.predict 문서와 소스에서 확인한 의미는 다음과 같다.

- `(B, C, L)`의 3차원 입력은 각 B 항목을 독립 과제로, 그 안의 C개 변수를 다변량으로 처리한다.
- `cross_learning=True`는 서로 다른 과제까지 묶을 수 있다. `cross_learning=False`는 과제 간 공유를 끄는 것이며 과제 내부 다변량 attention을 끄는 것이 아니다.
- API의 `batch_size`는 예측 원점 수가 아니라 모델에 들어가는 계열 행 수를 뜻한다.
- `predict`는 과제마다 `(C, n_quantiles, H)`인 예측을 반환한다.

아래 이름은 구현 의미를 설명하는 새 인터페이스 별칭이며, 기존 파일의 변수 이름을 가정한 것이 아니다. 실제 설치 버전의 문서·소스·출력을 확인한 뒤 구현한다.

### MV 두 비교군

기존 표준 입력을 `[B,512,C]`로 읽고 `[B,C,512]`로 전치한다. **한 예측 원점의 C채널이 한 과제·한 그룹**이다. 서로 다른 원점·자료는 서로 다른 그룹이어야 한다.

공식 API 의미상 설정은 다음과 같다.

    inputs: [B, C, 512]
    prediction_length: 48
    context_length: 512
    cross_learning: False
    batch_size: B * C  # 공변량을 추가하지 않고 한 호출에 B개 원점을 처리하는 경우

같은 원점의 채널을 단변량 task C개로 만든 뒤 이것을 MV라고 부르지 않는다. 반대로 여러 원점의 채널을 하나의 task로 합치지 않는다. 큰 배치 안에서도 원점별 그룹 경계가 유지되어야 한다.

메모리가 부족하면 B를 줄여 독립 원점 묶음만 줄인다. MV 그룹 안의 C채널을 임의로 분할해서 별도로 예측하면 다른 방법이 되므로 금지한다. 원점 하나의 전체 C채널도 처리하지 못하면 해당 조건의 메모리 부족을 보고한다.

### UNI 두 비교군

같은 원점·같은 값의 입력을 `[B*C,1,512]`로 바꾸거나, 채널마다 하나의 1차원 독립 task로 제공한다. `cross_learning=False`를 유지한다. 모델 가중치와 나머지 규칙은 대응 MV와 같다. 출력은 원래 원점·채널 순서로 되돌린다.

### 점예측

주 점예측은 기본 quantile 출력의 **0.5 분위수, 즉 중앙값**으로 고정한다. 모델의 실제 quantile 목록에서 인덱스를 찾고, 최종 형상은 `[원점 수,48,C]`로 맞춘다. 다수 분위수의 평균이나 TEST에 맞춘 분위수 선택은 하지 않는다.

현재 공식 `predict_quantiles`는 두 번째 반환값의 이름을 mean으로 사용하지만 소스에서 실제로 중앙값을 반환한다. 변수 이름만 보고 조건부 평균이라고 설명하지 않는다. 기본 모델은 요청한 분위수 하나만 반환해도 내부의 다중 분위수 출력 계산을 할 수 있으므로, 구현하지 않은 연산 절감을 주장하지 않는다.

## 6. TEST 전에 통과할 검사

TRAIN/VAL 또는 수식 확인용 작은 고정 입력만 사용한다. 테스트는 optimizer 없이 수행한다.

1. **축·대응 검사:** 입력·출력 크기, 원점 시각, 채널 순서, 예측 48개, 중앙값 인덱스, 결측 평가 마스크가 기존 계약과 일치한다.
2. **실제 그룹 검사:** 문서만 인용하지 말고 모델 직전의 그룹 정보 또는 attention mask 생성 경로를 기록한다. MV에서 한 원점의 C채널은 상호 참조 가능하고 서로 다른 원점은 분리됨을 확인한다. UNI에서는 채널마다 분리됨을 확인한다.
3. **배치 독립 검사:** 동일 원점을 단독으로 계산한 예측과 다른 원점들과 묶어 계산한 예측을 비교한다. 다른 원점의 이력을 바꿔도 고정한 원점의 결과가 허용오차 안에서 동일해야 한다. 원점 목록의 순서를 바꿔도 원래 순서로 복원한 결과가 일치해야 한다.
4. **정보 경로 보조 검사:** 같은 원점에서 목표 채널은 유지하고 다른 채널의 과거만 고정된 방식으로 바꾼다. UNI에서 목표 채널 예측은 유지되어야 한다. MV 출력 변화는 다른 채널을 사용할 수 있다는 보조 증거이나, 변화가 반드시 크게 나와야 통과한다는 성능 게이트를 만들지 않는다. 출력이 거의 같으면 구조 확인과 구분해 기록한다.
5. **미래 차단 검사:** 실제 미래 target은 모델 입력 객체에 포함하지 않는다. 저장된 미래 배열을 바꾸더라도 구성되는 과거 입력이 같고 예측이 같음을 확인한다. 다른 원점의 이력을 통한 간접 누출도 별도로 검사한다.
6. **고정·재현 검사:** 평가 모드·no-grad, 가중치 불변, 유한한 출력, 같은 경로 재호출, 저장·재로딩 후 예측/점수의 재현을 확인한다.
7. **기준선 재생 검사:** 기존 선택 모델의 VAL 예측을 재생하고 저장 예측·점수와 대조한다. MSE-LoRA 병합 전후도 확인한다. 다른 손실의 LoRA나 다른 LEVEL 변형을 가져온 경우 먼저 수정한다.

수치 허용오차는 기존 계약의 값과 근거를 우선한다. 동일 경로 복원 `atol=1e-6, rtol=0`, 배치/병합 경로 비교 `atol=1e-5, rtol=1e-4`는 기존 v12 계약에서 확인된 출발점이다. 새 모델에서도 실제 차이와 스케일을 보고 기록하며, 통과시키려고 사후 허용오차를 넓히지 않는다. 게이트 실패는 과학적 성능 저하가 아니라 구현·계약 문제로 분리한다.

## 7. 실행 규모와 자원 상한

새 적합은 0회다. 신규 정확도 비교는 **공식 가중치 2개 × 입력 관계 2개 × 자료 3개 = 12개 평가 단위**다. TEST-A/B 원점이 위 기대값과 같다면 총 890개 원점에 각 4개 방법을 적용하므로 3,560개의 “전체 원채널 예측 원점”을 계산한다. 이를 3,560개의 독립 통계 표본이나 API 호출 수라고 부르지 않는다.

[추정·운영상 제안 상한 — 예상 소요시간이나 과거 승인 예산이라는 뜻은 아님]
- 로컬 GPU 1장, 동시 GPU 작업 1개.
- 이 회차 GPU 작업 점유 합계 180분, CPU 전용 작업 합계 60분.
- 신규 다운로드 4 GiB, 신규 로컬 저장 8 GiB 이내. 실제 과거 데이터는 새로 받지 않는다.
- 기술적 실패의 재시도는 같은 실패 원인에 대해 원인 수정 후 최대 1회. 동일 조건의 실패를 반복해서 예산을 소모하지 않는다. 전체 예산에는 최초 실패와 재시도를 모두 포함한다.
- 기존 사용자 승인 상한이 더 작으면 더 작은 상한을 따른다. 다른 프로세스를 종료하거나 새 서버·유료 서비스로 이전하지 않는다.

실행 전 작은 VAL 검사에서 처리시간을 재어 전체 평가·비용 캠페인의 소요를 추정하고 원장에 적는다. 상한 내 완료가 불가능해 보이면 TEST 개봉 전에 필요한 범위/예산 변경만 보고한다. 자동으로 상한을 늘리거나 유리한 자료·비교군만 남기지 않는다. 계정·GPU 대기와 실제 작업 점유를 구분하고 부모·자식 작업 시간을 중복 합산하지 않는다.

사전 검사 뒤 모델 revision, 데이터/원점/체크포인트 hash, 입력 그룹, 출력 통계, 정밀도, 평가식, 비용 grid, 예산, 결과별 해석 규칙을 봉인한다. 이미 노출된 TEST라는 사실도 봉인에 기록한다.

## 8. 고정 정확도 평가와 불확실성

- 세 자료의 TEST-A/B 전체를 모든 새 비교군에 평가한다. 첫 결과가 유리하거나 불리해도 나머지를 생략하지 않는다. 순서와 중단 규칙은 사전에 고정한다.
- 기존 함수와 동일하게 관측 target 위치의 제곱오차 합(SSE), 절대오차 합(SAE), 관측 수를 채널별로 계산한다. 각 채널의 관측 수로 나눈 뒤 채널 평균을 낸다.
- A/B 전체값은 기간별 점수의 단순 평균이 아니라 채널별 SSE/SAE/관측 수를 먼저 합친 뒤 계산한다. 원수치로 집계하고 마지막에 반올림한다.
- 기존 학습 모델은 각 선택 seed의 손실을 평균한다. 예측을 평균해 새로운 앙상블로 만들지 않는다. 새 zero-shot은 각 조건당 한 모델 결과다.
- MSE와 평균절대오차(MAE), 기간별·채널별 값, 실제 관측 분모를 보고한다. 여러 자료의 표준화 MSE를 단순 평균해 종합 승리를 만들지 않는다.
- LEVEL 대 C2_MV, LEVEL 대 C2_SMALL_MV, 새 MV 대 대응 UNI, 새 MV 대 Bolt F0/MSE-LoRA/NLinear의 절대 차이와 상대 변화율을 낸다. 분모·방향을 명시한다. 참조가 0이면 상대 변화율을 억지로 계산하지 않는다.
- 기존 대응 시간블록 재표집 방식을 재사용한다. 해당 자료에서 블록 길이·재표집 수·난수 설정을 실제 확인한다. 기존 7원점·2,000회 규칙을 재사용하는 경우 채널과 비교 방법을 함께 이동시키고 A/B 경계를 넘지 않는다.
- 이 구간은 고정 모델·선택 seed·노출된 평가 조건에 조건부다. 겹치는 예측 원점과 미래값을 독립으로 세지 않는다. 구간이 0을 포함한다고 동등성·비열등성을 선언하지 않는다.
- ZERO-SHOT의 낮은 점수를 고치려고 문맥 길이, 그룹 구성, 입력 전처리, 모델 revision, 분위수, clipping, 추가 미세조정을 탐색하지 않는다.

## 9. 같은 회차 추론 비용 비교

비용의 주 대상은 C2_MV, C2_SMALL_MV, 기존 LEVEL, Bolt F0, **발표와 같은** 원채널 MSE-LoRA, 직접 NLinear다. UNI는 정확도 대조가 주 역할이므로 새로운 대형 비용 grid를 강제하지 않는다. b는 이미 구조 비교용이므로 별도 비용 실험을 의무화하지 않는다.

- 세 자료 각각에서 기존 규칙대로 첫 24개 시간순 VAL 원점을 사용한다. TEST 점수로 비용 표본을 고르지 않는다.
- 과제 배치 B=1과 B=4를 구분한다. B=4는 “원점 4개에서 각 자료의 원채널 전체를 예측”하는 단위이며 네이티브 API batch_size=4를 의미하지 않는다.
- 같은 GPU, 정밀도, CPU 스레드, timing 경계, 예열·반복 규칙을 사용한다. 기존 v12의 10회 예열, 전체 24원점 10회 반복, 실행 순서 3블록을 재사용하고 실제 호출 수를 기록한다.
- 측정 범위는 표준화된 CPU 입력을 받아 필요한 전치·그룹 구성·GPU 전송·온라인 모델 forward·원채널 출력 조립·CPU 반환을 마치는 전체 추론이다. 로드·디스크·채점·hash·원장 기록은 latency 밖에 두고 별도 시간을 기록한다. GPU 동기화를 포함한다.
- 모델은 하나씩 로드하고 측정한다. 다른 모델의 가중치·optimizer·이전 출력 때문에 peak가 부풀지 않게 한다. peak 메모리에는 해당 배포 모델의 전체 가중치가 포함되어야 한다. 측정 중마다 cache를 비우는 비현실적 경로는 쓰지 않는다.
- 모든 seed와 순서 블록을 보존한다. F0 전후 sentinel로 변동을 확인하고 유리한 블록만 버리거나 남기지 않는다. 비용 반복을 학습 seed처럼 세지 않는다.
- B1 지연은 ms/원점, B4 처리량은 **모든 C채널의 H=48 예측을 마친 원점/초**로 보고한다. 계열 행/초를 섞지 않는다.
- allocated/reserved peak, 파라미터·버퍼 바이트 수, 전체 모델 크기를 구분한다. 조회할 수 없는 CPU/프로세스 메모리는 N/A이지 0이 아니다.
- 새 Chronos-2의 학습 비용은 “이번 과제 추가 적합 없음”으로 표시한다. 사전학습 비용 0 또는 전체 메모리 0이라고 쓰지 않는다. 추론 결과로 새 학습 메모리 값을 만들지 않는다.

### 단순 소배치 대안 보존

원채널 F0/MSE-LoRA는 채널 독립 구조를 이용한 기존 chunk 러너를 재사용한다. 원래 full 조건 외에 B1은 K행, B4는 4K행과 K행의 독립 계열 묶음을 사전에 고정해 같은 회차에서 측정한다. 분할 전후 예측 정합성을 확인한다. TEST 점수를 보면서 chunk 크기를 고르지 않는다.

Chronos-2 MV의 그룹 내부 채널을 같은 방식으로 나누는 것은 금지한다. 서로 다른 원점을 나누는 것만 허용하며, 이를 모델 간 같은 채널 분할이라고 설명하지 않는다.

NLinear의 CPU 경로는 기존 러너로 별도 실용 대조를 낼 수 있으나 GPU kernel 시간과 섞지 않는다. 새 서버나 CPU Chronos-2 전수 grid는 이번 범위에 추가하지 않는다.

기존 보고서의 과거 시간과 이번 Chronos-2 시간을 나누어 속도비를 만들지 않는다. 기존 정확도는 계약·hash가 맞으면 재사용 가능하지만 비용 우열은 이번 같은 회차에서 확보한 결과끼리만 판단한다. 체크포인트·환경 재생에 실패한 비교는 비용 미확정으로 남긴다.

## 10. 결과별 판단 — 유리한 결과만 성공으로 정의하지 않음

1. **Chronos-2 MV 또는 Small-MV가 LEVEL보다 정확하고, 관련 추론 메모리·처리량도 유리하다:** 해당 측정 조건에서 LEVEL의 실용적 우위가 지지되지 않는다고 쓴다. 이전 b 대비 보완 효과를 새 모델 대비 우위로 바꿔 주장하지 않는다. 불확실한 작은 시간 차이를 확정적 지배라고 부르지 않는다.
2. **새 모델이 더 정확하지만 LEVEL이 중요한 비용 축에서 유리하다:** 정확도 손해와 절약량을 병기하고 조건부 절충으로만 결론낸다. 임의의 허용 손해율을 사후 도입하지 않는다.
3. **LEVEL이 일부 자료에서 더 정확하다:** 해당 자료·원점·현재 설정에 한정한다. 큰 모델 대비의 이득을 Small에도 자동 적용하지 않고, zero-shot 대 적응 모델이라는 차이를 남긴다.
4. **MV가 UNI보다 낫다:** 같은 체크포인트·관측 조건에서 동시 채널 공유의 이득이 있었다고 쓴다. LEVEL 대비 차이를 채널 공유만의 인과 효과로 주장하지 않는다.
5. **MV와 UNI 차이가 없거나 MV가 나쁘다:** 먼저 그룹 구현을 확인하고, 구현이 맞다면 그 결과를 유지한다. “다변량 기능을 켜면 반드시 좋아진다”는 전제를 버린다.
6. **일부 조건의 메모리 부족·호환성·자료 접근 실패 또는 예산 종료:** 성능 패배/승리로 세지 않는다. 확인 가능한 결론과 누락된 결론을 구분하고, 실행 가능한 다른 고정 비교는 가능한 범위에서 마친다.

다른 모델 간 비교는 구조·사전학습 자료·가중치 규모 등이 다른 **실용 모델 비교**다. “압축의 순수 인과 효과”, “LEVEL의 신규성이 증명됨”, “TSFM 범용 우위”로 확장하지 않는다. F0는 추가 학습이 없으므로 LoRA 대비 학습 메모리 이득으로 F0 대비 필요성을 대신 설명하지 않는다.

- `evaluation_seal.json`: TEST 전 고정된 실행 정의와 이전 노출 상태.
- `accuracy_comparison.csv`: 전체·기간·모델별 MSE/MAE 및 관측 분모. 원수치 정밀도를 보존한다.
- `paired_comparisons.csv`: 절대/상대 차이, 분모, 조건부 구간, 대응 표본 범위.
- `prediction_manifest.json`: 로컬 예측 파일의 실제 경로·키·축·원점·채널·hash. 실제 파일을 보고 작성한다.
- `cost_comparison.csv`: 같은 회차의 원 측정과 요약, full/chunk 구분, 장치/배치/단위/측정 범위.
- `STATUS.md`: 시간·저장·다운로드 사용량, 실패·수정·재시도, 완료/미완료.
- `FINAL_REPORT_KO.md`: 무엇을 확인했고 어느 주장을 유지/축소/보류하는지. 관찰과 해석을 분리한다.
- `final_checks.json`: 저장 예측에서 재계산한 수치, 표·원장 정합성, 미래 누출 검사, 실제 완료 목록.

보고서에는 아래를 포함한다.
- 본문 표: 기존 b/LEVEL/Bolt F0/MSE-LoRA/NLinear에 C2_MV·C2_SMALL_MV 두 행을 추가한 결과.
- 보조 표: 모델별 MV–UNI 비교. 서로 다른 자료의 원점수를 종합 평균하지 않는다.
- 비용 표: 같은 회차 정확도–메모리–처리량과 기존 단순 chunk 대안.
- 발표에 쓸 영어 표/캡션과 “F0보다 못한데 왜 하나?”, “Chronos-2를 쓰면 되지 않나?”에 대한 **관측 결과에 맞춘** 한국어 답변. 단정적 방어문을 미리 정해놓고 결과를 맞추지 않는다.
- 기존 슬라이드에서 바꿀 주장과 근거를 먼저 목록화한다. PowerPoint/PDF 원본을 자동 덮어쓰지 않는다. 비교군 이름만 추가하는 것이 아니라 비용과 결론의 일관성까지 검토한다.

새로운 방법 탐색이나 불리한 결과 구조 변경 없이 이번 유한 비교를 종료한다. 검산은 실행팀의 자체 검산이지 독립 재현이 아니다. 대형 원자료·가중치·예측 배열·비밀정보는 Git에 올리지 않는다. 명시적으로 승인된 기존 commit/push 규칙이 있을 때만 관련 작은 파일을 그 규칙대로 게시하고, 없으면 로컬 산출물과 변경 목록을 보고한다. 새 브랜치·PR·force push·외부 제출을 임의로 하지 않는다.
