# Peacock 원입력 대조(matched RAW) 보충 실험 — 실행 지시문

## 목표
Peacock Education에서 빠진 원입력 대조(matched RAW)를 학습·채점해서
발표 8장 "잔차 입력 제한은 자료에 따라 다르다"의 Peacock 칸을 채운다.
이건 v12 확인 실험의 일부가 아니라, Peacock TEST가 이미 노출된 뒤 추가하는 보충 대조다.
모든 산출물에 "TEST 노출 후 보충 대조 (v12 확인 실험 아님)"라고 표기해.
새 방법 탐색이나 성능 개선 시도가 아니다.

## 확인된 사실 (계획자가 저장소 2154e7f에서 직접 읽은 것)
- [확인: research/tsfm_peft_a_confirmation_v12_20261001/TOPIC_DECISION.md 26행]
  v12는 Peacock에 별도 RAW 적합을 하지 않았다.
- [확인: research/tsfm_peft_level_confirmation_v6_20260928/PLAN.md 33행] 정의:
  LEVEL_RES = b + P_H(r) + G_res(r − P_L(r))
  LEVEL_RAW = b + P_H(r) + G_raw(X − P_L(X))
  G는 채널 공유·편향 없음·활성화 없음 512→32→48, down 무작위·up 0 초기화, 학습 변수 17,920개.
  두 모델의 학습 전 함수는 모두 b + P_H(r). 같은 seed끼리 초기 텐서와 원점 순서를 공유한다.
- [확인: 같은 폴더 model_v6.py 157–162행] 구현 차이는 G 입력 한 줄뿐이다.
  level_raw는 x − x[:, -1:, :], level_res는 residual − last. 수준항(잔차 마지막 값을 48번 반복)은 같다.
- [확인: model_v6.py 75행] model_v6.py는 Robin C17/K5만 허용하므로 Peacock에 그대로 쓸 수 없다.
- [확인: v6 PLAN.md 45행, research/tsfm_peft_practical_controls_v7_20260928/PLAN.md]
  Robin·Jena의 RAW는 LEVEL과 같은 G LR 1e-3, 같은 학습·checkpoint 규칙으로 학습했다.
- [확인: v12 PLAN_SUPPLEMENT.md] Peacock LEVEL 학습 설정:
  - LR 1e-3 × seed 92601·92602, AdamW wd 0, clip 1, batch 4
  - epoch당 phase-balanced TRAIN 원점 512개, 최대 120 epoch
  - VAL 비개선 6회에서 중단, ReduceLROnPlateau(factor 0.5, patience 2, 상대 임계 1e-4)
  - step0도 후보, VAL MSE 최소·동률이면 가장 이른 checkpoint
  - Chronos-Bolt-small revision 772f3d25d38aec6d914c8949dab4462e2d46f5d8
- [확인: v12 PLAN_SUPPLEMENT.md] v12는 TEST 봉인 후 추가 학습을 금지했다.
  그래서 이번 작업은 v12 안이 아니라 새 버전에서 한다.
- [확인: presentation_support_level/source_values.csv] Peacock LEVEL 결합 TEST MSE:
  seed 92601 0.2037268471433063, seed 92602 0.20280549532911796, 평균 0.2032661712362121.
- [확인: presentation_support_level/training_cost_extract.csv]
  Peacock LEVEL seed 92602 학습은 23 epoch에 160초였다.
  [계산] epoch당 약 7초, 최대 120 epoch면 fit당 약 840초.
- [확인: v12 TOPIC_DECISION.md 24행] v12의 Peacock 구간은 조건부 7원점 블록 95% 구간이다.
- [확인: research 폴더 목록] 마지막 버전은 v16이다.

## 확인이 필요한 전제 (실행 전에 확인, 하나라도 실패하면 중단하고 보고)
1. [추정] v12 로컬 캐시에 다음이 남아 있다:
   - Peacock 고정 자료 계약(채널 13개·기간·TRAIN 표준화·입력 대체)
   - TRAIN PCA basis(13×4)
   - seed별 LEVEL 초기 G 텐서와 TRAIN 원점 순서
   - 선택 checkpoint와 TEST 예측
   → 확인: v12 기록(protocol·seal·manifest)의 hash와 대조해.
     PCA는 다시 적합하지 말고 저장된 basis를 써.
2. [추정] v12에서 Peacock LEVEL을 학습한 코드 경로에 RAW 분기를 넣으면
   바뀌는 건 G 입력 한 줄뿐이다(model_v6.py 160–161행과 같은 차이).
   → 확인: 수정 diff를 보고해. 입력 줄 외에 학습·선택·채점 코드가 달라지면 중단.
3. [추정] v12 Peacock 구간 계산의 블록 길이(7원점)·반복 수(2,000)·난수 seed가 기록에 있다.
   → 확인: 기록에서 찾아 그대로 써. 못 찾으면 새로 정하지 말고 중단하고 보고해.
4. [추정] 저장된 LEVEL TEST 예측을 지금 채점 코드로 다시 채점하면 평균 0.2032661712362121이 나온다.
   → 확인: 상대오차 1e-9 안에서 일치해야 RAW TEST 채점으로 넘어가.
     예측 배열이 없으면 저장 checkpoint로 TEST 추론을 다시 해서 같은 값이 나오는지 확인하고,
     그것도 안 되면 중단.

## 실행 순서
1. 새 디렉터리를 만든다:
   research/tsfm_peft_peacock_matched_raw_v17_<YYYYMMDD> [제안 이름].
   v16 이하는 읽기만 한다.
2. 전제 1~4를 확인하고, 관련 기존 파일의 hash를 기록한다.
3. RAW 구현: v12 Peacock LEVEL 코드 경로를 새 디렉터리로 복사하고,
   G 입력만 "X − X의 마지막 값을 512번 반복한 것"으로 바꾼다.
   수준항·G 구조·초기화·손실·옵티마이저·스케줄러·선택 규칙은 그대로 둔다. diff를 저장한다.
4. 짝 맞춤 확인: 같은 seed의 RAW와 LEVEL이 다음 셋을 공유하는지 본다.
   - 같은 초기 G 텐서 hash
   - 같은 TRAIN 원점 순서 hash
   - 같은 학습 전 출력(b + 수준항, 원소별 일치)
   하나라도 다르면 중단한다.
5. 학습: seed 92601 다음 92602, 한 번에 하나씩. checkpoint는 VAL로만 고른다.
6. TEST 채점 전 봉인: 두 seed의 선택 checkpoint·코드·설정·초기 상태 hash를 봉인 파일에 적는다.
   봉인 뒤에는 학습 금지.
7. TEST 채점은 한 번만, v12와 같은 집계로 한다:
   기간별 채널 SSE/관측수 합산 → 채널 평균 → 두 seed 손실 평균. MSE가 주지표, MAE는 보조.
8. 대응 구간: LEVEL − RAW의 절대 MSE 차와 상대 차 100×(LEVEL/RAW − 1)를
   결합·TEST-A·TEST-B별로 낸다.
   재표집은 TEST-A/B 안에서 각각 하고, 채널·방법을 함께 움직이고, seed는 고정한다(조건부 구간).
9. 아래 판정표에서 해당하는 줄 하나를 골라 보고한다.

## 사전 판정표 (결과 보기 전에 정한 것 — 결과를 본 뒤 바꾸지 마)
기준: 결합 TEST 상대 차 100×(LEVEL/RAW − 1)의 조건부 95% 구간.
- 구간 상한 < 0 → "Peacock에서도 잔차 입력 제한이 이득"
  8장 문장: "잔차 입력 제한은 Robin·Peacock에서 이득, Jena에서 손해"
- 구간 하한 > 0 → "Peacock에서는 원입력 버전이 더 정확"
  8장 문장: "잔차 입력 제한은 Robin에서만 이득, Jena·Peacock에서 손해"
- 구간이 0을 포함 → "Peacock에서는 차이를 가르지 못함"
  8장 문장: "Robin 이득, Jena 손해, Peacock 불분명"
- TEST-A와 B의 방향이 다르면 "기간에 따라 방향이 다름"을 덧붙인다. 유리한 기간을 골라 쓰지 않는다.
- 세 경우 모두 8장 소제목은 그대로 둔다.
  이 실험으로는 잔차 제한이 언제 이득인지 설명할 수 없다.

## 게이트
아래 항목을 실행 전에 확인하고, 실패하면 그 자리에서 멈추고 보고해줘.
멈추는 게 기본값이야. 대충 맞으니 진행하지 마.
1. 이 지시문이 지목한 변수/배열/키가 실제로 존재하는가
   → 없거나 의미가 다르면 중단하고 실제 구조를 보고
2. 이 지시문이 전제한 값의 일치가 수치로 성립하는가
   → 불일치하면 중단하고 어디서 얼마나 벗어나는지 보고
3. 기준선 계산에 쓰라고 한 값이 예측 시점에 알 수 있는 것인가
   → 미래 정보나 정답이 섞이면 중단하고 leakage 경로를 보고
4. 만들라고 한 산출물이 이미 존재하는가
   → 있으면 만들지 말고 경로를 보고
5. RAW의 G 입력이 과거 512관측과 그 마지막 값만 쓰는가
   → 미래 구간 값이나 TEST 통계가 섞이면 중단
6. 표준화·PCA·입력 대체 통계가 TRAIN에서만 나왔는가
   → 아니면 중단
