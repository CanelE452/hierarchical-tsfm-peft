# Appliances 추론 비용 측정 결과

사진의 Appliances 행에 넣을 값은 다음과 같다.

- Memory vs Raw: **-14.7%**
- Speed-up vs Raw: **2.22×**

Raw의 배치 추론 시간 중앙값은 43.3017 ms, 우리 방법의 두 seed 중앙값 평균은 19.4853 ms다. peak allocated GPU memory는 Raw 353.1143 MiB, 우리 방법 301.0654 MiB다.

## 측정 조건

기존 선택 Raw 모델과 Full-P K10 seed92601/92602를 그대로 불러왔다. 새 학습·refit·모델 선택은 없었다. 배치8, FP32, F 호출당 최대128행의 기본 정책, warmup10회와 timed20회, 매 호출 CUDA 동기화와 peak reset을 사용했다. Raw는208개 논리 시계열을128+80행의2회 F호출로, 우리 방법은80행의1회 F호출로 처리한다. 측정 대상은 입력 전처리부터 P/E/F/D 또는 Raw와 역정규화·CPU출력까지의 전체 추론 경로이며, 모델 로딩·전체V일치검사·해시·지표계산 시간은 제외한다.

각 모델은 별도 프로세스로 순차 측정했다. 우리 방법 시간은 각 seed의20회 시간 중앙값을 구한 뒤 두 중앙값을 산술평균했다. 메모리는 각 seed의20회 peak allocated 최댓값을 구한 뒤 두 seed를 산술평균했다. 속도 배수는 Raw시간/우리시간, 메모리 변화율은100×(우리메모리/Raw메모리−1)이다. 메모리는 PyTorch peak allocated이며 GPU 전체사용량이나 reserved memory와 구분한다.

이는 표의 기본128행 정책에 해당한다. Jena 본문에 있는 F호출당48행 고정의3.6배 결과와는 배치 조건이 다르므로 그 조건을 혼용하지 않는다. Appliances의 표 각주에는 `Raw128+80 rows, ours80 rows; B=8, F-row cap128`을 덧붙일 수 있다.

## 무결성과 실행 환경

전체V41origins의 예측·정답·관측mask·채널·A60정규화와 원 모델 텐서 해시를 확인한다. 보호T 수치는 열지 않았다. 기존 검산기 핵심을 재사용한 COST_VALIDATION.json은 PASS이며, 별도 계산과 호스트 원시추적 검산은 INDEPENDENT_COST_AUDIT.json에 기록한다.

세 모델 모두60초/1Hz의 전체엔진 사전검사와 실제 측정 중 연속검사를 통과했다. 등록 한도는 background엔진 p95≤5%,max≤15%,표본간격≤2.5초로 유지했다. 알려진 Windows desktop 프로세스가 함께 있는 조건이며 완전유휴·전용GPU의 보장은 아니다. 반복20회의기술통계이며 서비스전체의 p95지연 보장이나 다른장치·배치에서의 동일배수 보장이 아니다.

앞선정오실패와 v2저녁실패는 모두추론전 PREFLIGHT였고 각각의기록을보존했다. 사용자가허용한RustDesk종료후현재32desktop신원을새로등록했으며 측정기준·모델·배치·시험횟수는바꾸지않았다. 유리한timedtrial만고르거나삭제하지않았다. 발표파일·대본은생성하거나수정하지않았다.
